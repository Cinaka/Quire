# P4 正式本机入口验收指南

本指南对应真相来源第68～73章，验证p4/schedules分支的/schedules本机试用页，不等于生产已部署、完整R3/P4验收或跨设备同步已上线。正式页使用当前地址原有数据库，不是5179/5181/5182隔离库。

## 一、开始前

1. 如日常库有重要内容，先在设置中完成JSON防蠹并确认文件可用。不要清库、导入验收夹具或修改本机时钟。
2. 在当前分支更新并检查：

```bash
git pull --ff-only
cd frontend
npm run check:p4:sync
npm run test:p3
```

沿用原开发服务及地址（通常http://localhost:5173），打开/schedules；手机宽度可点底栏“预简”，桌面直接进入这个路径。需要启动服务时执行已有npm run dev，不新增专用端口。页面应显示“本机试用”及“日程同步需在云笺明确启用本次会话”，/schedules普通工作区没有内部普通日记首存桥；第71章新增明确进入的资源/终态核对区，同步默认关闭，明确启用入口位于云笺。

## 二、本地预简与离开保护

1. 选明天创建一份明确标注“测试”的文字预简。编辑标题和正文，点“保存预简”，应显示已保存本机。
2. 再编辑但不正式保存，点击“返回今简”或其他导航。普通预简允许保留已落库安全草稿后离开，不应静默正式保存或清除草稿。
3. 重新进入/schedules，明确恢复草稿，检查文字；正式保存后返回列表。保存失败/输入法仍在组字时，不应直接离开。
4. 日期筛选、分页以及移入断简/恢复沿用原本地行为。恢复不改变来源转换身份。
5. 在中文输入法组字期间尝试导航；应先留在页面，确认最后文字上屏后再操作。实际浏览器IME行为需本机验证，Node模拟不能替代。

## 三、到期转简与关联日记

- 新预简只允许未来日，不为了验收开放“新建过去预简”。如有已有到期测试记录可直接使用；否则将刚建测试记录通过既有编辑改期流程明确改为今天，正式保存后回列表。
- 点“刻成日记”，核对来源日期并明确确认；从“已转简”打开同一篇关联日记，检查标题/正文/日期。未来待刻没有转简按钮是正常的。
- 修改关联日记后不保存，直接点页面导航：应保持当前路由，出现现有未保存处理提示。取消要保留输入；明确保存或弃去后，再次点击导航才能离开，不应过一会儿自动跳转。
- 重新打开同一篇，应仍是同一来源对应的日记，不生成第二篇；日记已删除/已弃去时不能补生内容。普通安全草稿与关联日记运行时修改不是同一种保存机制。

## 四、首页待刻提醒

1. 返回今简，应看到“本机待刻”今日/逾期及二者合计，以及顶栏“预简 / 待刻”入口。这里统计的是本机自然日，不是云端全部数据，也不是首页选中的历史日期。
2. 记录原数量。在已有测试预简上明确改期至今天并正式保存，返回首页，今日待刻应相对增加；改为昨天则进入逾期，改回未来则不计入到期待刻。不要修改真实记录或系统时钟来凑测试。
3. 对测试来源软删，数量应相对减少；恢复后恢复计数；明确转简后不再计入待刻。库内有其他记录时不能假设总数恰好是1或0。
4. 首页切换到历史日，提醒仍显示按当前本机自然日的数量；返回前台或点击重新读取可以刷新。实际跨午夜、多标签页变更和IndexedDB watcher需真实环境单独验证，Node通过不替代这些结果。
5. 点击提醒的“查看预简工作区”，应只进入/schedules，不应自动保存、转简或签到。提醒读取失败/失效不能显示成0；独立顶栏入口仍可用。账号/恢复失效后请按提示处理归属，离开首页再重新进入，不要求旧端口自动重绑账号。
6. 原首页今日日记/近作、过去/今日日记及上名青简保持原行为；第70章允许选择未来日留为文本预简；请跑原P3测试并实际检查，不因本批只读接线就默认签到回归通过。

## 五、账号/恢复与云端边界

- 正式宿主沿用固定owner、登录代际和恢复epoch。已有库归属与登录账号不匹配时应拒绝操作，不能自动认领或清库；请走既有备份/认领流程。
- 如果上下文在编辑时失效，旧页面应锁写、保留可复制输入；先复制后明确弃去此面板内存副本，不应删除持久草稿。组字中失效时副本可能未含最后输入，按提示另行复制编辑器可见文字。
- 不为此测试放入真实凭据或手工改owner/清库；实际账号、同账号恢复和多标签页应使用独立测试数据，单独登记结果。
- 页面常规本机操作不请求日程云端；第71章核对区仅在明确请求后使用账号读取/处置。未确认转换仍由原P2保护，不能将“本机已转简”视为云端完成。第71章仅挂已有资源/终态窄路径：可能明确下载图片或发布独立标签，不增加自动图片/日记上传，不放宽共享/未知回执保护。
- 第69章已接首页只读提醒；第70章已接普通新建未来日期首存，但尚未验证PWA离线刷新。可以验证已加载页面的本地读写不依赖网络，但不要据此声称闭应用后后台可用或所有离线重载已验收。

记录实际通过/失败步骤、构建输出和控制台异常；没有实际结果的项目保持待验。完成本指南不授权合并main或生产部署。


## 六、普通新建的未来日期首存（第70章，待本机结果）

1. 首页选明天或更远日期，应显示“留一简”，点击后进入首存预简页面，不应改成今天、跳到已生成的日记或自动写入日记表。空预简草稿槽应打开所选日的编辑器；有旧草稿则先明确恢复/处理，不覆盖旧稿。
2. 输入带“测试”标记的标题和文字，明确点“保存预简”，应显示本机保存成功。进入/schedules核对日期与内容；未来记录没有转简按钮。返回首页今天/简册，不应出现刚刚这篇未来日记。
3. 再次编辑而不正式保存，导航时沿用已有安全草稿/组字保护；重新进入时需明确恢复，不能无提示覆盖。普通今天/过去新建与/entry/:id已有日记仍走原编辑器，检查保存、图片/标签/心情/天气以及P3签到无回归。
4. 仅当当前库已有真实“未关联普通安全原稿”时检查恢复分流：原稿日期未来，即使不传日期或首页选今天，也应先进入只读原稿核对，不自动新建今日日记。明确核对未来首存日，再确认写入预简；如原稿含图片/标签/心情/天气，应明确受阻并保留原稿，不可删字段绕过。不要向日常库手工写夹具或localStorage伪造原稿。
5. 首存核对区域允许明确选择已至日期并核对为日记；核对结果需与确认时规则一致，跨午夜应重核或受阻，不能静默改变资源。此条只在有合适测试原稿时操作，无原稿则登记未测。
6. 编辑中通过地址栏同路由改date不应自动切换当前新建会话或覆盖输入；请先明确保存/处理草稿，离开后重新进入。账号/恢复代际变化沿用既有锁写和可复制副本保护，不静默重新认领。

以上需要实际浏览器结果。当前仍无日程自动同步，不把本机保存/提醒数量当作跨设备成功；本批不新增提醒通知、重复日程或预简图片载荷。


## 七、资源冲突 / 终态统一核对区（第71章，待真实结果）

### 进入、离开与账号保护

1. /schedules点击“资源冲突 / 终态核对…”。如果关联日记有未保存输入，应先阻止进入；取消保留输入，保存/明确处理后再点入口。不要为了测试放弃真实未保存内容。
2. 核对区初次只列本机已转简来源，包含已移入断简的来源；没有来源不是“云端无冲突”。挂载、重读本机列表或选择来源都不应自动请求日程云端。
3. 游客或账号/库归属不一致时，选择来源应明确受阻，不自动认领、登录或清库；游客本机列表/编辑仍按原功能使用。
4. 有独立测试账号及测试来源时，选择来源，点击“打开双方资源核对…”。还未完成明确确认关闭前，切来源、点击页面导航或返回本机预简不得直接卸载面板/丢名称。取消关闭保留输入，明确关闭后才能返回。实际文件操作忙碌时同样检查。
5. 返回本机预简应保留原宿主并重读列表，不重建认领；账号/同owner恢复变化应锁住旧核对区、保留可复制名称，不自动切新账号续跑。真实账号/恢复步骤仅在测试库做，无合适环境登记未测。

### 资源取舍（只用原有测试冲突）

- 先明确同意读取双方实物，然后单独选全新空文件保存/回读，再明确读取原证据文件。取消文件框不得自动下载、提交或替换原文件。
- 两种正文选择无默认项。独立标签先明确命名、保存本机准备，再另行授权发布/用原ID核对，最后明确引用交接；不能自动串行完成，也不能丢响应后另建标签ID。共享/无法证明独占的图片等不支持条件必须阻断，不强制解锁。
- 不支持showSaveFilePicker及独占保存回读的浏览器只能看说明/读取原文件，不应以下载链接假装完成保存证据，从而解锁写操作。
- 未保存名称、失败后输入、取消关闭、账号失效后的复制均需实际浏览器验证；不要在生产账号制造冲突测试。

### 终态观察与窄处置（只用已有相应测试来源）

- 点击“明确读取云端终态与本机观察”，应先显示白名单受阻说明；不应请求转换POST、自动恢复日记或清意图。
- “保存观察”只保全本机实物及当前云端观察，不含云端图片字节/标签定义；缺口必须标明，保存不解除保护或确认首次回执。
- 只有原严格条件满足才显示来源墓碑接纳/既有永久弃去处置；每个动作独立勾选、选新空文件、关闭回读及事务前重核，完成后要求重新核对，旧授权不可重放。来源墓碑接纳后日记不变，原意图与保护保留；既有弃去不生成新日记、不恢复活动内容，也不等于云端全量完成。
- 未知回执、无原意图、共享资源或证明不足必须维持受阻；不得为了测试手工改库伪造授权。没有相应测试数据时，这些处置登记“未测”，不是通过。

本批仍无日程自动同步、后台通知、重复日程或新隔离端口。先运行check:p4/test:p3并提交实际构建/浏览器输出，再登记通过范围。


## 八、R4本次会话日程同步（测试后端与测试账号）

1. 先防蠹备份并使用允许测试的账号/后端及测试内容，不为了验收对生产数据启用。上方check:p4:sync已包含build；完整阶段收尾另跑check:p4及P3/后端回归，见测试分组指南。
2. 刷新后先不启用：进入今简、预简和云笺、编辑本地预简，网络中不应因此出现日程云端请求。P2自己原有请求不算P4请求。游客或本机归属不匹配时启用应拒绝，不应自动认领。
3. 在云笺明确启用本次会话日程同步。只对测试数据观察原意图→push→pull及独立剩余状态，未来预简不自动转成日记。已有冲突应解释受阻而不是强行覆盖。
4. 开启时测试本地变化、断网后联网、回前台的恢复；普通失败有界退避，多批有界继续，预算用完需明确重试，不无限请求。暂停后不再开启新周期；已在途服务端提交可能完成，不声称回滚。刷新后启用恢复为关闭。
5. 原会话中退出/切号/同账号备份恢复应停止旧会话；不得将旧回包写给新账号。真实多标签页/双设备与在途恢复另需实际日志；不要用真实数据制造冲突。
6. 旧后端拒绝支持端点时应停止自动重试并提示核对；单条转换404可为来源不存在，不得伪造已同步。P2同步按钮与状态独立，P2结束不报P4全完成；P3签到仍走既有在线规则。
7. 资源/终态手动核对前先暂停日程调度，依原明确步骤保全/取舍；已持久意图和保护不能被自动丢弃。暂停不保证在途请求撤销，并发证据变化仍应重读复核。
8. 记录实际分支、测试后端、步骤、状态/网络结果与控制台。没有执行或日志的场景保持待验，不因为专项Node测试通过就登记真实存储/跨设备通过。完整P4未验收，不合并或部署。


## 九、手动核对与会话同步互斥（第73章）

1. 先按第八节使用允许测试的账号/后端，不直接测试生产真实内容；执行更新后的check:p4:sync（含build）。
2. 在云笺启用本次会话日程同步，进入预简，点击资源冲突/终态核对：应要求暂停，不直接打开。若同步轮次忙碌，入口禁用并说明需等待。
3. 点“明确暂停日程同步，准备核对”。只暂停后续调度，不自动打开核对、不承诺回滚在途云端提交。等待已有轮次结束，再次点击核对入口。
4. 若有未保存编辑，仍由原编辑区明确协商；取消要保留输入。协商期间同步状态发生变化，不应使用旧判断进入核对。
5. 正常进入后仅做原已授权核对操作；关闭后同步应仍关闭，不自行重试。回云笺明确启用才能恢复。若同页组件仍持有核对占用，云笺应提示且禁止启用；这是运行时也执行的限制。
6. 取消返回时保持原占用；真正离开/卸载后占用释放但不自动启用。刷新后日程仍默认关闭。
7. 此保护不锁住其他标签页/设备，也不暂停P2；观察到证据/版本变化仍应由原安全校验拒绝旧操作。真实并发矩阵保持待验，不能用本机单页流程代替。
