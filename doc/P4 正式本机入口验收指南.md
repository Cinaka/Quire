# P4 正式本机入口验收指南

本指南对应真相来源第68～70章，验证p4/schedules分支的/schedules本机试用页，不等于生产已部署、完整R3/P4验收或跨设备同步已上线。正式页使用当前地址原有数据库，不是5179/5181/5182隔离库。

## 一、开始前

1. 如日常库有重要内容，先在设置中完成JSON防蠹并确认文件可用。不要清库、导入验收夹具或修改本机时钟。
2. 在当前分支更新并检查：

```bash
git pull --ff-only
cd frontend
npm run check:p4
npm run test:p3
```

沿用原开发服务及地址（通常http://localhost:5173），打开/schedules；手机宽度可点底栏“预简”，桌面直接进入这个路径。需要启动服务时执行已有npm run dev，不新增专用端口。页面应显示“本机试用”“日程云端同步尚未开放”，没有内部普通日记首存桥、云端取舍或自动同步按钮。

## 二、本地预简与离开保护

1. 选明天创建一份明确标注“测试”的文字预简。编辑标题和正文，点“保存预简”，应显示已保存本机。
2. 再编辑但不正式保存，点击“返回今简”或其他导航。普通预简允许保留已落库安全草稿后离开，不应静默正式保存或清除草稿。
3. 重新进入/schedules，明确恢复草稿，检查文字；正式保存后返回列表。保存失败/输入法仍在组字时，不应直接离开。
4. 日期筛选、分页以及移入断简/恢复沿用原本地行为。恢复不改变来源转换身份。
5. 在中文输入法组字期间尝试导航；应先留在页面，确认最后文字上屏后再操作。实际浏览器IME行为需本机验证，Node模拟不能替代。

## 三、到期转简与关联日记

- 新预简只允许未来日，不为了验收开放“新建过去预简”。如有已有到期测试记录可直接使用；否则将刚建测试记录通过既有编辑改期流程明确改为今天，正式保存后回列表。
- 点“刻成日记”，核对来源日期并明确确认；从“已转简”打开同一篇关联日记，检查标题/正文/日期。未来待刻没有转简按钮是正常的。
- 修改关联日记后不保存，直接点页面导航：应保持当前路由，出现现有未保存处理提示。取消要保留输入；明确保存或弃去后，再次点击导航才能离开，不应过一会儿自动跳转。
- 重新打开同一篇，应仍是同一来源对应的日记，不生成第二篇；日记已删除/已弃去时不能补生内容。普通安全草稿与关联日记运行时修改不是同一种保存机制。

## 四、首页待刻提醒

1. 返回今简，应看到“本机待刻”今日/逾期及二者合计，以及顶栏“预简 / 待刻”入口。这里统计的是本机自然日，不是云端全部数据，也不是首页选中的历史日期。
2. 记录原数量。在已有测试预简上明确改期至今天并正式保存，返回首页，今日待刻应相对增加；改为昨天则进入逾期，改回未来则不计入到期待刻。不要修改真实记录或系统时钟来凑测试。
3. 对测试来源软删，数量应相对减少；恢复后恢复计数；明确转简后不再计入待刻。库内有其他记录时不能假设总数恰好是1或0。
4. 首页切换到历史日，提醒仍显示按当前本机自然日的数量；返回前台或点击重新读取可以刷新。实际跨午夜、多标签页变更和IndexedDB watcher需真实环境单独验证，Node通过不替代这些结果。
5. 点击提醒的“查看预简工作区”，应只进入/schedules，不应自动保存、转简或签到。提醒读取失败/失效不能显示成0；独立顶栏入口仍可用。账号/恢复失效后请按提示处理归属，离开首页再重新进入，不要求旧端口自动重绑账号。
6. 原首页今日日记/近作、过去/今日日记及上名青简保持原行为；第70章允许选择未来日留为文本预简；请跑原P3测试并实际检查，不因本批只读接线就默认签到回归通过。

## 五、账号/恢复与云端边界

- 正式宿主沿用固定owner、登录代际和恢复epoch。已有库归属与登录账号不匹配时应拒绝操作，不能自动认领或清库；请走既有备份/认领流程。
- 如果上下文在编辑时失效，旧页面应锁写、保留可复制输入；先复制后明确弃去此面板内存副本，不应删除持久草稿。组字中失效时副本可能未含最后输入，按提示另行复制编辑器可见文字。
- 不为此测试放入真实凭据或手工改owner/清库；实际账号、同账号恢复和多标签页应使用独立测试数据，单独登记结果。
- 页面本地操作不请求日程云端。未确认转换仍由原P2保护，不能将“本机已转简”视为云端完成。此页不新增云端图片/标签上传，也不提前暴露资源冲突或终态处置。
- 第69章已接首页只读提醒；第70章已接普通新建未来日期首存，但尚未验证PWA离线刷新。可以验证已加载页面的本地读写不依赖网络，但不要据此声称闭应用后后台可用或所有离线重载已验收。

记录实际通过/失败步骤、构建输出和控制台异常；没有实际结果的项目保持待验。完成本指南不授权合并main或生产部署。


## 六、普通新建的未来日期首存（第70章，待本机结果）

1. 首页选明天或更远日期，应显示“留一简”，点击后进入首存预简页面，不应改成今天、跳到已生成的日记或自动写入日记表。空预简草稿槽应打开所选日的编辑器；有旧草稿则先明确恢复/处理，不覆盖旧稿。
2. 输入带“测试”标记的标题和文字，明确点“保存预简”，应显示本机保存成功。进入/schedules核对日期与内容；未来记录没有转简按钮。返回首页今天/简册，不应出现刚刚这篇未来日记。
3. 再次编辑而不正式保存，导航时沿用已有安全草稿/组字保护；重新进入时需明确恢复，不能无提示覆盖。普通今天/过去新建与/entry/:id已有日记仍走原编辑器，检查保存、图片/标签/心情/天气以及P3签到无回归。
4. 仅当当前库已有真实“未关联普通安全原稿”时检查恢复分流：原稿日期未来，即使不传日期或首页选今天，也应先进入只读原稿核对，不自动新建今日日记。明确核对未来首存日，再确认写入预简；如原稿含图片/标签/心情/天气，应明确受阻并保留原稿，不可删字段绕过。不要向日常库手工写夹具或localStorage伪造原稿。
5. 首存核对区域允许明确选择已至日期并核对为日记；核对结果需与确认时规则一致，跨午夜应重核或受阻，不能静默改变资源。此条只在有合适测试原稿时操作，无原稿则登记未测。
6. 编辑中通过地址栏同路由改date不应自动切换当前新建会话或覆盖输入；请先明确保存/处理草稿，离开后重新进入。账号/恢复代际变化沿用既有锁写和可复制副本保护，不静默重新认领。

以上需要实际浏览器结果。当前仍无日程自动同步，不把本机保存/提醒数量当作跨设备成功；本批不新增提醒通知、重复日程或预简图片载荷。
