## 一、范围结论

P3 的目标是：登录用户可以在账号时区的“今天”完成一次幂等签到，并看到当前连续签到天数与本月签到日历；同一账号在不同设备上看到一致的签到结果。

P3 不把签到伪装成日记，也不把签到记录塞进 Entry 的 `dirty` 同步循环。签到是独立的账号行为，服务器保存唯一事实；日记仍遵守 P2 的 local-first 与 push → pull 协议。

### P3 必做

- 首页真实签到卡：今日未签到 / 今日已签到两种状态。
- 未登录时保留「上名青简 / 登录后可用」入口，点击进入云笺；登录后隐藏该占位入口，显示真实签到卡。
- 登录用户点击「上名青简」完成今日签到；同一天重复点击必须幂等，不产生第二条记录。
- 显示当前连续签到天数；连续性的日期边界按账号保存的 IANA 时区判定。
- 显示本月签到日历 / 热力格，至少能区分已签到、未签到与今天。
- 服务端鉴权、用户隔离、统一 `{code, message, data}` 响应体。
- 账号时区由 P2 已保存的 `users.timezone` 提供；P3 不新增时区编辑入口。
- 具备加载中、成功、失败、未登录与离线提示；离线时不虚假写入“已签到”。

### P3 可选

- 同一张卡同时显示历史最高连续天数。
- 将签到卡抽成独立组件 / composable，供未来岁编或小程序复用。
- 对最近月份做只读客户端缓存，明确标注缓存可能不是最新。
- 为接口增加客户端请求幂等键，作为数据库唯一键之外的重复请求诊断信息。

### P3 明确不做

- 补签、撤销签到、修改历史签到日期。
- 签到提醒、Web Push、邮件、短信验证码、社交排行、徽章与奖励。
- 将“写了一篇日记”自动视为签到，或把签到绑定到 Entry 是否存在。
- 预简 / 待刻与未来日期日程；这整条仍推 P4。
- 岁编、PDF 杀青、日记本视图、OSS 迁移与 PWA 离线首开。
- 把 check-in 加入 `/sync/push`、`/sync/changes` 或 Entry / Tag / Media 的 dirty 集合。

## 二、已冻结的产品语义

| 项目 | P3 定案 |
| --- | --- |
| 签到对象 | 当前登录账号，不是浏览器、不是真实日记条目 |
| 一天的定义 | 以 `users.timezone` 计算服务端当前本地日期；客户端只展示服务端返回日期 |
| 可签到日期 | 仅账号时区的今天；拒绝未来与历史日期写入 |
| 重复请求 | 同一账号、同一 `checkin_date` 返回成功与既有结果，不报重复错误 |
| 撤销 | P3 不提供；签到表按 append-only 语义使用 |
| 离线写入 | P3 不排队、不乐观标记；离线只读缓存或提示恢复网络后操作 |
| 真相来源 | 服务端 `checkins` 表；前端缓存不是权威副本 |
| 连续天数 | 从该账号已签到日期计算；今天已签到时从今天向前连续，今天未签到时按产品展示规则计算“截至昨天”的连续段，并在页面明确状态 |
| 跨设备 | 以服务端唯一约束与查询结果为准；设备 A 成功后，设备 B 刷新或重新进入页面即可看到 |

连续天数的展示规则必须在实现前写成单元测试：建议“今天未签到”时显示截至昨天的连续天数，避免用户在当天尚未操作时看到连续天数突然归零；“今天已签到”时把今天纳入计算。

## 三、前端方案

### 1. 首页替换点

当前 `HomeView.vue` 已通过 `isLoggedIn()` 区分登录态：未登录渲染占位按钮并进入 `/sync`，登录后隐藏占位。P3 只替换登录后的空缺区域，不改变 P2 的登录、退出、云笺与本地日记逻辑。

登录后首页显示：

- 今日状态与主按钮：未签到显示「上名青简」，已签到显示成功态且不可重复提交。
- 当前连续天数。
- 本月日历格：按服务端返回的日期集合渲染，今天有独立视觉标记。
- 请求失败、离线、账号过期时的可理解提示；401 继续交给 P2 的刷新队列处理。

建议新增 `src/api/checkins.ts` 与一个 composable；页面上层仍只通过 API / composable 使用数据，不直接访问 `@/db/*`。P3 核心不需要新增 Dexie 表，也不升 Dexie version。

### 2. API 契约

建议保持 `/api/v1` 前缀与 P2 Envelope：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| POST | `/api/v1/checkins/today` | 按账号时区签到；重复调用幂等 |
| GET | `/api/v1/checkins/month?year=YYYY&month=MM` | 返回月份签到日期、今日状态、当前连续天数与可选最高连续天数 |

`POST` 不接收任意日期，避免客户端时钟和跨设备时区造成伪造；服务端从当前用户的 `timezone` 计算 `checkin_date`。`GET` 的月份范围按账号时区校验，返回的日期全部为 `YYYY-MM-DD`。

建议的 `data` 语义：签到接口返回 `checkin_date`、`checked_in`、`created`、`current_streak`；月份接口返回 `year`、`month`、`checkin_dates`、`today`、`checked_in_today`、`current_streak`，最高连续天数若实现则作为附加字段。

## 四、后端与数据库方案

### 1. 数据表

新增一张 `checkins` 表：

| 字段 | 约束 / 语义 |
| --- | --- |
| `id` | UUID v7，主键；便于日志定位与未来扩展 |
| `user_id` | UUID BINARY(16)，必填；应用层鉴权隔离 |
| `checkin_date` | DATE，按账号时区计算；必填 |
| `created_at` | DATETIME(3) UTC；服务端生成 |

新增唯一约束 `uk_checkins_user_date (user_id, checkin_date)`，并建立按 `user_id, checkin_date` 的查询索引。P3 不新增 `user_streaks` 汇总表：连续天数从签到日期集合计算，避免“签到明细”和“汇总缓存”出现双写不一致；数据量变大后再评估物化汇总。

### 2. 后端模块

- 新增 `app/models/checkin.py`、`app/api/v1/checkins.py` 及对应 schema / service。
- 在 `app/api/v1/router.py` 注册 check-ins 路由。
- 新增 Alembic 迁移；既有用户不需要回填签到数据。
- 复用 `get_current_user`、`utcnow()`、统一 Envelope 与现有异常处理。
- 只允许当前用户访问自己的签到；任何用户 ID 不从客户端请求体读取。
- 服务端用 IANA 时区计算日期，非法或不可识别时区沿用 P2 注册默认值并记录校验错误；实现阶段应优先把时区字段限制为可解析值。

### 3. Redis 与限流

P3 核心不引入 Redis，也不做签到缓存。单人使用阶段先依靠数据库唯一约束保证幂等；若公开部署后发现刷接口或并发压力，再单独评估 Redis 限流 / 缓存，不把它混入 P3 的数据库与同步改动。

## 五、同步协议与跨设备一致性

P3 签到不进入 P2 的 `dirty`、`bootstrap`、`push → pull`、冲突留档或墓碑清理流程，原因是签到不是本地日记副本，且 P3 明确采用服务端权威。

- 设备 A 在线签到成功后，服务端唯一键保证只生成一条记录。
- 设备 B 通过月份查询读取同一账号的 `checkin_dates`；无需等待 Entry 同步。
- 两台设备同时签到同一天时，双方都可收到成功结果，最终只有一条数据库记录。
- 退出账号或切换账号后，前端必须清空当前签到查询状态并重新读取，不能沿用上一个账号的日期集合。
- 401 仍由 P2 的 access/refresh 机制处理；刷新失败时回到登录入口，不把签到状态写入本地。
- 网络失败不显示已签到；可保留上一次月份结果，但必须标记为可能过期，并允许重试。

这套方案不修改 Dexie version 2，不迁移现有 Entry / Tag / Media 数据，不改变 `lastSyncAt`、冲突缓冲或 `pendingPurges` 的语义。

5. 将 HomeView 的登录后占位替换为真实签到卡；保持未登录入口与 `/sync` 跳转不变。
6. 做双设备与时区边界测试，再跑 P2 回归：前端 build、后端 Ruff、全部 pytest。
7. 更新本页与项目状态索引的完成状态；未通过真机与跨设备验收前，不标记 P3 已完成。

## 八、兼容与验收条件

### 兼容策略

- 只增加后端表、路由、前端 API / 组件；不修改 Dexie schema、备份 `formatVersion` 或现有同步载荷。
- 旧客户端访问新后端仍可正常使用日记与 P2 同步；它们不会发送签到请求。
- 新客户端遇到旧后端时，签到卡显示服务不可用 / 重试，不阻断写日记、列表与同步；发布前确认部署顺序或提供能力探测。
- 已有账号的 `timezone` 直接沿用 P2 值；P3 不重算历史、不回填签到。
- 所有时间戳仍由服务端以 UTC 存储；只有 `checkin_date` 是账号时区下的 DATE。

### 验收条件

- 未登录首页仍显示「上名青简 / 登录后可用」，点击进入云笺；登录后该占位入口消失。
- 登录用户可在首页完成一次今日签到；刷新、重复点击、双设备并发均不会生成重复记录。
- 当前连续签到天数与测试矩阵约定一致；本月所有签到日期可见，今天状态明确。
- 前端离线不伪造签到成功；恢复网络后可重试；401 与退出登录路径正确。
- 后端 `ruff check`、完整 `pytest`、前端 `npm run build` 全部通过；新增测试覆盖时区、唯一键、鉴权、连续性和月历查询。
- P2 回归通过：现有日记、图片、登录认领、push → pull、冲突处理和 Dexie v2 旧数据均不受影响。
- 未完成补签、提醒、社交、日程等内容不被混入 P3 提交；P4 入口继续保持未开放。
