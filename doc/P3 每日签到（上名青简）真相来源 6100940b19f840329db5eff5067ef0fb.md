## 一、范围与完成结论

P3 必做范围已经实现：真实首页签到卡、登录态入口、在线每日签到、同日幂等、连续统计、月历、鉴权与账号隔离、统一 Envelope、账号时区及加载/失败/离线提示。

原方案可选项均已落地：最长连续统计、独立组件/composable、最近月份账号隔离只读缓存、UUID 幂等诊断头。另完成累计签到日数、历史月份导航、回到本月、权威时区和更新时间展示、成功状态播报。

### 冻结语义

- 签到属于当前账号，不能由日记条目自动代替。
- 服务端 `users.timezone` 决定自然日；客户端展示服务端日期。
- 仅签到今天，不补签、不撤销、不改历史日期。
- 同账号同日期重复返回成功，唯一事实保存在 `checkins`。
- 离线只读，不排队、不乐观标记成功。
- 今天未签到时从昨天向前计算当前连续天数；今天已签到时包括今天。
- 不引入 Redis 或 `user_streaks` 汇总表。

## 二、前端实现

- `frontend/src/api/checkins.ts`：签到请求和响应类型。
- `frontend/src/api/checkinCache.ts`：sessionStorage 最近 6 个月只读缓存，按账号隔离，异常存储安全失效。
- `frontend/src/composables/useCheckins.ts`：状态、月份加载、提交、重校验、账号变化及旧请求失效。
- `frontend/src/components/CheckinCard.vue`：签到状态、当前/最长/累计天数、日历、月份导航、时区和更新时间。
- `frontend/src/views/HomeView.vue`：未登录保留“上名青简 / 登录后可用”，点击进入 `/sync`；登录后显示真实签到卡。

### 状态恢复与同步

- 同账号 BroadcastChannel 刷新；不支持时降级 storage 事件，广播载荷包含账号 ID。
- online、focus、visible、手动刷新及可见页面每 60 秒重校验；离线、加载中或签到中不轮询。
- 当前月使用服务端自动选择年月；回到本月或箭头进入本月后恢复当前月跟随。历史月保持显式年月。
- 退出和账号切换清理状态；同账号 token 刷新不误重置；旧账号请求不能回写新账号。
- 首次失败或离线无缓存可恢复；缓存禁用/损坏不会中断流程；当前月索引不能跨账号读取。
- 旧缓存“今日已签到”不作为禁用新一天签到的权威依据；在线提交仍由服务端幂等判定。
- POST 成功后立即更新摘要并尝试缓存；后续月历刷新失败保留已确认日期和统计，仍提示月历未完全刷新。写入前查询失效，避免迟到响应覆盖。
- 前端 `updatedAt` 表示成功读取月份时的客户端时间，不是服务端 API 字段；POST 局部更新不冒充完整月历更新时间。

## 三、实际 API 契约

统一响应 `{code, message, data}`，复用 P2 鉴权与 access/refresh 机制。

| 方法 | 路径 | 语义 |
| --- | --- | --- |
| POST | `/api/v1/checkins/today` | 无任意日期参数；按账号时区签到，重复幂等 |
| GET | `/api/v1/checkins/month` | 省略年月，读取账号当前月 |
| GET | `/api/v1/checkins/month?year=YYYY&month=MM` | 读取指定历史月份；年月必须成对，单独提供返回 422 |

POST data：`checkin_date`、`checked_in`、`created`、`current_streak`、`longest_streak`、`total_checkins`。

GET data：`year`、`month`、`checkin_dates`、`today`、`timezone`、`checked_in_today`、`current_streak`、`longest_streak`、`total_checkins`。

`X-Idempotency-Key`：UUID 诊断头，后端校验、回显和记录；真正去重仍由账号/日期唯一键承担。

无效、空值、路径形式账号时区统一返回 HTTP 422“账号时区无效”；不静默回退到默认或设备时区。注册校验合法 IANA 时区。未来签到记录在查询与返回层防御性过滤。

## 四、数据库与迁移

新增 `checkins`：`id BINARY(16)` UUID v7 主键；`user_id BINARY(16)` 非空；`checkin_date DATE` 非空；`created_at DATETIME(3)` UTC。

- 唯一约束：`uk_checkins_user_date(user_id, checkin_date)`。
- InnoDB、utf8mb4、utf8mb4_0900_ai_ci；沿用项目不加外键约定。
- 迁移文件：`backend/alembic/versions/20260923_add_checkins.py`。
- revision：`p3_checkins`；down_revision：`p2_refresh_sessions`。
- 既有用户不回填签到，也不重算历史记录。

## 五、P2 兼容与跨设备一致性

签到是独立账号行为，不进入 `/sync/push`、`/sync/changes`、dirty、sync issues、bootstrap、墓碑及冲突协议。不修改 Dexie version 2、日记/媒体/标签数据、备份 formatVersion、lastSyncAt 或 pendingPurges。

双设备同日签到依靠服务端唯一约束收敛；另一设备通过月份查询读取结果。在线可见页面定时刷新提供最终一致性，不承诺所有设备瞬时同步。

旧客户端可继续使用新后端的 P2 日记与同步；新客户端遇旧后端时只提示签到不可用，不阻断日记。发布顺序为后端与迁移先于前端。
