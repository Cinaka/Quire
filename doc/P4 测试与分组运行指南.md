# P4 测试与分组运行指南

## 为什么不能只跑build

build执行vue-tsc与Vite，可发现类型、引用和打包错误；不能证明事务回滚、草稿不被覆盖、转简不重复、切号后旧回包不落库、独立游标不跳过记录。这些数据安全行为即使build成功也可能失败。因此优化运行范围，不删除安全测试。

用户上一批2511项全通过，311861.740375ms约5分12秒，不是2511项都必须每次执行，也不能据此判定哪些应删。本批未做完整性能剖析；不能把所有耗时归咎于单一环节。

## 何时运行什么

| 变更 | 建议验证 |
| --- | --- |
| 仅文档 | 核对文字/命令与实际实现；无需为文档机械重跑全部测试 |
| 纯样式/文案 | build、相关界面人工检查及受影响静态断言 |
| 明确局部逻辑 | 对应专项测试+build，按依赖补相邻保护回归 |
| 本次同步调度/状态接线 | check:p4:sync，加P3相关回归；真实账号/存储人工验收另做 |
| schema/恢复/备份/鉴权或共享保护的广泛修改 | 完整P4及相邻P2/P3/后端回归，不能机械只选sync |
| 阶段关闭/PR前 | 完整check:p4、P3/后端及既定真实集成矩阵 |

## 命令

在frontend目录，日常本次同步改动：

```bash
npm run check:p4:sync
npm run test:p3
```

check:p4:sync = test:p4:sync + build。需要单跑测试可用npm run test:p4:sync。阶段完整回归：

```bash
npm run check:p4
npm run test:p3
```

原test:p4/check:p4继续发现全部P4测试文件，没有删除或skip。分组只支持显式--group sync，错误参数或清单缺失直接失败。
