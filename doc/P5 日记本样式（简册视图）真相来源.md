## 一、既有约定与本次决策边界

### 已存在的产品约定

1. 原始《日记 App 需求分析与技术方案》的 P5 是“日记本样式：纸张视觉、手写字体子集化、视图切换、翻页动效”。列表支持普通列表与日记本两种阅读呈现；日记本视图要求登录。
2. 品牌名称采用“简册视图”，沿用青简现有纸色、墨色、竹青、装订意象，不另起产品名。
3. P6 才是打印与导出：A4 横版双 A5、打印模板、PDF 等；P5 不据“日记本”名称扩展成排版出版系统。
4. 当前 main 已有普通列表和禁用的日记本按钮，尚无可用的简册正文阅读器。已有字体不等于任意正文的手写字体已经完成。
5. 原始方案中 P3/P4 顺序、Pinia/PostgreSQL/Docker 等历史文字，不覆盖现行 P3 签到、P4 预简、composable/Repository、MySQL 8 等已生效决策。

### 本次推荐，已由用户确认

以下布局、分页、字体与实现方式是本次推荐，不伪称原清单已有细则：

- P5 聚焦**已有日记的只读阅读呈现**，不再造编辑器、同步协议或日记内容格式。
- 宽屏双页、窄屏单页；每个阅读单元对应一篇日记。长文完整向下阅读，不截断、不按纸张高度硬切页。双页阅读采用普通页面滚动，避免两个狭小独立滚动框。
- “翻页”是切换前后阅读单元，不是 PDF 物理分页。界面使用“第几篇 / 当前筛选共几篇”等准确口径，不将数据库每批 20 条当成 20 张纸，也不虚构印刷页数。
- 正文优先评估现有许可来源的**霞鹜文楷**，使用公开固定字符集制作自托管分包；现有马善政 9 字子集只保留装饰用途。未覆盖字、emoji、字体失败必须有可读系统回退。
- 列表内切换，推荐 URL `view=book` 表示呈现方式；不新增数据库偏好，不跨设备同步阅读位置。本阶段不要求跨刷新保存全部筛选条件。
- 简单短时 CSS 翻页过渡；不引入重型 3D 翻书依赖。尊重减少动态效果设置。

## 四、实施契约

### 1. 数据与只读呈现

- 单一来源是现有 Entry；未转简的 Schedule 不进入日记本。已转简日记按本机当前 Entry 呈现，不通过阅读确认回执、解锁 P4 保护或重新生成日记。
- 现有 dirty 日记允许按原本本地语义阅读；“可读”不代表“已云端确认”。必要状态说明沿用现有口径，不伪造同步成功。
- 默认不显示软删日记。打开到翻页期间若记录删除、失去归属或版本变化，重核对后展示当前可读状态，不闪现其他账号/旧篇正文。
- 排序继续采用现有 repo 规则，不借 P5 改写同日排序或 P2 同步顺序。过滤后当前篇消失，明确回到仍可读的结果或空态。
- 支持现有段落、标题、列表、引用、代码/代码块、现有文字 marks、图片等实际 schema 内容；节点和 marks 以实施核对的清单及测试为准。代码块使用等宽字体，不强制手写体。
- 未知 schemaVersion / 不支持节点应明确提示并保留安全可读信息，不静默吞掉内容后称显示完整，更不回写降级结果。
- 默认无外部 HTML 渲染；图片仅解析合法 `local://media/{id}` 本机引用。不得把任意正文 URL 直接变成远程图片请求。
- 图片保留比例，缺失 blob 显示“本机图片未就绪”等占位；不自动请求资源证明、补齐或全库下载。临时 Object URL 在替换、离开、退出时回收，永不持久化。

### 2. 布局、切换与编辑往返

- 原普通列表保持可用，游客不受新增登录门槛影响。点击简册时才触发该视图的登录要求，登录取消保留列表及筛选。
- 共用现有列表控制器，不复制两套筛选和排序逻辑。布局断点变化以当前日记 ID 为锚，不能因为单双页变化跳回开头。
- 切换呈现方式不重置当前结果集；跨视图保留筛选与当前锚点。进入编辑页前保存轻量返回上下文，现有编辑未保存保护不被绕过。
- 编辑后返回重新核对该篇，显示最新已保存内容；若新内容不再满足筛选，说明变化，不伪造仍满足筛选。
- 键盘前后操作不得抢占输入框、正文选择或 IME；按钮说明与焦点明确；动画不能遮挡错误提示或阻止连续正常阅读。

### 3. 字体与性能

- 优先复用既有霞鹜文楷官方来源、版本/哈希与 OFL 记录。正文需要重新设计固定公开字符覆盖和 unicode-range 分包，而非直接扩大首页通用字体。
- 不上传用户日记文字制作字库，不将私人正文编入仓库公共字体；不依赖第三方字体 CDN 请求正文字符。
- 简册组件与正文手写字体按需加载；普通首页/列表不得提前拉取新增正文字体包。字体阻断时仍立即可读，不出现空白正文或方框替代所有罕见字。
- 本阶段不承诺覆盖全部 Unicode、任意书法字形或“离线第一次访问即有全部字体”。字体缺字与未缓存都走可读回退。
- 每次仅加载当前/邻近阅读单元，图片也按可见范围加载；过期请求、快速翻页、布局变化不应形成 blob URL 泄漏或旧正文覆盖新正文。
- P5-1 应登记新增各字体包大小、首次可读表现、普通列表新增请求情况；根据实测收敛预算，不在未生成字库前编造性能结果。

### 4. 登录、离线、跨设备

- 沿用原产品“简册需登录”的约定；它是当前产品入口规则，不等于加密本机数据库，也不宣称 JWT subject 解码有服务端签名验证效力。
- 使用现有认证流程取得当前身份，并核对本机 owner、会话代际与数据库 epoch。若现有机制无法建立一致身份，回退列表/提示登录，不自动认领、清库或跨账号展示。
- 已建立合法上下文的当前会话离线后，可阅读本机已有日记与图片；无网络并非清除正文的理由。退出/换号/身份失效后按现有规则阻断该视图，不能由残留 token 或旧回包重新打开。
- 不要求每翻一篇在线请求；也不承诺过期 token、退出后或离线重新启动时永远免登录。P5-0 必须核对现有刷新/身份路径，登记离线重开边界后再接入口；如需改变鉴权契约，应另提方案，不能偷偷加后端或新凭据表。
- 离线使用以应用资源、本机记录与图片实际可用为前提；缓存不到的字体系统回退。PWA 首次安装/缓存策略改造不并入本次。
- 设备间内容继续由 P2/P4 已有机制提供。简册本身不创建同步请求、不推进游标、不确认冲突，不同步视图偏好或阅读位置。
- 异步正文/图片读取必须在返回后再次核对身份、owner/epoch 与当前日记锚点；退出和 A→B 切换清理内存内容及 Object URL，不清除本机业务数据。

## 六、有限实施顺序与出口

仅以下四个交付批次，不把每个异常拆成独立产品功能。分支建议 `p5/notebook-view`，**方案确认后**从当时最新 main 创建。

1. **P5-0 接口与样式冻结（短核对）**：确认只读 schema、现有账号/owner/epoch 与离线重开路径、编辑返回上下文；完成字号/纸色/单双页与公开字库分包决定。若推荐范围不能落地，先报告差异，不自动扩张。
2. **P5-1 只读阅读与纸张/字体**：本机正文、安全图片、长文与异常内容、按需手写字体，先做到完整可读且零业务写入。
3. **P5-2 正式切换与翻页**：接入列表同一结果集、前后篇/单双页、动画/键盘/减少动态效果、登录边界和编辑往返；不另建长期隔离宿主取代正式入口。
4. **P5-3 集成验收与收尾**：相关边界、真实浏览器视觉与性能、P2/P3/P4 兼容回归，记录实际结果/限制，用户确认后再准备 PR。不把方案文档或 build 成功记成验收完成。

## 七、测试策略与验收门槛

### 平时：小步验证，不再每次全量 P4

- 每批只跑其受影响的 P5 测试及直接相关旧用例，再执行 `npm run build`（vue-tsc + Vite）。确实改到账号/图片/列表共享行为才补对应旧分组。
- 测试命令名称与文件以实际落地为准；本次不提前声称已有 `check:p5` 或捏造测试数量。
- build 能检查类型和打包，不能代替正文完整性、只读零写入、退出换号竞态、图片释放等运行时验证。
- 纯文档改动无需跑 2600 项 P4。若后端没有改动，不在每个前端节点重复跑全量 pytest。

### 阶段收尾：集中一次完整回归

- P5 全量、既有 P3/P4 前端全量及正式构建；相关 P2 列表/编辑/图片/同步路径回归。若发现影响共享契约，应补相应后端全量并如实登记。
- 自动化与真实浏览器分别记录，不以模拟存储测试替代真实浏览器视觉/本机只读验证。
- P4 历史未测矩阵继续保留原记录；不要求本阶段重做全部恢复/双设备/MySQL 并发验收，不借 P5 将其补记通过。

### P5 必验结果

1. 普通列表仍可游客使用；登录进入简册，取消登录不丢筛选；登录状态与本机归属不一致时不得自动展示/认领。
2. 搜索、标签 AND、日期、含图、三种排序结果与普通列表一致；切换、增量翻页与单双页变化不重复、漏篇、错序或回到错误锚点。
3. 无标题、长标题、长文、列表/引用/代码/marks、多图、罕见字/emoji 及未知版本的表现有明确结果；完整正文可读、不裁切，不静默丢节点后冒充完整。
4. 本机图片正常、缺失、读取失败均不自动写入/下载；离开可回收 URL；字体加载失败与离线仍可读，不拖慢普通首页/列表。
5. 阅读前后 Entry、Schedule、媒体、dirty、同步游标/意图没有业务写入差异；进入现有编辑页明确保存才走原编辑写入。
6. 编辑保存后返回更新同一篇；未保存返回依旧受现有保护；删除/筛选不再匹配有明确说明。
7. 快速翻页/筛选、退出、A→B 切换与既有 epoch 变化后旧结果不串篇、不串账号。不要求为此执行破坏性的真实恢复，仅覆盖上下文变化边界。
8. 375px 手机、768px 中等屏与 1440px 桌面布局可用；200% 缩放、键盘、减少动态效果正常；至少本机实际 Chrome 和 Safari 各记录结果，不将“无控制台错误”等同所有用例通过。
9. P3 签到和 P4 正式入口/转简编辑及既有同步状态没有可见回归；未经确认不合并、不部署。
