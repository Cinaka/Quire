## 摘要

青简 Quire 是一款以“私密而郑重的个人编年史”为定位的本地优先日记应用。它围绕设备本地记录，逐步建立账号同步、预简转日记、只读简册与浏览器打印成册的路径，而不是要求每次写作都等待云端请求完成。

系统采用 Vue 3 / TypeScript / Vite 前端、Dexie / IndexedDB 本地存储，以及 FastAPI / SQLAlchemy / MySQL 后端。日记首先在当前设备保存，登录、联网并满足归属条件后参与同步；图片与正文分离存储，云端读取需要身份与归属校验；打印采用本机一致性快照与系统打印能力，不额外上传到新的云端 PDF 服务。[S2][S3][S4][S7][S11]

本文坚持三个区分：**本地保存不等于云端同步；鉴权和 HTTPS 不等于端到端加密；代码合并不等于生产上线。**

当前版本面向单服务器、单 API 进程的自用与小范围分享。公开注册需要配合限流、容量保护、HTTPS、备份与监控。Redis 业务接入、Service Worker/PWA、原生小程序和后端异步 PDF 均不属于本基线已交付能力。

## 3. 架构与技术选型

### 3.1 逻辑架构

```text
浏览器
├── Vue 页面 / Tiptap 编辑
├── Repository 与会话上下文
│   └── Dexie → IndexedDB（正文、标签、Blob、预简、meta）
├── 同步 / 私有媒体传输 → HTTPS /api/v1/*
└── 只读阅读 / 本机快照 → 物理分页 → 系统打印 / 另存 PDF

Nginx
├── 网站根 → 前端构建产物
├── /api/ → 回环 FastAPI
└── 拒绝旧 /media 静态入口；私有磁盘不公开

FastAPI（首版单进程）
├── 认证、归属、限流与业务接口
├── SQLAlchemy async → asyncmy → MySQL
└── 安全媒体发布与读取 → 私有磁盘目录
```

这是职责关系，不是已运行生产环境或已完成跨设备验证的证明。[S3][S4][S9][S11][S13][S14]

### 3.2 选型与代价

| 层 | 当前采用 | 技术取舍 |
| --- | --- | --- |
| UI | Vue 3、TypeScript、Vite、Vue Router、Tailwind CSS | Web 交互与静态构建；不直接提供小程序运行时 |
| 编辑 | Tiptap / ProseMirror | 结构化富文本；依赖浏览器编辑环境 |
| 本地存储 | Dexie / IndexedDB | 事务与 Blob；受浏览器配额/回收约束 |
| 网络 | Axios | API 和认证适配；重试不等于业务成功 |
| 后端 | FastAPI、Pydantic v2 | 路由、输入模型和响应封装 |
| 持久化 | SQLAlchemy 2 async、asyncmy、MySQL 8 | 归属数据、锁与同步；须验证真实 MySQL 行为 |
| 迁移 | Alembic | 显式结构演进；不自动获得改库授权 |
| 运行 | Nginx、systemd、Conda | HTTPS、托管与环境；无 Docker 前置要求 |

前端安装依据 lock 文件；后端 environment.yml 固定主要依赖版本，但不是全部间接依赖的完整哈希锁。本文不触发依赖升级。[S2][S3]

### 3.3 模块边界

- `views` / `components`：页面与交互。
- `shared`：领域类型与可复用规则；是否平台无关仍需逐模块检查。
- `db`：本地仓储、同步状态、预简和只读会话。
- `repo`：面向上层的仓储入口和受控工厂，目前仍绑定本地实现，不是完整跨端插件体系。
- `api`：同步与私有媒体传输。
- `capabilities` / `print`：平台能力、打印布局和生命周期。
- `backend/app/api/v1`、`core`、`models`、`db`：接口、公共机制、ORM 与会话。
- `deploy`：部署模板，不等于已安装配置。
- `doc`：阶段来源、验收记录与说明文档。[S4][S7][S11][S13][S14]

## 4. 数据模型与存储语义

### 4.1 领域对象

| 对象 | 核心信息 | 含义 |
| --- | --- | --- |
| Entry | 日期、结构正文、纯文本、标签、心情天气、预简来源、删除与同步时间 | 内容、自然日与修订分离 |
| Tag | 名称、颜色、同步标记 | 日记的多对多分类 |
| MediaItem / Media | 原图、缩略图、关联、类型、尺寸、顺序、远端定位 | 本地 Blob 与云端文件分离 |
| Schedule | 提醒自然日、正文、pending/converted、转换结果 | 到期/逾期是派生展示状态 |
| Meta | owner、游标、同步与恢复状态 | 整库身份/恢复边界 |
| User / RefreshSession | 账号、令牌版本、刷新有效期和吊销信息 | 会话可验证、可轮换 |

本地表包括 entries、tags、media、meta、schedules；Dexie schema 基线定义到 v3，保留历史升级逻辑。服务端还包括签到、关联与转换回执等结构；不能仅凭概览重建实际数据库。[S4][S8][S12][S15]

### 4.2 标识、日期与正文

- 业务记录使用 UUID；客户端可离线生成标识，服务端辅助生成器使用 UUID v7。
- MySQL 迁移使用二进制 UUID。手工读写必须依据实际 ORM 编解码，不能照搬历史 UUID_TO_BIN 换位示例。
- entryDate、remindDate 是自然日，不应被 UTC 转换移动一天。
- 创建、修改与同步时间使用明确 UTC 语义；客户端修改时间与服务端更新时间不可互换。
- 正文包含 schemaVersion 与 Tiptap 文档；纯文本字段不替代原始结构。
- 图片以媒体 ID 建立引用，不能把任意远程 URL 当作可信内容。[S8][S10][S12]

### 4.3 检索说明

首次 MySQL 迁移创建了 ngram 全文索引，但基线日记列表接口的关键词条件仍使用字符串 contains。**有全文索引不等于所有搜索已经使用 MATCH AGAINST，更不是规模化性能证明。** 本地和服务端搜索路径需分开理解。[S10][S12]

## 5. 本地优先与同步

### 5.1 基本链路

```text
编辑 → 本地提交记录/Blob → 标记待同步
       ↓ 登录、联网、上下文有效
推送变更 / 上传媒体 → 检查逐项结果 → 更新同步状态
       ↓
拉取增量 → 按归属、修订与冲突规则合并 → 记录游标
```

该图概括职责，不把浏览器、数据库与文件系统描述为一个分布式原子事务。[S9][S11]

服务端通用 push 分别返回 entries、tags、media_meta 的结果，各输入数组有数量限制。changes 使用服务端更新时间与 ID 的组合游标，并以高水位约束本轮范围，避免只按时间戳分页造成边界含糊。[S9]

### 5.2 修订与冲突

日记 upsert 比较客户端修改时间：严格更旧的写入被判 stale，相等按既有幂等重放规则处理。它不是 CRDT，不提供逐字符自动合并；设备时钟与跨设备竞争仍需实测，不能把后来到达的请求必然当作更新内容。预简另有修订、回执与冲突规则。[S9][S10][S5]

### 5.3 成功与失败语义

- 本地保存不证明服务器持久化；HTTP 批次成功也不证明每个业务项成功。
- 图片上传失败保留本地字节与待同步状态；未解决或暂停错误不能在下一轮无工作时被洗成成功。
- 异步结果发布前继续核对账号与恢复上下文，迟到结果不能跨账号写入。
- 断网、限流和暂不可用须明确提示，不靠清本地数据掩盖错误。[S11]

当前没有 Service Worker：已经加载的页面可完成部分本地工作，但不保证首次离线打开、离线强制刷新或任意浏览器资源保留。本地存储、云同步、JSON 备份互补，不互相替代。

## 6. 预简与转换一致性

预简具有独立状态、来源修订与转换过程，不是未来日期日记的简单别名。到期/逾期由日期派生；手动转简复制已保存来源，不接受页面任意提交另一份正文冒充同次转换。[S5][S8]

主要约束：

1. 首次转换快照和来源修订可追溯，目标日记后续编辑不悄悄改写来源证据。
2. 转换意图、结果关联和回执约束重放，避免重复生成不一致目标。
3. 目标可能活跃、软删或已清除，不能把“没有活跃日记”一律解释为未转换。
4. 图片、共享标签等资源有证明、补齐与冲突边界，不能凭 ID 存在直接认领。
5. 本地、云端及迟到请求仍受 owner/恢复上下文约束。

P4 已在接受限制内交付；真实 MySQL 转换竞争及完整双设备/多标签在途矩阵缺少充分独立证据，不在本文补记通过。[S5]

## 7. 简册阅读与打印导出

### 7.1 简册只读原则

P5 提供纸张式只读阅读、长文、翻页及按需字体。读取通过受控会话进入，不顺带编辑、同步、认领或下载修复云端图片；身份、owner、恢复代际变化后，旧会话及迟到结果需失效。[S6]

本地 Entry 不是每行均含 owner，主要采用整库 owner/epoch 边界。这不是浏览器磁盘上的逐行加密隔离，用户仍须保护共享设备和已解锁浏览器。[S4][S7]

### 7.2 杀青路线 A

流程为：范围与筛选确认 → 本机一致性只读快照 → 内容/图片/字体预检 → 结构分页与目录 → 预览确认 → 系统打印/另存 PDF。

快照读取本机已保存的活跃日记和引用图片，可包含尚未同步的已保存内容；排除未保存输入、未转简预简、来源证据和断简。选择“全部”指本机范围，不代表其他设备云端全集；打印本身不先强制同步或自动云端补图。[S7]

输出支持 A5 顺序页、A4 顺序双页及 A4 折叠小册子。连续双页不是装订拼版；小册子需要补至四倍数。物理分页与 P5 滚动阅读分离，不使用截图切片或隐藏溢出替代续页。最终字体改变要重新分页，缺图/未知内容须显式诊断而非静默丢弃。[S7]

### 7.3 不可消除的系统边界

**打印/另存 PDF 不是应用内自动生成下载 PDF。** afterprint 或对话框返回不能证明保存、打印成功。应用可清理自己的模型、DOM、Object URL，但不能保证撤回系统已取得的内容、保存文件或纸张。

当前未新增后端 PDF 引擎、持久导出任务或异步队列；MD ZIP、DOCX 不因原规划提过就被算为交付。手机、Firefox 独立平台、八页实物折叠、峰值内存等未独立核验项保留未验。阅读 PDF 不可替代可恢复的 JSON 备份。[S7]

## 8. 身份认证与隐私边界

### 8.1 网页会话

登录返回 access token；刷新令牌通过 HttpOnly Cookie 传递。生产 Secure 属性要求 HTTPS。刷新检查用户 token_version、会话有效期和撤销状态，吊销旧会话并签发新会话；退出处理当前刷新会话。[S15]

只读阅读、打印和媒体异步请求在最终发布边界仍需核对身份与代际，不能因为请求开始时验证过就接受换号后的迟到结果。[S6][S7][S11]

### 8.2 信任边界

| 机制 | 提供的保护 | 不提供的保证 |
| --- | --- | --- |
| HTTPS | 链路加密、证书身份 | 不替代授权，不防服务端管理员读取 |
| 登录与 owner 校验 | 约束跨账号资源访问 | 不等于 E2EE 或全量安全审计 |
| owner/恢复上下文 | 防止应用旧任务跨身份发布 | 不等于磁盘加密或防同设备恶意程序 |
| private/no-store | 要求相关 HTTP 响应不被普通缓存保留 | 不等于远程擦除、禁截图或撤回打印 |
| 会话机制 | 身份与令牌轮换管理 | 不自动带来邮件验证、找回密码和风控体系 |

云端正文与图片不能描述为“服务端不可读”。托管方需要保护数据库、文件、服务器和备份；用户需要保护浏览器配置文件与导出内容。

## 9. 私有媒体与上传安全

### 9.1 读取

旧 `/media/` 静态入口在后端与 Nginx 模板关闭，新入口为：

```text
GET /api/v1/media/{id}/original
GET /api/v1/media/{id}/thumbnail
```

接口验证身份并按 Media.user_id 限定归属；未登录和其他账号拒绝访问。前端仅使用固定 ID/variant 的受控请求，不随意 fetch remoteUrl、不向 URL query 写 token；响应使用 private/no-store 等控制。磁盘路径和历史 URL 元数据不再代表公开可读地址。[S11][S13]

本地 Blob 优先。网络补齐需固定账号/恢复上下文，不能重建已删除行、覆盖新本地字节或把旧账号结果发布给新账号。

### 9.2 上传发布

上传先验证归属、锁定账号分配，再落盘，阻止“先覆盖文件、随后数据库失败”的破坏路径：

- 受限路径与目录访问，拒绝符号链接；
- 同目录唯一临时文件、flush/fsync、no-replace hard link 发布；
- 不使用覆盖式发布，已有目标必须核对；
- 文件系统锁协调发布与磁盘空间检查；
- 失败只清理由本次新建且 inode 匹配的文件；
- 同账号完整资源幂等，修复不能覆盖已有不同字节。[S11]

### 9.3 事务不确定性

数据库与文件系统不是统一事务。COMMIT 回执丢失时，不能断言未提交并删除可能已引用的图片；当前返回暂不可用、保留可能已提交字节并允许重试核对。

进程中断可能遗留中间或孤儿文件，本基线无自动清理器。清理需停写、备份、只读对账后明确处理，不能仅凭一次“未引用”查询盲删。该选择优先防误删，不声称永远无残留。[S11]

## 10. 限流与资源治理

### 10.1 默认应用边界

| 项目 | 默认 |
| --- | --- |
| 注册 IP 尝试 | 5 次/小时 |
| 注册全实例尝试 | 100 次/滚动 24 小时 |
| 登录 IP 尝试 | 30 次/分钟 |
| API IP 请求 | 240 次/分钟 |
| 上传 IP / 账号尝试 | 各 20 次/分钟 |
| 媒体读取账号请求 | 120 次/分钟 |
| 每账号媒体实际字节 | 500 MiB，原图+缩略图 |
| 每账号媒体记录 | 1000，包含元数据空槽位 |
| 媒体文件系统空闲储备 | 1 GiB |

这些值可配置，需结合容量和监控调整，不是压测得到的规模承诺。失败与畸形请求消耗尝试预算，高成本密码处理前即执行相应保护。[S11][S16]

### 10.2 分层与限制

Nginx 的 API IP 限速与请求体控制，和应用的尝试限流、读取体积、账号物理配额并存；只调整其中一层不会改变另一层。[S11][S13]

- 429：请求过频，明确提示并参考 Retry-After。
- 413：请求过大或媒体配额超限，保留本地内容。
- 503：存储、空间或提交等暂不可用，不伪报成功或盲删字节。

当前限流为进程内存状态，重启重置、多进程不共享。全局注册尝试预算可能被恶意耗尽；它不是完整反机器人/DDoS 防护。媒体配额也不是日记正文、账号总数或全系统磁盘硬配额；多账号累积仍可能耗尽服务器。物理字节统计有成本，不能把返回行数限制当作数据库扫描成本上界。[S11]

## 11. 部署拓扑与运行责任

### 11.1 拟定方式，不代表已部署

```text
https://cinaka.com
       └── Nginx
           ├── / → /webs/frontend（本地 build 后上传）
           └── /api/ → 127.0.0.1:8000
                            └── FastAPI / Conda
                                ├── MySQL 127.0.0.1:3306
                                └── /webs/static/aaa（私有媒体）
```

目标为 Oracle ARM Ubuntu 24，同机 MySQL、无 Docker、手工部署。`/webs` 是示例绝对路径，实际不同则统一替换；目录名 static 不代表公开权限。

### 11.2 生产最低要求

- 有效 HTTPS 与可验证续期，正式登录不使用明文 HTTP；
- DEBUG=false、独立随机 JWT 密钥与数据库凭据；
- 非 root 运行、回环监听、单 worker；8000/3306 不开放公网；
- 可信代理与真实 IP 明确，不盲信客户端 X-Forwarded-For；
- MySQL 版本、utf8mb4、UTC 与 ngram 配置兼容迁移；
- 迁移明确确认目标库与 revision 后执行；
- 网站根不包含源码、.env、备份和私有媒体；
- 同版前后端、正式域名冒烟、备份与独立恢复验证。[S3][S12][S13][S14]

ARM64 依赖安装、systemd、Nginx 需在目标机实测，不能以其他架构本地构建代替。单机整机故障会影响应用和数据库，不是高可用拓扑。

## 12. 测试与已知限制

### 12.1 证据分层

测试包括纯规则、注入端口、真实文件、HTTP/数据库、浏览器/设备和生产冒烟。SQLite、SQL 编译或模拟锁不证明 MySQL 锁等待；Chromium 不替代 Safari/Firefox；build 不证明打印完整；健康 HTTP 200 也需看数据库状态。

- 合并前用户报告定向 pytest、Ruff、前端安全测试和 build 无错误，浏览器媒体鉴权无问题；没有全部原始日志，不补造计数与逐平台结果。[S18]
- P4/P5/P6 的环境、计数及反馈边界保留在阶段材料；不把历史数量相加成当前 main 的一次全量通过。[S5][S6][S7]
- 合并成功不等于 CI 通过，没有运行记录就不登记绿色流水线。

## 13. 备份恢复与发布治理

防蠹 JSON 用于应用数据备份恢复；杀青 PDF/纸张用于阅读成册，不包含完整可恢复状态。[S7]

服务端需备份数据库、媒体目录和必要配置/密钥，并保持同一时间窗口的一致性。只备份 SQL 会缺图片，只复制图片会缺归属与关系。可接受维护窗口时停 API 与其他写入者后备份；在线备份需单独设计。

备份是私密资产，不放 Web 根、公开存储或仓库。设置受限权限、加密异地副本、保留周期与恢复演练；在独立数据库和媒体根恢复，验证正文、图片字节和账号隔离，不以“压缩包能打开”代替恢复成功。

发布应记录实际 SHA、依赖清单、revision 和配置差异；不自动升级或改无关架构。合并、迁移、部署分别授权。保留阶段分支、验收源码和真实结果，可再生构建物与唯一证据分开处理。先备份再切换一致的前后端，避免半套 assets；回退先评估 schema 兼容性，不能把 downgrade 当通用撤销。

## 14. Redis与小程序演进

本节是建议，不是已实现能力，也不授权立即新增依赖或开发。

### 14.1 Redis 按需求引入

自用和少量朋友分享优先保持单进程 Web 稳定。Redis 当前默认关闭，只有可选健康检查配置；启用开关不会迁移业务限流，environment.yml 也没有完整业务接入所需的 Redis 依赖配置。[S3][S11][S16]

| 触发需求 | 可评估用途 | 必须定义 |
| --- | --- | --- |
| 多 worker / 多实例 | 共享限流 | 原子性、TTL、故障策略、真实 IP |
| 公开推广/验证码 | 短期验证状态与集中风控 | 平台/邮件等流程，不能只安装 Redis |
| 实测重复查询瓶颈 | 针对性缓存 | 失效、隐私、容量与监测 |
| 明确后台任务 | 队列和执行器 | 幂等、重试、持久性和清理；Redis 本身不等于可靠任务系统 |

接入后 MySQL 仍是持久业务来源，不默认缓存私密正文/图片，Redis 故障也不能悄悄变成无限注册上传。公开推广前重新评估共享防滥用；有小程序不天然要求 Redis。

### 14.2 小程序共用后端，适配客户端

按微信原生小程序方向评估：现有 Vue/Vite Web 工程不能直接打包原生小程序。uni-app 等 Vue 路线可能降低部分学习成本，但不自动解决 Tiptap、Dexie 和浏览器依赖。[S2][S4]

| 层 | 复用判断 | 工作重点 |
| --- | --- | --- |
| MySQL / 领域数据 | 优先沿用 | 归属与 schema 兼容 |
| FastAPI 业务与媒体服务 | 优先共用 | 新客户端认证、请求和上传适配 |
| 同步规则/协议 | 沿用规则，评估代码 | 不假设当前实现全部平台无关 |
| TS 类型/纯逻辑 | 逐模块提取 | 排查 DOM、Dexie、Vue 耦合 |
| 本地数据库 | 不原样复用 IndexedDB | 重新定义配额、文件、事务与恢复 |
| Tiptap 编辑器 | 不原样复用 | 内容共同子集与无损往返 |
| 页面/媒体展示 | 可参考设计 | 平台组件、文件及鉴权展示 |
| 打印/PDF | 首版建议留在 Web | 不直接外推系统能力 |

认证刷新目前依赖浏览器 HttpOnly Cookie，小程序需要独立适配，不应降低 Web 安全。若引入微信身份，应设计与现有邮箱账号绑定，避免两套孤立数据。[S15]

最大风险是内容兼容：小程序不认识某富文本节点时，不能打开保存后静默丢掉原文。应定义共同 schema、保留未知内容，或在无法保证无损时只读。

先验证同账号登录、读取、文字图片新建、网页同步和复杂内容不损坏，再确定小程序最小首版；暂缓复杂预简、完整离线、简册打印。私有图片不能为适配退回公开 URL。平台主体、域名、隐私、内容安全与审核按开发时官方规则核对，本文不保证政策结论或审核通过。

## 15. 结论与资料索引

青简的技术重点是以本地记录保持写作连续性，以明确的账号/同步状态实现云端中转，以受控只读会话提供简册和打印，以私有媒体及有界资源保护支撑小规模运行。

后续先做稳定部署、真实环境验证、备份恢复和缺陷修复，再按需求扩展 Redis/PWA/跨端。始终保持三条底线：**不丢内容、不跨账号、不把未完成说成成功。**
