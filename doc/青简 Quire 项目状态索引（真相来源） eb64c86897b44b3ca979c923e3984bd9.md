## 四、生效中的技术决策

凡与主文档原始方案冲突，以本表为准。

| 决策 | 结论 | 理由 |
| --- | --- | --- |
| 容器化 | **不用 Docker**，手动部署 | 用户自行部署，Docker 增加不必要复杂度 |
| Python 环境 | **完全 conda**，环境名 `quire`，Python 3.12 | 不用 uv。镜像源**纯 conda-forge**，清华源已无 `pkgs/free` 与 `pkgs/r` |
| Redis | **P0 / P1 完全不用** | 原方案的缓存与限流在这两阶段无实际用途 |
| 主键 | UUID **v7**，存 `BINARY(16)` | v7 前 48 位是毫秒时间戳且大端序，天然递增，不造成 B+ 树页分裂 |
| UUID 字节序 | **直接存 `value.bytes`，绝不交换** | 字节交换（等价 `UUID_TO_BIN(x, 1)`）是为 v1 设计的，对 v7 反而破坏顺序性 |
| 外键 | **故意全部不加** | 便于分库与软删除，一致性在应用层保证 |
| 时间存储 | 所有 `DATETIME(3)` 存 UTC | 见项目状态索引第五节 |
| `entry_date` | `DATE` 类型，客户端按本地时区算好传入 | 回答「这篇算哪一天的」，与时区无关 |
| 全文检索 | MySQL FULLTEXT + ngram 解析器，`ngram_token_size = 2` | 中文分词最小可用配置 |
| 前端栈 | Vue 3 + Vite + TypeScript |  |
| 样式方案 | **混合**：CSS 变量做地基 + Tailwind 管布局 | 令牌集中在 `src/styles/index.css`，是唯一真相来源 |
| 农历库 | **`lunar-typescript`** | 宜忌开箱可用，纯算法推导、无需年度维护 |
| 星座运势 | **不做** | 用户明确否决。若将来要做，推到 P2 由后端代理并加缓存 |
| 中文字体 | 令牌 `--font-cn-kai`，完整黄历区用楷体 | 层级靠**字号**不靠加粗——多数系统楷体单字重，伪粗会抹平笔画 |
| 农历库体积 | **不做动态 `import()`，不手配 `manualChunks`** | gzip 后首屏约 169 KB，未达优化阈值。P1-6 真机弱网测过再评估 |
| 正文格式 | **Tiptap JSON**，外层包 `schemaVersion` | 小程序端跑不了 Tiptap，但能读同一份 JSON。选 JSON 而非 HTML 正是为此 |
| 正文双存 | `content`（JSON）+ `contentText`（派生纯文本） | JSON 无法全文检索，纯文本无法恢复编辑状态，两者都要 |
| 图片存储 | `src` 永远是 `local://media/{id}` | 见下方铁律 |
| Tiptap 版本 | **锁 `^2`** | v3 把 `Placeholder` 挪进 `@tiptap/extensions`、改了 NodeView 注册方式
已确定均为2.27.2版本 |
| P1 数据落点 | **只在浏览器 IndexedDB**，完全不经过后端 | 已建的五张 MySQL 表要到 P2 才开始接收数据 |
| IndexedDB 布尔 | 一律用 `0 / 1` 数字字段 | 见下方铁律 |
| 多端范围 | **三个平台**：PC Web、移动 Web、小程序 | 原方案说「PC + 小程序」是漏算 |

## 五、铁律

违反这些不会立刻报错，但会造成静默的数据损坏。

1. **`contentText` 只能由 `content` 派生，且必须同一次写入。** 分两次写、或漏掉重算，搜索会永远停留在旧内容上，且不抛任何异常。实际由 `entryRepo` 内部完成——**调用方不要自己传 `contentText`**（`EntryCreateDto` 里没这个字段）。
2. **`toPlainText()` 接收的是 `EntryContent` 整包，不是裸 `doc`**。它内部读 `content.doc`；传裸 doc 会静默返回空串。
3. **`update` 必须逐字段判断 `!== undefined`**，不能用对象展开。否则「只想改标题」会把正文清空。
4. **IndexedDB 里凡需索引的布尔语义，一律用 `0 / 1`**。IndexedDB 会跳过索引键为 `null` / `undefined` 的记录，用 `deletedAt` 当索引查未删除项会永远返回空，且不报错。
5. **图片 `src` 永远是 `local://media/{id}`，绝不能是 blob URL。** blob URL 是页面级临时凭据，刷新即失效；存进 JSON 就是不可逆的数据废弃（原图还在库里但找不回来）。
6. **`src/shared/` 必须是纯 TS**：禁 `window`、`document`、Vue API、Dexie、Tiptap。这一层将来要被小程序端直接复用。Tiptap 相关代码放 `src/editor/`。
7. **上层只 import `@/repo`**，绝不直接碰 `@/db/*`（唯一例外是 `src/repo/index.ts` 本身）。
8. **时间**：后端统一走 `utcnow()`，禁用 `datetime.now()`；前端取本地日用 `todayLocal()`，**禁用 `toISOString().slice(0, 10)`**（那取的是 UTC 日期，只在凌晨 0–8 点窗口出错）。
9. **超过 20 行的代码写进 Notion 页面**，不在聊天里贴。聊天的 Markdown 会吞掉双下划线、超长代码块会中途跳出格式——已直接导致过缩进事故四次。
10. **浏览器控制台里不能用 `@/` 别名**，那是构建期别名。dev 下用 `/src/shared/almanac.ts` 这类绝对路径带扩展名，或用已挂好的 `window.$repo` / `window.$almanac`。
