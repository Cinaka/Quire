# P4 图片补齐隔离验收指南

适用：P4-4F2C6专用浏览器宿主。**用户已报告本机全流程通过、无控制台错误，最终补齐并刷新后仍可读取**；记录见[图片补齐浏览器验收记录](<P4 图片补齐浏览器验收记录.md>)。这不是整批P4完成记录，未附逐项原始日志或本机精确HEAD。

P4-4F2C8已在同一5181隔离页接入P4-4F2C7双方核对/空文件保存回读面板。**第6节是本轮新增待验，不在此前用户已通过范围。** 保留当前已补齐验收库，不清库重放；先完成原有补齐、再做一次最终交接，禁止为了测试另一选择而重置现有数据。

## 1. 范围与隔离

- 独立地址：`http://127.0.0.1:5181/p4-resource-acceptance.html`。
- 专用库：`quire-p4-resource-acceptance`；不用日常`quire`或旧5179游客验收库`quire-p4-acceptance`。
- 固定演示身份只存在于专用构建内，不是登录账号/JWT，不创建或清理真实凭据。
- 文件选择/真实Dexie与IndexedDB补齐走现有内部工厂；“云端证明”**只是本地模拟数据**，没有HTTP、后端启动、媒体下载、同步或生产部署。
- 专用构建替换单例库名和tokenStore为无令牌演示身份，并只在该构建注入事务暂停钩子；普通dev/build不启用。页面显示的证明/取舍文字不能当作真实服务端确认。
- 不提供清库、覆盖、重新认领或追加夹具。不要放入真实日记/文件/token；已有未知数据时拒绝，不通过清除日常数据解决。

## 2. 拉取、检查与启动

先确认工作区干净；有本地改动先保留并核对，不用reset覆盖。

```bash
cd ~/Documents/Quire
git status --short
git pull --ff-only origin p4/schedules
git rev-parse HEAD
cd frontend
npm run check:p4
npm run test:p3

# 如日常地址不是localhost:5173，下面两行都替换成实际完整origin。
P4_RESOURCE_DAILY_ORIGIN='http://localhost:5173' npm run build -- --config vite.p4-resource-acceptance.config.ts
P4_RESOURCE_DAILY_ORIGIN='http://localhost:5173' npm run dev -- --config vite.p4-resource-acceptance.config.ts
```

前面的检查/专用构建成功后，再打开上述5181完整地址。不要改成localhost，不用普通dev访问新HTML，不占用/替换旧5179页。不需要启动后端，不运行数据库迁移。

浏览器需支持`indexedDB.databases()`；不支持、同名未知库/旧版本、错误origin/标记或已有token时会拒绝。建议关闭其他该验收origin标签页，使用专用浏览器配置文件。

**只通过专用Vite dev服务验收。** build仅验证打包，当前文档不授权把dist放到生产、普通静态服务或Vite preview；后者没有同样的专用dev中间件/CSP闸门。

## 3. 初始化与材料

1. 核对日常/隔离地址，勾选不放真实数据的确认，点击“明确进入隔离验收”。进入前先做原生只读预检；无业务/Vue/Dexie导入。首次进入只登记验收标记，不自动创建夹具、选择文件或打开面板。
2. 点击“仅在空验收库创建一次夹具”。成功后的只读状态应是：
   - 来源/日记/首次意图/候选：`1 / 1 / 1 / 1`。
   - 媒体行/补齐留档：`0 / 0`。
   - 原图/缩略图摘要：两者均“尚未补齐或不同”。
3. 点击“下载验收材料JSON（不是保存确认）”，自行确认下载目录出现`quire-p4-resource-fixture-v1.json`。这是固定非私人样例材料；下载点击不是业务冲突证据落盘确认。
4. 点击“明确打开补齐面板”。选择刚下载的文件，勾选唯一的验收图片。此时仍不应自动准备/写入。该页只接受固定夹具材料，不拿真实证据包做测试。

若重复点创建收到拒绝，保留已有数据，改用“读取验收状态”；不要再次追加、清库或覆盖。完成最终补齐后的库不能当作全新缺失资源场景重放。

## 4. 先做取消测试，再做最终成功补齐

成功补齐后图片不再缺失，因此**务必按下列顺序**。整个过程中可用Network面板确认无`/api`/`/media`请求、无外部云端请求；HMR/静态模块请求正常。

### A. 模拟证明暂停时停止

1. 完成文件和图片选择后，点宿主“暂停下一次模拟证明（不发网络）”。
2. 点面板“准备补齐计划（不写入）”；上方应显示暂停在“本地模拟证明”。
3. 点面板“停止后续步骤”。暂停应结束；旧计划不能晚到后显示成功或自动补齐。
4. 点“读取验收状态”，应仍为保护`1/1/1/1`、媒体/留档`0/0`。
5. 不设置暂停，再点准备。应显示新计划：**新建媒体行、补原图、补缩略图**。未勾选确认时不能应用。

换文件、取消文件选择或改选图片也应让旧计划/确认失效；不自动生成新计划。测试这些动作后需要重新选择、准备。

### B. 真实事务内暂停时停止或关闭

1. 准备好新计划后，点宿主“暂停下一次真实写事务（最多10秒）”。
2. 勾选面板的明确确认，再点“明确确认并补齐本机图片”。
3. 看到“真实IndexedDB事务内复验”暂停后，**10秒内**点“停止后续步骤”或“停止并关闭”。专用钩子在真实事务的Blob复验阶段等待，Dexie.waitFor仍受10秒限额保护。
4. 等旧操作结束，点“读取验收状态”：媒体/留档仍应`0/0`；来源/日记/首次意图/候选仍为`1/1/1/1`。不能留下半批字节或审计。
5. 如超过10秒，失败并要求重新准备是预期；不以超时替代手动取消验收。关闭后要明确重开面板、重选文件/图片并新准备。

该人工暂停验证真实事务**复验阶段**的取消，不等于覆盖所有写入中途/提交竞争；沙箱另有写后与提交先赢的回归用例。取消也不能撤销已提交内容。

### C. 不暂停，最终明确补齐

1. 不设置暂停，重新准备并核对计划。
2. 另行勾选“仅补齐缺失图片、日记/标签/保护不变”，点击明确补齐。
3. 成功后点击宿主“读取验收状态”：
   - 媒体/留档：`1 / 1`。
   - 实际原图/缩略图摘要均“是”。
   - 来源/日记/首次意图/候选保持`1 / 1 / 1 / 1`。
4. 关闭面板，刷新并重新明确进入；不要再次创建夹具，直接只读核对，应保留上述状态。
5. 已有完整图片再准备被拒绝是预期，不会重复补齐或追加审计，不应自动解除首次意图/候选。

## 5. 记录与停止条件

请保留：精确HEAD、普通/专用构建完整结果、P4/P3汇总、浏览器版本、A/B/C各步骤结果，以及控制台/Network异常（如有）。仅有“继续”不登记上一批通过。

如果出现默认库访问、API/外部请求、已有数据被覆盖、身份/保护数量变化或取消后出现错误补齐，停止操作，保留验收库和日志，不清除来掩盖问题。

本指南不验收真实账号、网络租约、MySQL、双设备、云端取舍、不同字节/共享标签冲突、永久弃去、完整业务备份恢复或正式文件保存确认；这些仍按真相来源列为剩余事项。


## 6. 新增：真实证据文件保存与一次明确交接（P4-4F2C8，待本机验收）

### 6.1 启动与现有数据

继续使用第2节相同专用build/dev命令和完整5181地址。不需要启动后端或迁移。请使用安全上下文中支持`showSaveFilePicker`的浏览器（如支持该接口的Chrome/Edge）；如果页面提示不支持，保存交接入口应阻塞，不用普通下载代替。未实测的浏览器版本不预先标为兼容。

你已完成补齐：**不要再点创建夹具，不用重下补齐材料，不清空数据库。** 更新后重新进入，点“读取验收状态”，应为：

- 阶段“受保护、尚未交接”；来源/日记/首次意图/候选`1/1/1/1`。
- 本机媒体行/补齐留档`1/1`，两份实际摘要均“是”，交接留档`0`。

如果没有完成补齐，先做前面的流程；已有未知状态被拒绝时保留数据与日志。最终交接后合法阶段是`1/1/0/0`，不要再要求首次意图/候选保持1。后续只读状态验证会严格核对来源、所选日记、基线、完整双方留档、原补齐留档及实际图片，不放宽成接受任意已有数据。

关闭补齐面板后，点“明确打开证据保存与交接面板”。两个面板不能同时持有验收会话。此时尚未读取双方、弹保存器或进行交接。点“明确读取当前双方版本”，应显示：

- 本机标题：`验收：受保护图片日记`。
- 模拟云端当前标题：`验收：模拟云端当前图片日记`。
- 两个选择都没有默认勾选，都接受同一模拟云端终态来源；图片内容及标签定义一致。标题差异只为本次夹具演示，不来自HTTP。

明确选择一种取舍后，先尝试取消原生保存窗口，应无保存授权/业务交接，重新选择才可继续；选择已有非空文件应拒绝覆盖，原文件需保留。

### 6.2 先做取消：证明暂停与已保存文件不等于交接

**暂停应在读取预览、选择取舍和选好文件之后设置。** 重新读取双方会失效旧票据并清除暂停；不要在读取之前设置后等待它触发。每次取消后都需重新读取/选择全新空文件，确认不沿用。

A. 模拟证明阶段取消（无网络）：

1. 读取双方后明确选择一种取舍（建议本轮最终选“采用云端当前日记”，便于看到标题变化），选择全新空JSON文件。
2. 点宿主“暂停下一次交接模拟证明”，另行勾选面板确认，点“明确保存、回读并尝试交接”。
3. 暂停在本地模拟证明时，点面板“停止后续步骤”。旧操作不应晚到后成功或保存；关闭面板，再只读核对仍为保护`1/1`、交接留档`0`。原生选择器可能已创建空文件，不能把空文件存在当保存成功。

B. 文件已经保存、真实事务取消：

1. 明确打开/读取新预览，重新选择取舍与**新的空JSON文件名**。
2. 点宿主“暂停下一次交接真实事务（最多10秒）”，另行确认并提交。
3. 看到“真实IndexedDB事务内复验”暂停时，在**10秒内**点“停止后续步骤”或“停止并关闭”。文件此时可能已真实close且回读过，不能删除它或宣称文件未写入。超时只算失败重核，不代替手动取消验收。
4. 等旧操作结束并关闭面板，点读取状态：首次意图/候选仍`1/1`，交接留档仍`0`，媒体/原补齐留档仍`1/1`，摘要均“是”。不能留下半次来源/日记/基线/交接留档写入。
5. 用页底“明确重新打开已保存双方证据JSON”选择刚保存的取消场景文件。应提示**文件完整性通过，但当前验收库尚未交接**；只读回读不执行历史选择、不解除保护。

上述人工事务暂停点覆盖复验阶段，不是所有提交竞争的浏览器证明；事务提交先赢不能撤销的规则仍有效。

### 6.3 不暂停，最终交接一次

1. 不设置暂停，重新打开新会话/读取双方、选择取舍。没有默认选择，不把先前文件choice当作本次授权。
2. 选择**另一个全新空JSON文件**；旧文件非空应拒绝，不覆盖。核对私人内容保存提醒，再单独勾选并提交。
3. 成功应说明双方证据已保存并回读、仅本来源明确交接，没有启动P2/上传/同步。关闭面板并只读读取状态：
   - 来源/日记/首次意图/候选：`1/1/0/0`；交接留档`1`。
   - 本机媒体/原补齐留档：`1/1`；原图/缩略图摘要仍均“是”。
   - 若采用云端，标题为`验收：模拟云端当前图片日记`，dirty为`0`。
   - 若保留本机，标题仍`验收：受保护图片日记`，dirty为`1`，仅表示后续待P2同步，本页不会启动它。
4. 刷新并重新明确进入，不创建夹具；读取状态应保持所选结果。重新交接/补齐入口不应再开放，不生成第二份日记或重复交接留档。
5. 从页底明确重新选**最终成功那次**证据文件，应该提示“文件完整性与本次交接留档一致”。取消场景的旧文件不当然代表本次留档，不用它替代最终文件；未知/损坏/完整内容不同的文件应拒绝，不写库/自动恢复。

一次现有库只做一种最终选择。两种选择均有沙箱组合回归，但这不等于两种都已在本机浏览器实测，不要清库来凑两次通过。全程不应出现API、媒体代理或外部云端请求；保存窗口/文件操作是本机浏览器接口。
