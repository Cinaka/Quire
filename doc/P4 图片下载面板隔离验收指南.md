# P4 图片下载面板隔离验收指南

适用P4-4F2C11。**模拟云端证明与图片响应，实际前端校验、Blob和IndexedDB事务。不是实际HTTP下载、真实账号或双设备验收。**

## 1. 隔离与范围

- 固定地址：`http://127.0.0.1:5182/p4-resource-download-acceptance.html`。
- 专用库：`quire-p4-resource-download-acceptance`，新origin、新标记。保留旧5181图片补齐/保存交接库、5179游客验收库及所有证据文件，不迁移、不清除或重放。
- 日常origin必须显式配置，下例以`http://localhost:5173`为例；如你的实际日常地址不同，请替换环境变量，不猜测或复用日常地址进入隔离页。
- 新面板使用独占注入port。构造、选图片不下载；明确下载准备后仍只留内存，另行勾选确认才能整批补齐。没有默认全选、默认真实HTTP传输、登录/上传/同步/清库/删除图片按钮。
- 专用配置固定5182/strictPort，无API/media代理，并阻断默认main/router/request及其他HTML；tokenStore替换为无JWT的构建内演示身份，不写凭据。CSP不允许外部网络。普通dev/build不启用该身份或库名。
- 原生只读预检先于Vue/Dexie/业务动态导入。已存在同名库须为已登记的v3（原生version30）及精确marker；未知库、旧marker、已有token均拒绝接管，不升级、清除或删除。浏览器需支持`indexedDB.databases()`。

## 2. 拉取、检查与启动

在仓库根目录、工作区干净后：

```bash
git status --short
git pull --ff-only origin p4/schedules
cd frontend
npm run check:p4
npm run test:p3
P4_RESOURCE_DOWNLOAD_DAILY_ORIGIN=http://localhost:5173 npm exec -- vite build --config vite.p4-resource-download-acceptance.config.ts
P4_RESOURCE_DOWNLOAD_DAILY_ORIGIN=http://localhost:5173 npm run dev -- --config vite.p4-resource-download-acceptance.config.ts
```

然后打开上述5182完整地址。保持5173/5181原数据不动，不运行数据库迁移或依赖升级，不把真实凭据/日记放进新验收库。

沙箱未执行完整vue-tsc/Vite或P3；请保留本机命令日志及精确HEAD。已有后端下载接口的响应头修复后全量结果仍以原backend本机日志为准，前端模拟页不能补记其通过。

## 3. 首次进入与空夹具

1. 页面最上方勾选隔离确认，再点“明确进入隔离验收”；只创建专用marker，不自动创建业务夹具或下载。
2. 点“仅在空下载验收库创建一次夹具”。
3. 应显示来源/日记/首次意图/候选 **1/1/1/1**，媒体/下载留档 **0/0**，原图/缩略图尚未补齐。
4. 已有夹具时不再点创建；重复创建会拒绝，不会追加/覆盖。已有同名库被拒绝时保留其数据并反馈，不通过清库绕过守卫。

接下来请**先完成取消场景，再最终补齐**，不要先成功补齐后删除图片以重复测试。

## 4. 下载准备取消（无网络）

1. 点“明确打开模拟下载面板”，初始不默认选择、不准备计划。
2. 明确勾选唯一的验收图片。
3. 点“暂停下一次模拟图片响应”，再点面板“下载并准备计划（不写入）”。
4. 看到图片响应暂停后，点面板“停止后续步骤”或“停止并关闭”。
5. 读取验收状态，应仍为 **1/1/1/1、0/0**，没有半批图片或下载留档。

可用“暂停下一次模拟证明”同样验证取消。先选图片、再设置暂停：更改选择会使旧计划及暂停失效。

## 5. 准备完成不等于写入

1. 重新打开面板（若尚未关闭可继续），明确勾选图片，直接点“下载并准备计划（不写入）”。
2. 应出现新建媒体行、补原图/缩略图的计划。此时不要勾选确认。
3. 读取状态仍为 **0/0**。点“停止并关闭”，再读取仍为 **0/0**。
4. 重新打开不会恢复旧下载计划；须重新明确选择/下载。

## 6. 真实事务内取消

1. 重新选图片并完成准备计划。
2. **准备成功后**点“暂停下一次真实写事务（最多10秒）”。不要在准备前设置此暂停。
3. 勾选“我确认仅补齐…”并点“明确确认并补齐本机图片”。
4. 看到真实IndexedDB事务暂停后，**10秒内**点面板停止或关闭，不要放行。
5. 等操作结束后读取状态，仍为 **1/1/1/1、0/0**。若超时，保留当前数据并反馈，不宣称已通过取消；需重新准备。

取消不是撤销按钮。已提交后的停止/关闭只能要求重新读取，不能承诺回滚成功或清空已保存图片。

## 7. 最终一次补齐与刷新

1. 重新打开、选图片、下载准备，不设置暂停。
2. 核对计划，单独勾选确认，再明确补齐。
3. 关闭面板，读取状态：来源/日记/意图/候选仍 **1/1/1/1**；媒体/下载补齐留档 **1/1**；实际原图/缩略图一致均为“是”。
4. 刷新5182页面，重新明确进入，仅点“读取下载验收状态”；上面的数值应保持。刷新不会自动下载、重放计划或解除保护。
5. 再明确打开面板、选同一图片并准备，应拒绝已有完整资源的空操作；媒体/留档仍 **1/1**，不新增副本。

本页不接证据保存或双方交接，不解除首次意图/候选，不启动P2。这些只在既定其他流程独立确认，旧5181验收结果保持原范围。

## 8. 反馈与未验范围

请反馈：精确HEAD、浏览器版本；check:p4/test:p3及专用build日志；图片响应取消、准备后关闭、事务内取消、最终补齐与刷新数值；控制台及Network是否异常。Network不应出现业务API、媒体HTTP请求或真实认证请求；Vite模块/HMR不算业务网络。

本批全量38文件1478项通过（含新增90项）。自动测试是实际运行源码/crypto/Blob、模拟事务与传输及组件/配置静态断言，不是实际DOM或浏览器IndexedDB证据。**尚待真实浏览器反馈**；真实账号HTTP、流式限额、跨设备、不同资源/共享标签冲突、删除不一致/purged/未知回执/永久弃去及完整P4仍未完成，未合并main或部署。
