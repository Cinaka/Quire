### 二、src/main.ts 完整替换

**三处改动**：① 删 Pinia 相关四行（import 两行、`createPinia()`、`pinia.use()`）与 `app.use(pinia)`；② 不再 import `./styles/main.css`；③ DEV 块删 `$router`、补挂 `$almanac`。

**没有改动的**：`purgeOrphans` 整段连注释原样保留，位置仍在 `app.mount` 之后（P1-5 页第 11 节定的接入点）；`import * as repo` 仍是静态导入。

```tsx
import "@/styles/index.css"

import { createApp } from "vue"

import App from "./App.vue"
import router from "./router"
// 静态导入整个 repo 命名空间：既给下面的 purgeOrphans 用，
// 也让 DEV 调试句柄不再需要顶层 await import()
import * as repo from "@/repo"

// 拆开链式调用，才能在 mount 之后继续往下写
const app = createApp(App)
app.use(router)
app.mount("#app")

/**
 * 清理孤儿图片。三个刻意的选择：
 *   1. 放在 mount 之后 —— 它跟首屏渲染没有任何关系，不能让它挡在前面
 *   2. 不 await（fire-and-forget）—— 失败了也不该影响应用启动
 *   3. 默认只清 24 小时之前的 —— 正在另一个标签页里编辑、还没保存的图片
 *      entryId 同样是空串。不设这个窗口就会把它们删掉，用户那边表现为
 *      「图片突然变空白」，且完全无法归因。
 */
void repo.mediaRepo
  .purgeOrphans()
  .then((n) => {
    if (import.meta.env.DEV && n > 0) console.info(`[quire] 已清理 ${n} 张孤儿图片`)
  })
  .catch((err) => {
    console.warn("[quire] purgeOrphans 失败", err)
  })

// DEV 调试句柄，生产构建整块摇掉。铁律 10 依赖这两个句柄，P1 阶段保留。
// $router 已删：那是 P1-4 验收组件复用串文 bug 时的一次性工具。
// $almanac 用动态 import 挂：农历库 gzip 98 KB，静态导入会把它拽进 dev 的
// 初始依赖图；也不用顶层 await，那会挂住整个模块求值、拖长 dev 首屏。
if (import.meta.env.DEV) {
  Object.assign(window, { $repo: repo })
  void import("@/shared/almanac").then((m) => {
    Object.assign(window, { $almanac: m.getAlmanac })
  })
}
```

<aside>
💡

**为什么 `$repo` 静态、`$almanac` 动态，不是不一致。** `repo` 无论如何都要在启动时求值——下面的 `purgeOrphans` 就用它，静态导入不额外增加任何成本。农历库不一样：它只有 `HomeView` 需要，Vite 已经把它拆成独立 chunk（索引页第四节「农历库体积」那条决策）。如果为了挂调试句柄而静态 import，dev 下每次启动都会多加载一个 295 KB 未压缩的 chunk，等于自己把已经拆好的 chunk 又粘回来。

</aside>

### 一、src/shared/types.ts 追加

追加到文件末尾。它是纯数据形状，不依赖 Dexie、也不依赖 `statsRepo` 的实现，本来就该待在 shared 层。

```tsx
/**
 * 本机数据统计。定义放 shared 层：它只是一个形状，
 * 谁来填（Dexie / 将来的小程序存储 / 云端）与它无关。

export interface LocalStats {
  entries: number
  deleted: number
  tags: number
  media: number
  /** 图片原图字节数之和。navigator.storage.estimate() 不可用时的兜底 */
```

### 二、src/db/statsRepo.ts 完整替换

只有两处变化：删掉本地的 `interface`，改成从 `@/shared/types` import type。`load()` 的实现一字不动。

```tsx
import { db } from "./schema"
import type { LocalStats } from "@/shared/types"

export const localStatsRepo = {
  async load(): Promise<LocalStats> {
    const [entries, deleted, tags, media] = await Promise.all([
      db.entries.where("isDeleted").equals(0).count(),
      db.entries.where("isDeleted").equals(1).count(),
      db.tags.count(),
      db.media.count(),
    ])

    // 用 each 逐条累加，不用 toArray()。
    // toArray() 会把所有原图 Blob 同时留在数组里；each 走游标，
    // 每条用完即可回收，只是免不了逐条反序列化。
    let mediaBytes = 0
    await db.media.each((m) => {
      mediaBytes += m.size || m.blob.size
    })

    return { entries, deleted, tags, media, mediaBytes }
  },
}
```

<aside>
⚠️

**不要在 `statsRepo.ts` 里加一句 `export type { LocalStats }` 做兼容。** 那样两个位置都能 import，下次给统计加字段时必然有人只改一处，类型漂移查起来比现在这点改动成本高得多。迁走就是迁走，旧位置不留门。

</aside>

## C3. 统一「已至卷末」的显示条件

索引页第八节记的那条不一致，两处原文：

| 文件 | 现状 | 效果 |
| --- | --- | --- |
| `TrashView.vue`:35 | `v-else-if="page > 1"`，class `end` | 只在确实翻过卷之后提示，楷体居中 |
| `ListView.vue`:57 | `v-else`，class `hint` | 只要没有下一页就提示，**三篇日记也会说「已至卷末」**，且用的是无字族的 `.hint` |

**定案：把 ListView 对齐到 TrashView**，即采用 `page > 1` 这条软条件。反过来把 TrashView 改成无条件是不行的——P1-5 第 12 节 A 组第 5 条已经把「断简里只有三两篇时**不应**出现『已至卷末』」写成了验收判据并且验过了，推翻它等于让一条已验收的用例作废。

### 一、src/views/ListView.vue 三处改动

<aside>
🚩

**第 1 处是这一项唯一的坑，漏了就是静默失效。** `ListView` 现在的 destructure **没有取 `page`**（TrashView 取了）。如果只改模板条件不补这一行，模板里的 `page` 是 `undefined`，`undefined > 1` 恒为 `false`——「已至卷末」**从此再也不出现**，而且不报错、不告警、build 也过。`useEntryList` 本身是返回 `page` 的（P1-4 页第 4 节），只是这里没接。

</aside>

**1. script 段的 destructure**，补一个 `page`：

```tsx
// 改前
const { keyword, order, items, total, loading, hasMore, reload, loadMore } = useEntryList()
// 改后
const { keyword, order, items, total, page, loading, hasMore, reload, loadMore } = useEntryList()
```

**2. 模板里那一行**，就在「再展一卷」按钮下面：

```jsx
<!-- 改前 -->
<p v-else class="hint">已至卷末</p>

<!-- 改后：与断简页同一条口径。只在确实翻过卷（page > 1）且已无下一页时提示；
     首屏就装得下的几条不需要被告知「到底了」，一眼就能看完，提示只是噪声。 -->
<p v-else-if="page > 1" class="end">已至卷末</p>
```

**3. style scoped 段末尾追加 `.end`**（与 TrashView 的 `.end` 逐字一致）：

```css
.end {
  margin: 20px 0;
  font-family: var(--font-cn-kai);
  font-size: 12px;
  line-height: 1.6;
  text-align: center;
  color: var(--color-ink-faint);
}
```

<aside>
🧷

**别去改 `.hint` 本身。** ListView 里 `.hint` 还在给「检简中……」用，而且它跟 `.count`（右上角「共 N 简」）共用一条 `.count, .hint` 选择器。给它加 `font-family: var(--font-cn-kai)` 会把加载提示和计数文字一起变成楷体。新加一条 `.end` 是唯一无副作用的做法。

</aside>

## C4. 首页入口：设置放 header 右上，成编留在「近作」行

## B. media.thumbBlob（缩略图）

### 一、两个待定问题的答案：都不用升

| 问题 | 结论 | 依据 |
| --- | --- | --- |
| 要不要升 Dexie version | **不用** | P1-1 第 5 节 schema 是 `media: "id, entryId, createdAt, dirty"`，`thumbBlob` 不在索引里。Dexie 的 `version()` 管的是**索引声明**，非索引字段是自由形状，直接 `put` 就行 |
| `formatVersion` 要不要 +1 | **不用** | P1-5 第 1 节的 `BackupMedia` 已经有 `thumbBase64: string | null`，第 4 节的导出与导入两条路径也都已经在处理 `thumbBlob`。备份外壳**一字不变**，变的只是这个值从「恒为 null」变成「通常有值」。`formatVersion` 是给结构变更用的，值域变化不算 |

<aside>
🕳️

**批次 B 比原估的还小。** `MediaItem.thumbBlob: Blob | null` 在 **P1-1 第 1 节就已经定义好了**，备份格式也早就留好了位。真正缺的只有一件事：`mediaRepo.add()` 里那行 `thumbBlob: null` **从来没被填过**。这是 P1-1 就挖好、一直空着的坑，不是新开的字段。

</aside>

### 二、两个方向的兼容都得顾

**旧数据进来**：P1-1 到 P1-5 期间贴的图、以及任何旧备份（`thumbBase64: null`）导入后，`thumbBlob` 都是 `null`。所以**读取侧必须容忍 null 并回退原图**，不能假设缩略图一定存在——否则批次 G 的列表缩略图会在旧图上摆一片空白。

**不做启动时批量回填。** 对存量图片逐张解码生成，几百张就是启动时一次长时间占用主线程，而且跟 `purgeOrphans` 抢同一个启动窗口。改成**惰性补生成**：`getThumb()` 发现是 null 就当场生成一张写回去。

### 三、src/capabilities/image.ts（新增）

<aside>
🧱

**为什么放 `capabilities/` 而不是 `shared/`**：缩图要用 `createImageBitmap` 与 canvas，回退路径还要碰 `document.createElement`。铁律 6 要求 `shared/` 纯 TS，而 P1-5 第 3 节建 `capabilities/` 的时候就定了它是「唯一允许摸 document 的地方」。这是该目录的第二个成员。

**签名故意做成通用的 `resizeToBlob`，不是 `makeThumb`**。批次 E 的「图片压缩」需要的是同一个函数，只是 `maxEdge` 大得多（1600 之类）。现在就把参数留出来，E 那一批不用再动这个文件。

</aside>

```tsx
export interface ResizeOptions {
  /** 长边上限（CSS 像素）。短边按原比例缩 */
  maxEdge: number
  quality?: number
  mime?: string
}

/**
 * 把一张图缩到指定长边以内。
 *
 * 返回 null 有两种含义，调用方处理方式一样——「用原图就行」：
 *   1. 原图已经比目标小（不放大：放大只会让文件变大、画质不变）
 *   2. 解码失败（SVG / 动图 / 损坏文件 / 浏览器不支持）
 *
 * 注意它 throw 不出来。缩略图缺失只应降级成用原图，
 * 绝不能让「贴图」这个动作本身失败。
 */
export async function resizeToBlob(
  src: Blob,
  { maxEdge, quality = 0.8, mime = "image/webp" }: ResizeOptions,
): Promise<Blob | null> {
  if (typeof createImageBitmap !== "function") return null

  let bmp: ImageBitmap
  try {
    // imageOrientation 必须显式传。手机拍的竖图靠 EXIF orientation 记旋转，
    // 不传这个选项时部分浏览器会按未旋转的像素解码，
    // 结果是缩略图躺着、原图站着。
    bmp = await createImageBitmap(src, { imageOrientation: "from-image" })
  } catch {
    return null
  }

  try {
    const longEdge = Math.max(bmp.width, bmp.height)
    if (longEdge <= maxEdge) return null

    const scale = maxEdge / longEdge
    const w = Math.max(1, Math.round(bmp.width * scale))
    const h = Math.max(1, Math.round(bmp.height * scale))

    // OffscreenCanvas 不碰 document，优先走它
    if (typeof OffscreenCanvas === "function") {
      const canvas = new OffscreenCanvas(w, h)
      const ctx = canvas.getContext("2d")
      if (!ctx) return null
      ctx.imageSmoothingQuality = "high"
      ctx.drawImage(bmp, 0, 0, w, h)
      return await canvas.convertToBlob({ type: mime, quality })
    }

    // 回退：真实 DOM canvas。只有这一处碰 document，所以整个文件得待在 capabilities/
    const el = document.createElement("canvas")
    el.width = w
    el.height = h
    const ctx = el.getContext("2d")
    if (!ctx) return null
    ctx.imageSmoothingQuality = "high"
    ctx.drawImage(bmp, 0, 0, w, h)

    return await new Promise<Blob | null>((resolve) => {
      el.toBlob((b) => resolve(b), mime, quality)
    })
  } catch {
    return null
  } finally {
    bmp.close()
  }
}
```

<aside>
🔍

**webp 不支持时不会报错。** `convertToBlob` / `toBlob` 遇到不认识的 `type` 会**静默退回 PNG**，于是你拿到一张能用但大得多的缩略图。不必为此加探测（只影响体积，不影响正确性），但验收时若发现 `thumbBlob.type` 是 `image/png`，原因在这里，不是代码写错。

</aside>

### 四、maxEdge 定 480 的算术

两个消费方尺寸不同，取大的那个：

| 消费方 | CSS 尺寸 | 2× DPR 需求 |
| --- | --- | --- |
| 批次 E 九宫格预览 | 容器 `max-w-2xl` = 672px，三列减间距 ≈ **218px** | ≈ **436px** |
| 批次 G 列表缩略图 | ≈ 56–72px | ≈ 144px |

所以 `THUMB_MAX_EDGE = 480`，`quality = 0.8`。480px webp 一张约 30–60 KB，对照原图（手机直出常见 3–5 MB）是两个量级的差别——这正是 P1-4 那句「现在直接读原图 Blob 会让一屏列表吃掉几十 MB 内存」要解的问题。

### 五、src/db/mediaRepo.ts 改两处、加一个方法

`mediaRepo` 早就在用 `createImageBitmap`（`measure()`），本来就不是纯 TS，再多一个 `@/capabilities/image` 依赖不改变分层；铁律 7 禁的是**上层** import `@/db/*`，不管 `db/` 往下依赖。

**1. 顶部追加 import 与常量**

```tsx
import { resizeToBlob } from "@/capabilities/image"

/** 缩略图长边。算术见本节第四小节 */
const THUMB_MAX_EDGE = 480
const THUMB_QUALITY = 0.8
```

**2. `add()` 里把 `thumbBlob: null` 填上**

```tsx
  async add(blob: Blob): Promise<MediaItem> {
    const { width, height } = await measure(blob)
    // 返回 null 就是「不需要缩略图」（图本来就小，或解不了码），
    // 这与旧数据的 null 含义一致，读取侧统一回退原图，不用分两种情形
    const thumbBlob = await resizeToBlob(blob, {
      maxEdge: THUMB_MAX_EDGE,
      quality: THUMB_QUALITY,
    })

    const item: MediaItem = {
      id: newId(),
      entryId: "",
      blob,
      thumbBlob,
      mime: blob.type || "image/png",
      width,
      height,
      size: blob.size,
      sortOrder: 0,
      remoteUrl: "",
      createdAt: utcNow(),
      dirty: 1,
    }
    await db.media.add(item)
    return item
  },
```

**3. 新增 `getThumb()`，带惰性补生成**

```tsx
  /**
   * 取缩略图。永远能拿到一张能显示的图（实在没有才返回 undefined）。
   *
   * 旧图（P1-1~P1-5 期间贴的）与旧备份导入的 thumbBlob 都是 null，
   * 在这里惰性补上。不在启动时批量回填：那等于启动时把全库图片
   * 解码一遍，还要跟 purgeOrphans 抢同一个启动窗口。
   */
  async getThumb(id: string): Promise<Blob | undefined> {
    const m = await db.media.get(id)
    if (!m) return undefined
    if (m.thumbBlob) return m.thumbBlob

    const t = await resizeToBlob(m.blob, {
      maxEdge: THUMB_MAX_EDGE,
      quality: THUMB_QUALITY,
    })
    // 生成不出来就不写库，下次还会再试一次。对「本来就比 480 小」的图
    // 确实是白跑一次 decode，但换来的是不必在库里再存一份几乎等大的副本
    if (t) await db.media.update(id, { thumbBlob: t, dirty: 1 })
    return t ?? m.blob
  },
```

<aside>
⚖️

**一个明知的取舍：`add()` 里是同步 await 生成缩略图的。** 手机直出的 4000px 大图，decode + 缩图可能花几百毫秒，这段时间编辑器里的图还没插入。

选同步是因为它简单且没有竞态——异步补写会出现「先落库为 null、片刻后才有值」，而此间用户可能已经保存并导出了备份。**如果实测卡，不要在批次 B 改**：批次 E 做图片压缩时本来就要重排这条流水线（压缩后的图才是真正要存的原图），到时一并改成「先插占位 → 后台处理」。

</aside>

<aside>
📌

`measure()` 里的 `createImageBitmap(blob)` **没传 `imageOrientation`**，所以带 EXIF 旋转的竖图存下的 `width` / `height` 可能是反的。影响面很小（这两个值目前没有任何消费方），**批次 B 不改**，归批次 E（九宫格要靠它们算宽高比占位，那时才真正要紧）。

</aside>

### 七、批次 B 故意没做的

- **不改 UI**。列表缩略图属批次 G、九宫格属批次 E。B 只把数据准备好，**跑完 B 页面看不出任何变化**——这是正常的，验收全靠控制台
- **不做原图压缩**。那是批次 E，且会改到同一条流水线，两件事分开提交才能分清体积变化是哪一改带来的
- **不动 `remoteUrl` 与 `dirty` 的语义**。缩略图要不要上云、上哪个尺寸，是 P2 同步那一层的设计题
- **不动 Dexie version**。理由见本节第一小节。无事升 version 不是无害的：一旦升了，就得同时维护一段 `upgrade()` 逻辑，而那段逻辑在旧库上只跑一次、几乎无法重复测试

## D1. 编辑器：visibilitychange 时 flush

这一改是 P1-3 第 7 节那个黄框自己点名留给 P1-6 的：`beforeunload` 里的保存不保证成功，因为浏览器卸载页面时不等异步操作，而 IndexedDB 写入是异步的。

<aside>
💡

**为什么 `visibilitychange` 能真解决问题，而 `beforeunload` 不能。**

`beforeunload` 触发时页面正在死，异步写入可能执行不完。`visibilitychange`（切后台）触发时**页面还活着**，IndexedDB 写入能正常完成。而且移动端真实丢数据的路径几乎全是「切后台 → 系统回收 WebView」，不是「点刷新」——iOS Safari 在 App 切到后台时**会**发 `visibilitychange`，却常常**不发**完整的 `beforeunload`。

所以这不是「又加一道保险」，而是**在移动端把唯一可靠的那道补上**。

</aside>

### 一、EntryEditView.vue 改一处

找到现在这段（在 `onBeforeRouteLeave` 下面）：

```tsx
/** 关标签页 / 刷新前落盘。注意这里只能同步触发，await 不会被等待 */
function onBeforeUnload(): void {
  flush()
}

window.addEventListener("beforeunload", onBeforeUnload)

onBeforeUnmount(() => {
  window.removeEventListener("beforeunload", onBeforeUnload)
  flush()
})
```

换成：

```tsx
/** 关标签页 / 刷新前落盘。注意这里只能同步触发，await 不会被等待 */
function onBeforeUnload(): void {
  flush()
}

/**
 * 切后台 / 切标签页时落盘。
 *
 * 只在 hidden 时做。visibilitychange 双向触发，回到前台也会发一次，
 * 而回前台时并没有新输入，白跑一次 persist 没意义。
 *
 * 与 beforeunload 不重复：pending 为 false 时 persist 会直接 return，
 * 两个事件都触发也只会写一次库。
 */
function onVisibilityChange(): void {
  if (document.visibilityState === "hidden") flush()
}

window.addEventListener("beforeunload", onBeforeUnload)
document.addEventListener("visibilitychange", onVisibilityChange)

onBeforeUnmount(() => {
  window.removeEventListener("beforeunload", onBeforeUnload)
  document.removeEventListener("visibilitychange", onVisibilityChange)
  flush()
})
```

<aside>
📎

三个容易写错的细节：

1. **监听的是 `document` 不是 `window`**。`visibilitychange` 在 `window` 上也能冒泡到，但规范上它是 `document` 的事件，写 `window` 属于碰巧
2. **必须判 `hidden`**。不判的后果不是报错，而是每次切回页面都多走一次 `persist`（虽然 `pending` 为 false 时会提前 return，但意图不清）
3. **移除监听不能漏**。`EntryEditView` 是路由组件，反复进出会反复注册；漏了就是每进一次编辑器多一个监听，而旧监听里的 `flush` 闭包持有的是**已卸载组件的 `editorRef`**，切后台时会拿旧快照去写库
</aside>

### 二、debounce 仍然留 800ms，不调短

P1-3 那个黄框给了两个选项（调短 debounce / 加 `visibilitychange`），**只做后一个**。调短 debounce 是用“每次都多写库”去换“极少数情况少丢一点”，而 `visibilitychange` 是零成本覆盖真正的丢数据路径。两个一起做只会让 800ms 这个早已验收过的值白白变得可疑。

### 三、验收

1. **切标签页**：编辑器里输入一段字，**不等 800ms** 立即切到另一个标签页 → 右上角状态应已变「已保存」（切回来看）
2. **真机切后台**（这一条是重点，桌面浏览器测不出真价值）：手机访问 `5173`，输入一段字后**立即回桌面 / 切 App**，等十秒再回来刷新页面 → 内容在
3. **不重复写库**：在 `persist()` 开头临时加 `console.log("persist")`，输入一段字等它自动保存完，再切后台一次 → **不应再打印新的 persist**（因为 `pending` 已是 false）
4. **监听无泄漏**：首页 → 编辑器 → 返回，重复三次；第四次进去输入并切后台 → `persist` **只应打印一次**。打印多次就是漏了 `removeEventListener`
5. `npm run build`

## D2. 自动草稿（已定案 2026-08-24：整项推 P2，P1-6 不做）

<aside>
❓

**定案：不做。不新增 `draftRepo`，不改 `repo/index.ts`，不碰 `meta` 表。**

理由不是成本，是它在当前架构下**解决不了它想解决的问题**：

**P2 再评估。** 接后端后会出现「本地有、服务端没有」的真实中间态，草稿那时才有独立含义（而且那时该叫「待同步」，不是「草稿」）。

1. `meta` 表虽然在 P1-1 第 5 节就建好了（`MetaRow { key, value }`），但 **`repo/index.ts` 没有任何入口暴露它**。铁律 7 下 `EntryEditView` 不能直接碰 `@/db/*`，所以走 `meta` 就必须新增一个 `draftRepo` 并改 `repo/index.ts`
2. 更关键：`meta` 表在 IndexedDB 里，**写入同样是异步的**。用它去兜 P1-3 第 7 节那个「`beforeunload` 异步写不保证完成」的洞，等于用同一根不可靠的管子兜同一个洞

## **E1. 图片压缩：先定最终原图，再测量、再生缩略图**

### **一、定案**

1. **不引入 `browser-image-compression`。** B 批已经有 `src/capabilities/image.ts::resizeToBlob()`，继续复用，避免第二套 canvas / EXIF 逻辑。
2. 可压缩位图统一尝试输出 WebP：长边 `1920`、质量 `0.8`。
3. GIF 原样保留。把 GIF 画进 canvas 会只剩第一帧，这是数据损坏，不是“体积优化”。
4. `resizeToBlob()` 返回 `null`、解码失败或压缩结果不比原图小时，都保留原 Blob。
5. `mime / size / width / height` 必须描述**最终存进 `MediaItem.blob` 的 Blob**，不能继续描述用户选入的原文件。
6. 480px `thumbBlob` 从最终 Blob 生成，缩图与测量并行；仍会发生原图压缩解码、最终图测量解码、最终图缩略解码三次，E1 真机验收必须关注峰值内存，不能把并行误写成“只解码一次”。

### **二、先把 `collectMediaIds()` 移到 `src/shared/text.ts`**

媒体对账、备份导入和编辑保存都需要同一套正文引用解析。它只是纯 JSON 遍历，与同文件 `toPlainText()` 同类，不依赖 Tiptap 运行时：

```
export function collectMediaIds(doc: unknown): string[] {
  const ids: string[] = []

  const walk = (node: unknown): void => {
    if (!node || typeof node !== "object") return
    const value = node as {
      type?: string
      attrs?: { src?: string }
      content?: unknown[]
    }

    if (value.type === "image" && typeof value.attrs?.src === "string") {
      const id = parseLocalSrc(value.attrs.src)
      if (id && !ids.includes(id)) ids.push(id)
    }
    if (Array.isArray(value.content)) value.content.forEach(walk)
  }

  walk(doc)
  return ids
}
```

从 `src/editor/media.ts` 删除旧定义；`EntryEditView.vue` 改为从 `@/shared/text` 同时 import `collectMediaIds / toPlainText`。每个文件改完 build，并确认 shared 没有 Vue / DOM / Dexie / Tiptap import。

### **三、`src/db/mediaRepo.ts`**

顶部补 `import { collectMediaIds } from "@/shared/text"`。在缩略图常量上方补原图参数，并把 `measure()` 与 `add()` 换成下面的形状；文件里的 `get / listByEntry / purgeOrphans / getThumb` 此步不动：

```
const IMAGE_MAX_EDGE = 1920
const IMAGE_QUALITY = 0.8
const THUMB_MAX_EDGE = 480
const THUMB_QUALITY = 0.8

async function measure(blob: Blob): Promise<{ width: number | null; height: number | null }> {
  if (typeof createImageBitmap !== "function") return { width: null, height: null }
  try {
    const bmp = await createImageBitmap(blob, { imageOrientation: "from-image" })
    const size = { width: bmp.width, height: bmp.height }
    bmp.close()
    return size
  } catch {
    return { width: null, height: null }
  }
}

async function compressForStorage(blob: Blob): Promise<Blob> {
  // 动图不能经过 canvas，否则只剩第一帧。
  if (blob.type === "image/gif") return blob

  const compressed = await resizeToBlob(blob, {
    maxEdge: IMAGE_MAX_EDGE,
    quality: IMAGE_QUALITY,
    mime: "image/webp",
  })

  // 小图、解码失败、浏览器不支持，或转完反而更大：全部保留原图。
  return compressed && compressed.size < blob.size ? compressed : blob
}
```

同文件此时就新增全库对账，不能等 G 进列表才做。实现只一次取 Entry JSON 与 media 主键；媒体行在事务中逐条 `get`，避免 `db.media.toArray()` 把全库 Blob 同时握进内存：

```
async reconcileAll(): Promise<number> {
  const entries = await db.entries.toArray()
  const mediaIds = (await db.media.orderBy("id").primaryKeys()) as string[]
  const expected = new Map<string, { entryId: string; sortOrder: number }>()

  for (const entry of entries) {
    const ids = collectMediaIds(entry.content?.doc)
    ids.forEach((id, sortOrder) => {
      if (!expected.has(id)) expected.set(id, { entryId: entry.id, sortOrder })
    })
  }

  let changed = 0
  await db.transaction("rw", db.media, async () => {
    for (const id of mediaIds) {
      const item = await db.media.get(id)
      if (!item) continue
      const next = expected.get(id) ?? { entryId: "", sortOrder: 0 }
      if (item.entryId === next.entryId && item.sortOrder === next.sortOrder) continue
      await db.media.update(id, { ...next, dirty: 1 })
      changed += 1
    }
  })
  return changed
},
```

它包含在册与断简 Entry：断简图片仍保持关联，恢复不丢；只有任何正文都不引用的媒体才退回 `entryId=""`。

```
function detectImageMime(b64: string, fallback: string): string {
  const raw = atob(b64.slice(0, 32))
  const bytes = Array.from(raw, (char) => char.charCodeAt(0))

  if (bytes[0] === 0xff && bytes[1] === 0xd8 && bytes[2] === 0xff) return "image/jpeg"
  if (bytes.slice(0, 4).join(",") === "137,80,78,71") return "image/png"

  const head = raw.slice(0, 6)
  if (head === "GIF87a" || head === "GIF89a") return "image/gif"
  if (raw.slice(0, 4) === "RIFF" && raw.slice(8, 12) === "WEBP") return "image/webp"

  return fallback || "application/octet-stream"
}
```

### **六、E1 验收**

每测一种图，都先保存日记，再通过 `$repo.mediaRepo.listByEntry(id)` 看真实落库值：

1. 4000×3000 JPEG：`Math.max(width, height) <= 1920`；`blob.size < 原文件.size`；`mime` 与 `blob.type` 一致。
2. 1000px 小图：允许原样保留，不得放大。
3. GIF：`blob.type === "image/gif"`，动画仍会动；`thumbBlob` 允许为 null 并由读取侧回退。
4. 已经高度压缩的 WebP：若新 Blob 更大，应保留原图。
5. 手机竖图：`height > width`，编辑器预览方向正确。
6. 10MB 边界：原文件仍按 E 前已有的 10MB 入口限制判断；不要把“先压后允许超限”偷偷改进口径。
7. v2 导出里 `thumbMime` 等于真实 `thumbBlob.type`；导入后 Blob type 不变。
8. 导入一份无 `thumbMime` 的 v1 备份：WebP / PNG / JPEG 缩图均由文件头恢复正确 type。
9. 真机连续贴 9 张接近 10MB 的图，观察处理期间页面不崩溃；记录峰值内存与耗时，必要时 E1 内再改为串行测量/缩图，不能牺牲正确性。
10. 造一张超 24h、正文仍引用但 `entryId=""` 的图后刷新：启动对账先认领，purge 不得删除。
11. `asCopy` 导入后，新 Entry id、新 media id、media.entryId 与正文 local id 四者一致；立即彻底删除原条目不影响副本图片。

### **一、数据结构定案：不加 gallery 节点，不升 schemaVersion**

九宫格只是一种**编辑呈现**，正文仍是一串现有 `image` 节点：

```

        ↓ 唯一真相

        ↓ 保存时派生
```

- 不新增 `gallery` / `imageGrid` 节点，不升 `CONTENT_SCHEMA_VERSION`。

- `src` 与 alt 原样保留，永远不把 blob URL 写入 attrs。

```
import type { Node as ProseMirrorNode } from "@tiptap/pm/model"

function imageAt(
  doc: ProseMirrorNode,
  mediaId: string,
): { pos: number; node: ProseMirrorNode } | null {
  let found: { pos: number; node: ProseMirrorNode } | null = null

  doc.descendants((node, pos) => {
    if (found || node.type.name !== "image") return
    const id = typeof node.attrs.src === "string" ? parseLocalSrc(node.attrs.src) : null
    if (id === mediaId) found = { pos, node }
  })

  return found
}

export function moveImageNode(
  editor: Editor,
  sourceId: string,
  targetId: string,
  side: "before" | "after",
): boolean {
  if (sourceId === targetId) return false

  const source = imageAt(editor.state.doc, sourceId)
  const target = imageAt(editor.state.doc, targetId)
  if (!source || !target) return false

  const rawTarget = side === "before" ? target.pos : target.pos + target.node.nodeSize
  const tr = editor.state.tr.delete(source.pos, source.pos + source.node.nodeSize)
  const mappedTarget = tr.mapping.map(rawTarget, side === "before" ? -1 : 1)

  tr.insert(mappedTarget, source.node)
  editor.view.dispatch(tr.scrollIntoView())
  return true
}
```

⚠️

这里显式从 `@tiptap/pm/model` 只 import type，避免让 shared 层或持久化类型依赖 Tiptap。**不要**为省类型错误改成 `getJSON()` 后数组 splice 再 `setContent()`；`setContent()` 会重建整篇文档，破坏撤销栈与当前选区。

```
let holdTimer: number | null = null
let activePointer: number | null = null
let startX = 0
let startY = 0
let handle: HTMLElement | null = null

function cleanupDrag(): void {
  if (holdTimer !== null) window.clearTimeout(holdTimer)
  holdTimer = null
  window.removeEventListener("pointermove", onPointerMove)
  window.removeEventListener("pointerup", finishDrag)
  window.removeEventListener("pointercancel", cancelDrag)
  if (handle && activePointer !== null && handle.hasPointerCapture(activePointer)) {
    handle.releasePointerCapture(activePointer)
  }
  activePointer = null
  handle = null
  dragging.value = false
}

function activateDrag(): void {
  if (!handle || activePointer === null) return
  try {
    handle.setPointerCapture(activePointer)
    dragging.value = true
  } catch {
    cleanupDrag()
  }
}

function startDrag(event: PointerEvent): void {
  cleanupDrag()
  activePointer = event.pointerId
  startX = event.clientX
  startY = event.clientY
  handle = event.currentTarget as HTMLElement

  window.addEventListener("pointermove", onPointerMove, { passive: false })
  window.addEventListener("pointerup", finishDrag)
  window.addEventListener("pointercancel", cancelDrag)

  if (event.pointerType === "mouse") activateDrag()
  else holdTimer = window.setTimeout(activateDrag, 350)
}

function onPointerMove(event: PointerEvent): void {
  if (event.pointerId !== activePointer) return
  const moved = Math.hypot(event.clientX - startX, event.clientY - startY)
  if (!dragging.value && moved > 8) {
    cleanupDrag()
    return
  }
  if (dragging.value) event.preventDefault()
}

function finishDrag(event: PointerEvent): void {
  if (event.pointerId !== activePointer) return
  if (dragging.value && mediaId.value) {
    const target = document
      .elementFromPoint(event.clientX, event.clientY)
      ?.closest<HTMLElement>(".local-image[data-media-id]")
    const targetId = target?.dataset.mediaId
    if (target && targetId) {
      const rect = target.getBoundingClientRect()
      const side = event.clientX < rect.left + rect.width / 2 ? "before" : "after"
      moveImageNode(props.editor, mediaId.value, targetId, side)
    }
  }
  cleanupDrag()
}

function cancelDrag(): void {
  cleanupDrag()
}
```

### **三、新增 `src/db/tagRepo.ts`**

```
import { db } from "./schema"
import { newId } from "@/shared/ids"
import { normalizeTagName } from "@/shared/tags"
import { utcNow } from "@/shared/time"
import type { Tag } from "@/shared/types"

export interface ITagRepo {
  list(): Promise<Tag[]>
  getMany(ids: readonly string[]): Promise<Tag[]>
  getOrCreate(name: string): Promise<Tag>
}

export const localTagRepo: ITagRepo = {
  async list() {
    const rows = await db.tags.toArray()
    return rows.sort((a, b) => a.name.localeCompare(b.name, "zh-CN"))
  },

  async getMany(ids) {
    const rows = await db.tags.bulkGet([...ids])
    return rows.filter((row): row is Tag => Boolean(row))
  },

  async getOrCreate(name) {
    const normalized = name.trim()
    if (!normalized) throw new Error("标签不能为空")
    if ([...normalized].length > 32) throw new Error("标签不能超过 32 个字符")

    return db.transaction("rw", db.tags, async () => {
      const wanted = normalizeTagName(normalized)
      const rows = await db.tags.toArray()
      const existed = rows.find((tag) => normalizeTagName(tag.name) === wanted)
      if (existed) return existed

      const tag: Tag = {
        id: newId(),
        name: normalized,
        color: null,
        createdAt: utcNow(),
        dirty: 1,
      }
      await db.tags.add(tag)
      return tag
    })
  },
}
```

```
let editRevision = 0
let savedRevision = 0
let persistQueue: Promise<void> = Promise.resolve()

function schedule(): void {
  editRevision += 1
  pending = true
  status.value = "未保存"

  if (timer !== null) window.clearTimeout(timer)
  timer = window.setTimeout(() => {
    timer = null
    void persist().catch(() => {
      status.value = "保存失败"
    })
  }, 800)
}

function persist(): Promise<void> {
  // 每次都链到上一轮 settle 后；catch 只用于让队列可继续，
  // 当前调用仍返回 run，让 flush / 路由守卫能感知失败。
  const run = persistQueue.then(() => persistLatest())
  persistQueue = run.catch(() => undefined)
  return run
}
```

把原 `async function persist()` 改名 `persistLatest()`。开头不能再只看 `pending`，而是：

```
async function persistLatest(): Promise<void> {
  if (savedRevision >= editRevision) return

  // 在真正轮到本任务执行时取最新 revision 与最新表单快照。
  // 队列中的旧请求会自然合并到最新内容，不重复写过期快照。
  const revision = editRevision
  const doc = editorRef.value?.snapshot() ?? loadedDoc.value ?? {
    type: "doc" as const,
    content: [{ type: "paragraph" }],
  }

  // 后续沿用现有 targetId/title/date/content/空日记/payload/create-update/attach，
  // 并加入 E3 的 mood/weather/tagIds 快照。
```

空日记不落库分支不要直接写 `pending=false`，改为：

```
savedRevision = Math.max(savedRevision, revision)
pending = savedRevision < editRevision
status.value = pending ? "未保存" : ""
return
```

`await mediaRepo.attach(...)` 后删掉原来的无条件 `pending=false`，改为：

```
savedRevision = Math.max(savedRevision, revision)
pending = savedRevision < editRevision

// 保存期间若又有输入，editRevision 已更大，状态必须保持“未保存”，
// 后续 timer / flush 会在同一队列继续 update，绝不能被旧保存清掉。
if (entryId.value === savedId) {
  status.value = pending ? "未保存" : "已保存"
}
```

`flush()` 必须排空到调用期间出现的最新 revision：

```
async function flush(): Promise<void> {
  if (timer !== null) {
    window.clearTimeout(timer)
    timer = null
  }

  do {
    await persist()
  } while (savedRevision < editRevision)
}
```

`reset()` 只会在 `await flush()` 后执行；其中再把 `editRevision / savedRevision` 置 0，并把 `persistQueue = Promise.resolve()`。这样新条目首轮一定 create，保存中继续输入的下一轮一定看到已有 `entryId` 并 update，不会重复建两篇。

验收必须人工制造慢保存：在 `entryRepo.create/update` 前临时 delay 1 秒，输入 A 触发保存后立即继续输入 B；最终正文必须含 AB、只建一篇、状态最后“已保存”。保存过程中立刻返回 / 切条目，`flush()` 必须等最新 revision 落库。

🧹

当前 `schedule()` 的 timer 内还留着 D1 验收用的 `console.log("persist")`。E3 修改本文件时一并删掉，避免最终提交把调试日志带进去；D1 的功能代码与监听不删。

</aside>

```
  if (!/^\d{4}-\d{2}-\d{2}$/.test(value)) return false
  const [y, m, d] = value.split("-").map(Number)
  const date = new Date(y, m - 1, d, 12)

    date.getFullYear() === y &&
    date.getMonth() === m - 1 &&
    date.getDate() === d
  )
}

export function addLocalDays(value: LocalDate, amount: number): LocalDate {

}
```

### **四、后端全局异常处理器：不是新增，而是补 422 序列化缺口**

`backend/app/main.py` 已经有三类 handler：Starlette HTTP、RequestValidationError、Exception。不要重复注册第二套。已发现的真实缺口是：Pydantic 自定义 validator 抛 `ValueError` 时，`exc.errors()` 的 `ctx` 可能含 ValueError 对象，直接交 `JSONResponse` 会再次序列化失败，本来 422 变成 500。

顶部补：

```
from fastapi.encoders import jsonable_encoder
```

422 handler 改为：

```
@app.exception_handler(RequestValidationError)
async def validation_exc_handler(_: Request, exc: RequestValidationError):
    return JSONResponse(
        status_code=422,
        content=jsonable_encoder(
            {"code": 422, "message": "参数校验失败", "data": exc.errors()}
        ),
    )
```

404/HTTP 与 500 handler 保持现有统一体。I 的要求是全局**异常**处理，不顺手把 health 成功响应强改成 `{code,message,data}`，避免扩大 P0 已验收接口的回归面。

### J1（必改，静默丢数据）：`purgeOrphans` 的 24 小时窗口在 E1/E2 之后失效

P1-1 第 7 节的实现逐字是：

```tsx
async purgeOrphans(olderThanHours = 24): Promise<number> {
  const cutoff = new Date(Date.now() - olderThanHours * 3600_000).toISOString()
  const orphans = await db.media.where("entryId").equals("").toArray()
  const stale = orphans.filter((m) => m.createdAt < cutoff).map((m) => m.id)
  ...
}
```

窗口判据是 **`createdAt`**，即「这张图存进来多久了」。在 E 之前这是对的：孤儿只可能是「刚贴、没保存」的新图，贴完 24 小时内不会被清。

<aside>
🚩

**E1 的 `reconcileAll()` 与 E2 的 `attach()` 第一次引入了「追溯性变孤儿」**：一张**一周前**贴的图，今天从正文里删掉，`entryId` 被退回 `""`，而它的 `createdAt` 早已超过 cutoff——**下一次启动就被 `bulkDelete` 永久删除，撤销窗口为零**。

这与 E2 第四小节自己写的注释「不立即物理删除：用户仍可能撤销。退回孤儿后由启动时的 `purgeOrphans()` 按既有 24 小时窗口清理」**直接矛盾**——那句注释预设的窗口从退回孤儿起算，实际代码从贴图起算。不报错、不告警，符合第五节铁律列举的「静默的数据损坏」形态。

</aside>

**修法：给孤儿状态本身加一个时间戳，不动 `createdAt`**。

**1. `src/shared/types.ts` 的 `MediaItem` 追加一个可选非索引字段**（P1-1 第 5 节 schema 是 `media: "id, entryId, createdAt, dirty"`，该字段不在索引里，**沿用批次 B 的判据：不升 Dexie version**）：

```tsx
  /**
   * 变成孤儿的时刻（UTC）。null / undefined 表示当前不是孤儿，
   * 或是 E1 之前的历史数据（那时孤儿只可能是新贴的图）。
   * 非索引字段，不需要升 Dexie version。
   */
  orphanedAt?: Iso | null
```

**2. E2 第四小节的 `attach()` 两处 `update` 都要带上它**（退回时写入、认领时清空）：

```tsx
    for (const item of attached) {
      if (!keep.has(item.id)) {
        await db.media.update(item.id, {
          entryId: "",
          sortOrder: 0,
          orphanedAt: utcNow(),
          dirty: 1,
        })
      }
    }

    for (let i = 0; i < mediaIds.length; i++) {
      await db.media.update(mediaIds[i], {
        entryId,
        sortOrder: i,
        orphanedAt: null,
        dirty: 1,
      })
    }
```

**3. E1 第三小节的 `reconcileAll()` 同理**。把 `expected` 的默认值与比较、写入三处改成：

```tsx
      const next = expected.get(id)
      const wantEntryId = next?.entryId ?? ""
      const wantSortOrder = next?.sortOrder ?? 0
      // 已经是孤儿的保持原有 orphanedAt，不要每次启动都刷新时间戳，
      // 否则窗口永远走不完，孤儿永不被清。
      const wantOrphanedAt = next
        ? null
        : (item.orphanedAt ?? item.createdAt)

      if (
        item.entryId === wantEntryId &&
        item.sortOrder === wantSortOrder &&
        (item.orphanedAt ?? null) === (wantOrphanedAt ?? null)
      ) {
        continue
      }

      await db.media.update(id, {
        entryId: wantEntryId,
        sortOrder: wantSortOrder,
        orphanedAt: wantOrphanedAt,
        dirty: 1,
      })
      changed += 1
```

<aside>
⚠️

第三处那个 `?? item.createdAt` 是**历史数据的入口**：E1 上线前就已经是孤儿的图，没有 `orphanedAt`，用 `createdAt` 回填后**行为与今天完全一致**（超 24 小时就清）。不这么写会让所有历史孤儿在首次对账时被重新计时，白留 24 小时。

</aside>

**4. `purgeOrphans()` 判据改一行**：

```tsx
    const stale = orphans
      .filter((m) => (m.orphanedAt ?? m.createdAt) < cutoff)
      .map((m) => m.id)
```

**5. 备份不需要再动一次**。`BackupMedia extends Omit&lt;MediaItem, "blob" | "thumbBlob"&gt;`（P1-5 第 1 节原文），新字段自动进出；v1 旧备份没有它，导入后是 `undefined`，走上面的 `?? createdAt` 回退。**E1 已把 `BACKUP_FORMAT_VERSION` 升到 2，这里不再 +1。**

**6. E1 第四小节 `main.ts` 的 reconcile → purge 顺序不变**，但加上本条后它才真正安全：对账把「正文已不引用」的图打上时间戳，purge 至少 24 小时后才动手。

**验收补两条**：① 贴图存盘 → 隔一天（或把 `createdAt` 手改成两天前）→ 从正文删掉该图并保存 → 刷新 → 该 media 仍在库里、`orphanedAt` 是刚才、撤销重存后能重新认领；② 把 `orphanedAt` 手改成两天前 → 刷新 → 被清理。

### J2（必改）：E3 改造后 `flush()` 会 reject，D1 的三个调用点仍是裸调

D1 第一小节的 `onBeforeUnload` / `onVisibilityChange` / `onBeforeUnmount` 都是 `flush()` 裸调；那时 `flush()` 不会抛。E3 第七小节把它改成 `do { await persist() } while (...)`，而 `persist()` 明确「当前调用仍返回 run，让 flush / 路由守卫能感知失败」——**保存失败时这三处会产生未捕获的 Promise rejection**，控制台一片红，且用户看不到任何状态。

三处统一改成：

```tsx
function flushSafely(): void {
  void flush().catch(() => {
    status.value = "保存失败"
  })
}
```

`onBeforeUnload`、`onVisibilityChange`（仍只在 `hidden` 时）、`onBeforeUnmount` 都调 `flushSafely()`。**路由守卫 `onBeforeRouteLeave` / `onBeforeRouteUpdate` 保持 `await flush()`**，它们需要感知失败来决定拦不拦——这正是 P1-4 第 1、2 节串文 bug 修法依赖的行为，不要顺手改成 `flushSafely()`。

另外 `do / while` 循环不会死循环：`persistLatest()` 抛出时整个 `flush()` 直接 reject 退出，成功时 `savedRevision` 单调递增。实施时把这句写进注释，免得下次有人再加一层保护。

```tsx
import { resizeToBlob } from "@/capabilities/image"
import { newId } from "@/shared/ids"
import { collectMediaIds } from "@/shared/text"
import { utcNow } from "@/shared/time"
import type { MediaItem } from "@/shared/types"

import { db } from "./schema"

/** 原图入库上限。算术见 E1 第一小节 */
const IMAGE_MAX_EDGE = 1920
const IMAGE_QUALITY = 0.8
/** 缩略图长边。算术见批次 B 第四小节 */
const THUMB_MAX_EDGE = 480
const THUMB_QUALITY = 0.8

async function measure(blob: Blob): Promise<{ width: number | null; height: number | null }> {
  if (typeof createImageBitmap !== "function") return { width: null, height: null }
  try {
    const bmp = await createImageBitmap(blob, { imageOrientation: "from-image" })
    const size = { width: bmp.width, height: bmp.height }
    bmp.close()
    return size
  } catch {
    return { width: null, height: null }
  }
}

async function compressForStorage(blob: Blob): Promise<Blob> {
  // 动图不能经过 canvas，否则只剩第一帧。
  if (blob.type === "image/gif") return blob

  const compressed = await resizeToBlob(blob, {
    maxEdge: IMAGE_MAX_EDGE,
    quality: IMAGE_QUALITY,
    mime: "image/webp",
  })

  // 小图、解码失败、浏览器不支持，或转完反而更大：全部保留原图。
  return compressed && compressed.size < blob.size ? compressed : blob
}

export const localMediaRepo = {
  /** 用户粘贴或拖入图片时调用。此时还不知道会挂到哪篇日记上，entryId 留空。 */
  async add(blob: Blob): Promise<MediaItem> {
    const storedBlob = await compressForStorage(blob)
    const [{ width, height }, thumbBlob] = await Promise.all([
      measure(storedBlob),
      resizeToBlob(storedBlob, {
        maxEdge: THUMB_MAX_EDGE,
        quality: THUMB_QUALITY,
        mime: "image/webp",
      }),
    ])

    const item: MediaItem = {
      id: newId(),
      entryId: "",
      blob: storedBlob,
      thumbBlob,
      mime: storedBlob.type || blob.type || "image/png",
      width,
      height,
      size: storedBlob.size,
      sortOrder: 0,
      remoteUrl: "",
      createdAt: utcNow(),
      // 刚贴进来就是孤儿：窗口从此刻起算，与 createdAt 同值。
      // 写成显式字段而不依赖 undefined 回退，是为了新数据不再进 ?? 分支。
      orphanedAt: utcNow(),
      dirty: 1,
    }
    await db.media.add(item)
    return item
  },

  /**
   * 全库对账：以全部 Entry 正文 JSON 为唯一真相，校正 entryId / sortOrder，
   * 并维护 orphanedAt。包含在册与断简：断简图片仍保持关联，恢复不丢。
   *
   * 启动时先 reconcileAll() 再 purgeOrphans()（见 main.ts）：对账只负责
   * “打上变孤儿的时刻”，真正删除至少要等 24 小时后的下一次启动。
   */
  async reconcileAll(): Promise<number> {
    const entries = await db.entries.toArray()
    const mediaIds = (await db.media.orderBy("id").primaryKeys()) as string[]
    const expected = new Map<string, { entryId: string; sortOrder: number }>()

    for (const entry of entries) {
      const ids = collectMediaIds(entry.content?.doc)
      ids.forEach((id, sortOrder) => {
        // 同一张图被两篇引用时只归第一篇。已知、可接受：P1 不做多对多，
        // 且两篇正文都仍能按 id 正常显示图片。
        if (!expected.has(id)) expected.set(id, { entryId: entry.id, sortOrder })
      })
    }

    let changed = 0
    await db.transaction("rw", db.media, async () => {
      for (const id of mediaIds) {
        const item = await db.media.get(id)
        if (!item) continue

        const next = expected.get(id)
        const wantEntryId = next?.entryId ?? ""
        const wantSortOrder = next?.sortOrder ?? 0
        // 已经是孤儿的保持原有 orphanedAt，不要每次启动都刷新时间戳，
        // 否则窗口永远走不完，孤儿永不被清。?? item.createdAt 是历史数据
        // （E1 上线前已是孤儿、无 orphanedAt）的入口，行为与今天一致。
        const wantOrphanedAt = next ? null : (item.orphanedAt ?? item.createdAt)

        if (
          item.entryId === wantEntryId &&
          item.sortOrder === wantSortOrder &&
          (item.orphanedAt ?? null) === (wantOrphanedAt ?? null)
        ) {
          continue
        }

        await db.media.update(id, {
          entryId: wantEntryId,
          sortOrder: wantSortOrder,
          orphanedAt: wantOrphanedAt,
          dirty: 1,
        })
        changed += 1
      }
    })
    return changed
  },

  async get(id: string): Promise<MediaItem | undefined> {
    return db.media.get(id)
  },

  async listByEntry(entryId: string): Promise<MediaItem[]> {
    const rows = await db.media.where("entryId").equals(entryId).toArray()
    return rows.sort((a, b) => a.sortOrder - b.sortOrder)
  },

  async firstByEntries(entryIds: readonly string[]): Promise<Record<string, string>> {
    if (!entryIds.length) return {}

    const entries = await db.entries.bulkGet([...entryIds])
    const refs = new Map<string, string[]>()

    for (const entry of entries) {
      if (!entry) continue
      refs.set(entry.id, collectMediaIds(entry.content?.doc))
    }

    // 只取主键判断存在；bulkGet MediaItem 会把原图 Blob 一起载入内存。
    const existing = new Set((await db.media.orderBy("id").primaryKeys()) as string[])
    const result: Record<string, string> = {}

    for (const [entryId, ids] of refs) {
      const first = ids.find((id) => existing.has(id))
      if (first) result[entryId] = first
    }
    return result
  },

  /** 保存日记时调用，把这次正文里实际用到的图片关联过去。 */
  async attach(entryId: string, mediaIds: string[]): Promise<void> {
    await db.transaction("rw", db.media, async () => {
      const keep = new Set(mediaIds)
      const attached = await db.media.where("entryId").equals(entryId).toArray()

      // 不立即物理删除：用户仍可能撤销。退回孤儿时才写 orphanedAt，
      // 窗口从此刻起算（而不是从当初贴图起算）。
      for (const item of attached) {
        if (!keep.has(item.id)) {
          await db.media.update(item.id, {
            entryId: "",
            sortOrder: 0,
            orphanedAt: utcNow(),
            dirty: 1,
          })
        }
      }

      for (let i = 0; i < mediaIds.length; i++) {
        await db.media.update(mediaIds[i], {
          entryId,
          sortOrder: i,
          orphanedAt: null,
          dirty: 1,
        })
      }
    })
  },

  /**
   * 清理孤儿图片：用户贴了图但最后没保存，或者贴完又删掉了。
   * 建议在应用启动时跑一次，只清超过 24 小时的，避免误删正在编辑的内容。
   *
   * 判据是 orphanedAt（变成孤儿的时刻），不是 createdAt。两者在 E 之前等价；
   * E1 对账与 E2 attach 引入“追溯性变孤儿”后，继续用 createdAt 会把一周前
   * 贴、今天刚从正文删掉的图在下次启动就直接删光，撤销窗口为零。
   */
  async purgeOrphans(olderThanHours = 24): Promise<number> {
    const cutoff = new Date(Date.now() - olderThanHours * 3600_000).toISOString()
    const orphans = await db.media.where("entryId").equals("").toArray()
    const stale = orphans
      .filter((m) => (m.orphanedAt ?? m.createdAt) < cutoff)
      .map((m) => m.id)
    if (stale.length) await db.media.bulkDelete(stale)
    return stale.length
  },

  /**
   * 取缩略图。永远能拿到一张能显示的图（实在没有才返回 undefined）。
   *
   * 旧图（P1-1~P1-5 期间贴的）与旧备份导入的 thumbBlob 都是 null，
   * 在这里惰性补上。不在启动时批量回填：那等于启动时把全库图片
   * 解码一遍，还要跟 purgeOrphans 抢同一个启动窗口。
   */
  async getThumb(id: string): Promise<Blob | undefined> {
    const m = await db.media.get(id)
    if (!m) return undefined
    if (m.thumbBlob) return m.thumbBlob

    const t = await resizeToBlob(m.blob, {
      maxEdge: THUMB_MAX_EDGE,
      quality: THUMB_QUALITY,
    })
    // 生成不出来就不写库，下次还会再试一次。对「本来就比 480 小」的图
    // 确实是白跑一次 decode，但换来的是不必在库里再存一份几乎等大的副本
    if (t) await db.media.update(id, { thumbBlob: t, dirty: 1 })
    return t ?? m.blob
  },
}
```

<aside>
⚠️

**三个容易踩的点。**

1. **不能再用 `await db.media.update(id, { ...next, dirty: 1 })`**。展开 `next` 时 `next` 可能是 `undefined`，而且展开写法永远不会带上 `orphanedAt`——那等于 J1 只改了一半，`purgeOrphans` 依旧会误删。
2. **比较时必须把 `undefined` 与 `null` 归一**（`(item.orphanedAt ?? null) === (wantOrphanedAt ?? null)`）。直接 `===` 会让所有历史行（`undefined`）在每次启动都被当成“有变化”写一遗库，`changed` 永远不为 0。
3. **不要升 Dexie version、不要再升 `BACKUP_FORMAT_VERSION`**。`orphanedAt` 不在 `media: "id, entryId, createdAt, dirty"` 索引里；备份靠 `BackupMedia extends Omit&lt;MediaItem, "blob" | "thumbBlob"&gt;` 自动带上，v2 已由 E1 升过。
</aside>

### J7、`src/views/EntryEditView.vue` 合并后的完整文件（D1 + E3 + F 第三小节 + J2，2026-09-01）

<aside>
🧾

可直接整文件覆盖 `frontend/src/views/EntryEditView.vue`。与用户手里那份相比，**只动了四处**，均属 J2；保存队列、revision、空日记判断、日期 query、`reset()`、模板与样式**逼字未动**。

**问题实质**：不是“忘了 await”，而是 `void flush()` **并不能处理 rejection**——`void` 只丢弃返回值，不注册 handler。E3 把 `flush()` 改成会 reject 之后，保存失败（IndexedDB 写失败、配额溢出、断简里的条目被彻底删后的 update）就会在控制台拿到 `Unhandled promise rejection`，而右上角状态永远停在“保存中”。

</aside>

**四处改动**：

1. 新增 `flushSafely()`（唯一允许“发完就不管”的入口，内部带 `catch`）。
2. `onBeforeUnload`、`onVisibilityChange`、`onBeforeUnmount` 三处改调 `flushSafely()`。
3. `schedule()` 的 timer 回调也改调 `flushSafely()`：原来写 `void persist().catch(...)`，缺了 `flush()` 里那句 `clearTimeout` 与 do/while 排空，错过 800ms 窗口里累积的多个 revision。
4. `flush()` 的 do/while 补上不会死循环的注释。

**三个路由入口（`back` / `discard` / `onBeforeRouteLeave` / `onBeforeRouteUpdate` / `watch(routeId)`）仍保持 `await flush()`**，不得改成 `flushSafely()`——它们靠这个 await 保证“上一篇落库完才销毁编辑器”，正是 P1-4 串文 bug 修法依赖的行为。

```jsx
      v-model:tag-ids="tagIds"
      @change="schedule"

         内部的 useEditor 在它自己 setup 阶段就用当时的 props.doc 建好了实例，

         结果就是标题正常、正文空白。 -->
    <DiaryEditor v-if="ready" ref="editorRef" :doc="loadedDoc" @change="onChange" />
  </div>

import { computed, onBeforeUnmount, onMounted, ref, watch } from "vue"
import { onBeforeRouteLeave, onBeforeRouteUpdate, useRoute, useRouter } from "vue-router"

import DiaryEditor from "@/components/DiaryEditor.vue"
import EntryMetaFields from "@/components/EntryMetaFields.vue"
import { entryRepo, mediaRepo } from "@/repo"
import { collectMediaIds, toPlainText } from "@/shared/text"
import { isLocalDate, todayLocal } from "@/shared/time"
import { CONTENT_SCHEMA_VERSION, type TiptapDoc } from "@/shared/types"

const route = useRoute()
const router = useRouter()

/** null 表示这篇还没落库。点开编辑器不创建任何数据，第一次保存时才创建 */
const entryId = ref<string | null>(null)
const title = ref("")
const mood = ref<string | null>(null)
const weather = ref<string | null>(null)
const tagIds = ref<string[]>([])
const loadedDoc = ref<TiptapDoc | null>(null)
/** 旧文读完之前不能挂载编辑器，否则它会以空文档定型 */
const ready = ref(false)
const status = ref("")
const editorRef = ref<InstanceType<typeof DiaryEditor> | null>(null)

let timer: number | null = null
let pending = false
let entryDate = todayLocal()
let editRevision = 0
let savedRevision = 0
let persistQueue: Promise<void> = Promise.resolve()
let loadRevision = 0

const routeId = computed(() => (typeof route.params.id === "string" ? route.params.id : "new"))

/** 把视图恢复成「什么都没加载」的状态。切换条目时必须整体重置，漏一个字段就是串文 */
function reset(): void {
  entryId.value = null
  title.value = ""
  mood.value = null
  weather.value = null
  tagIds.value = []
  loadedDoc.value = null
  entryDate = todayLocal()
  pending = false
  status.value = ""
  editRevision = 0
  savedRevision = 0
  persistQueue = Promise.resolve()
  if (timer !== null) {
    window.clearTimeout(timer)
    timer = null
  }
}

async function load(id: string): Promise<void> {
  const revision = ++loadRevision
  reset()

  if (id !== "new") {
    const entry = await entryRepo.get(id)
    if (revision !== loadRevision) return
    if (!entry) {
      void router.replace("/")
      return
    }
    entryId.value = entry.id
    title.value = entry.title
    mood.value = entry.mood
    weather.value = entry.weather
    tagIds.value = [...entry.tagIds]
    loadedDoc.value = entry.content?.doc ?? null
    entryDate = entry.entryDate
  } else {
    const requested = route.query.date
    if (typeof requested === "string" && isLocalDate(requested) && requested <= todayLocal()) {
      entryDate = requested
    } else {
      entryDate = todayLocal()
    }
  }

  if (revision !== loadRevision) return
  // 新建和编辑两条路径都在这里置位，保证行为一致
  ready.value = true
}

onMounted(() => {
  void load(routeId.value)
})

/**
 * vue-router 在同一条规则内换参数时会复用实例、不重跑 onMounted，
 * 所以必须先排空上一篇的保存，再销毁旧编辑器并读取下一篇。
 */
watch(routeId, async (next, prev) => {
  if (next === prev) return
  // 新建落库后自己 replace 出来的地址变化（/entry/new → /entry/{id}）不算切换
  if (next === entryId.value) return
  await flush()
  ready.value = false
  await load(next)
})

/** 内容或元数据变化后排一次保存。 */
function schedule(): void {
  editRevision += 1
  pending = true
  status.value = "未保存"

  if (timer !== null) window.clearTimeout(timer)
  timer = window.setTimeout(() => {
    timer = null
    // 走 flushSafely 而不是裸 persist()：800ms 窗口里可能已累积多个 revision，
    // 只跑一轮 persist 可能排不空（persistLatest 只合并到开始那一刻的 revision）。
    flushSafely()
  }, 800)
}

function onChange(): void {
  schedule()
}

/**
 * 所有保存串到同一条 Promise 队列。run 保留本次错误给 flush / 路由守卫，
 * persistQueue 自身吞掉错误，以便下一轮保存仍能继续。
 */
function persist(): Promise<void> {
  const run = persistQueue.then(() => persistLatest())
  persistQueue = run.catch(() => undefined)
  return run
}

async function persistLatest(): Promise<void> {
  if (savedRevision >= editRevision) return

  // 真正轮到本任务时再取最新 revision 和表单快照，队列中的旧请求自然合并。
  const revision = editRevision
  const doc = editorRef.value?.snapshot() ??
    loadedDoc.value ?? {
      type: "doc" as const,
      content: [{ type: "paragraph" }],
    }

  const targetId = entryId.value
  const targetTitle = title.value
  const targetDate = entryDate
  const targetMood = mood.value
  const targetWeather = weather.value
  const targetTagIds = [...new Set(tagIds.value)]

  const content = { schemaVersion: CONTENT_SCHEMA_VERSION, doc }
  const text = toPlainText(content)
  const hasMeta = Boolean(targetMood || targetWeather || targetTagIds.length)

  // 空的新日记不落库；只有心情、天气或标签也属于有效日记。
  if (targetId === null && !targetTitle.trim() && !text.trim() && !hasMeta) {
    savedRevision = Math.max(savedRevision, revision)
    pending = savedRevision < editRevision
    status.value = pending ? "未保存" : ""
    return
  }

  status.value = "保存中"

  const payload = {
    title: targetTitle,
    content,
    entryDate: targetDate,
    mood: targetMood,
    weather: targetWeather,
    tagIds: targetTagIds,
  }

  let savedId: string
  if (targetId === null) {
    const created = await entryRepo.create(payload)
    savedId = created.id
    entryId.value = created.id
    // 只在地址栏还停在 /entry/new 时改写，避免跟用户的跳转抢路由
    if (routeId.value === "new") void router.replace(`/entry/${created.id}`)
  } else {
    savedId = targetId
    await entryRepo.update(targetId, payload)
  }

  // 图片认领必须在正文落库之后；正文 JSON 顺序是媒体 sortOrder 的真相来源。
  await mediaRepo.attach(savedId, collectMediaIds(doc))

  savedRevision = Math.max(savedRevision, revision)
  pending = savedRevision < editRevision

  // 保存期间若又有输入，旧保存不能清除“未保存”状态。
  if (entryId.value === savedId) {
    status.value = pending ? "未保存" : "已保存"
  }
}

/**
 * 排空到 flush 调用期间出现的最新 revision。会向上抛：路由守卫靠它判断拦不拦。
 *
 * do/while 不会死循环：persistLatest() 成功时 savedRevision 单调递增到
 * 当时的 editRevision；抛出时整个 flush() 直接 reject 退出循环。
 * 唯一能让它多转一圈的情形是“保存期间又有输入”，而那正是它存在的理由。
 */
async function flush(): Promise<void> {
  if (timer !== null) {
    window.clearTimeout(timer)
    timer = null
  }

  do {
    await persist()
  } while (savedRevision < editRevision)
}

/**
 * “发完就不管”的唯一入口。给三个无法 await 的时机用：beforeunload、
 * visibilitychange、onBeforeUnmount。
 *
 * 不能写成 void flush()：void 只丢弃返回值，不注册任何 rejection handler。
 * E3 把 flush() 改成会 reject 之后，写库失败（配额溢出、条目已被彻底删除后的
 * update）会变成未捕获 rejection：控制台一片红，而用户只看到状态卡在“保存中”。
 */
function flushSafely(): void {
  void flush().catch(() => {
    status.value = "保存失败"
  })
}

async function discard(): Promise<void> {
  if (!entryId.value) return
  if (!window.confirm("移入断简？可以再恢复。")) return
  await flush()
  const id = entryId.value
  await entryRepo.remove(id)
  void router.replace("/")
}

async function back(): Promise<void> {
  await flush()
  void router.back()
}

/** 换到另一篇（同路由换参数）时触发。onBeforeRouteLeave 在这种情况下不触发 */
onBeforeRouteUpdate(async () => {
  await flush()
})

/** 路由切走前落盘。不做这一步，快速点返回会丢掉最后 800ms 的输入 */
onBeforeRouteLeave(async () => {
  await flush()
})

// 关标签页 / 刷新前落盘。浏览器不会等待异步完成，但仍尽早触发队列。
function onBeforeUnload(): void {
  flushSafely()
}

// 切后台 / 切标签页时落盘。只在 hidden 时做：visibilitychange 双向触发，
// 回前台时并没有新输入。这是移动端唯一可靠的那道保险。
function onVisibilityChange(): void {
  if (document.visibilityState === "hidden") flushSafely()
}

window.addEventListener("beforeunload", onBeforeUnload)
document.addEventListener("visibilitychange", onVisibilityChange)

onBeforeUnmount(() => {
  loadRevision += 1
  window.removeEventListener("beforeunload", onBeforeUnload)
  document.removeEventListener("visibilitychange", onVisibilityChange)
  // 此处无法 await（钩子同步），但写入仍会在后台跑完：
  // persistLatest 已在开头快照了 doc 与表单，不依赖已销毁的 editorRef。
  flushSafely()
})
</script>
```

**两个容易改错的地方。**

1. **不要把路由守卫也改成 `flushSafely()`**。`onBeforeRouteLeave` / `onBeforeRouteUpdate` / `watch(routeId)` / `back` / `discard` 必须 `await flush()`：守卫一旦不再等待，就会在上一篇还没写完时销毁编辑器并 `load()` 下一篇，**直接退回 P1-4 那个串文 bug**。
2. **不要在 `flushSafely()` 里加 `if (!pending) return` 之类的早退**。真正的判据是 `savedRevision >= editRevision`，已经在 `persistLatest()` 开头了；`pending` 只是给 UI 看的镜像，拿它做门禁会在“保存中又输入”时漏写。
</aside>

🧪

**J2 的定向验收**（在 E3 原有验收之外补）：在 `entryRepo.update` 前临时插一句 `throw new Error("boom")`，然后分别试三个时机：① 输入后等 800ms 自动保存；② 输入后立即切后台；③ 输入后立即点返回。

三种情形都应该：右上角出现**“保存失败”**，且控制台**没有** `Unhandled promise rejection`。改前的 `void flush()` 在②③ 下会报未捕获异常、状态卡在“保存中”。验完删掉那句 throw，再跑 `npm run build`。

</aside>

## **K. 九宫格拖拽与灯箱的真机问题修正（2026-09-03）**

<aside>
📌

本节**覆盖 E2 第五节的第 5、7 条与那段 NodeView 模板**。它们已按原稿实施并 build 通过，但真机（Chrome）测出三个问题：“移”没反应、长按图片没反应、点图看大图会弹软键盘。以下 K1 是归因，K2 是可直接覆盖的整文件。

</aside>

### **K1、三个问题的真正原因**

**① “移”点下去没反应 —— 两个原因叠在一起。**

第一个是**交互语义错位**：它长得像按钮，但它不是按钮，是**拖拽把手**。单击它时 `pointerdown` → `pointerup` 中间没位移，`finishDrag()` 里 `document.elementFromPoint()` 命中的就是自己，`moveImageNode()` 开头的 `if (sourceId === targetId) return false` 直接返回 —— **从代码角度它“正常工作”，但从人的角度它就是个按下去没反应的按钮**。

第二个是真 bug：**ProseMirror 会给 leaf NodeView 的 DOM 自动加 `draggable="true"`**。你一按住把手往旁边拖，浏览器启动的是**原生 HTML5 drag**，而原生 drag 一开始就会发 `pointercancel`，直接跑进 `cancelDrag()`。所以即使你真的拖了，指针流也已经被掉头。`@pointerdown.prevent` 拦不住它 —— 那只拦 PM 自己的 `mousedown`，拦不住 `dragstart`。修法是 wrapper 上显式 `draggable="false"` 加 `@dragstart.prevent`。

**② 长按图片没反应 —— 这是原设计。** 长按逻辑只绑在把手上，图片本体只有 `@click`，不是 bug。你要的“长按图片就能拖”得重写交互，见 K2。

**③ 点图弹软键盘 —— 焦点回到了 `contenteditable`**。预览按钮在 ProseMirror 内部，点它会让 PM 把选区设为该图的 NodeSelection 并把焦点拉回编辑区，移动版 Chrome 一拿到编辑区焦点就弹键盘，而灯箱是后一帧才渲染的，于是被键盘顶得只剩上半截。修法三件一起做：预览上 `@pointerdown.prevent`（不让 PM 设选区）、开灯箱**之前** `document.activeElement.blur()` 加 `editor.commands.blur()`、关灯箱时**绝不回焦**编辑器（回焦就是再弹一次）。

### **K2、交互定案：拆掉“移”，长按图片即拖**

**不保留“移”按钮。** 它存在的唯一理由是“没地方放长按手势”，而图片本体完全能同时承担短按与长按：

| 手势 | 行为 |
| --- | --- |
| 短按（< 350ms、位移 ≤ 8px） | 开大图 |
| 长按 350ms | 进入拖拽（带轻微震动），抬手时落位 |
| 未满 350ms 就滑动 | 取消，页面正常滚动 |
| 鼠标按住拖 > 8px | 立即进入拖拽（桌面不用等 350ms） |
| 鼠标单击 | 开大图 |

拖拽时在目标格子左 / 右半区显示一条竖线提示插入位（before / after），落点判据与原来一致。“删”改成**内联 SVG 垃圾桶图标**，保留 `aria-label="删除图片"`（图标没文本，不留 label 屏读就只能报“按钮”）。

<aside>
⚠️

**为什么不能直接给图片写 `touch-action: none`**。 那会让手指落在图上时**整页没法滚动**—— 九宫格占满一屏时几乎无处下手。此处用 `touch-action: pan-y`：纵向滚动照旧，而“按住不动”不构成 pan，浏览器不会接管手势，350ms 后我们用 `setPointerCapture()` + `preventDefault()` 接住后续移动。这也是为何 `pointermove` 必须 `{ passive: false }`：passive 下 `preventDefault()` 无效且报警告。

</aside>

```
function paintDropTarget(el: HTMLElement | null, side: "before" | "after"): void {

  if (!el) return

  el.classList.toggle("drop-before", side === "before")
  el.classList.toggle("drop-after", side === "after")

// 落点只靠 elementFromPoint，不缓存 ProseMirror position（每次 transaction 都会变）。
function targetAt(

  y: number,

    .elementFromPoint(x, y)

function cleanupDrag(): void {
  if (holdTimer !== null) window.clearTimeout(holdTimer)
  holdTimer = null
  window.removeEventListener("pointermove", onPointerMove)
  window.removeEventListener("pointerup", onPointerUp)
  window.removeEventListener("pointercancel", onPointerCancel)
  if (host && activePointer !== null && host.hasPointerCapture(activePointer)) {
    host.releasePointerCapture(activePointer)
  }
  host = null
  activePointer = null
  dragging.value = false
  clearDropPaint()
}

function activateDrag(): void {
  holdTimer = null
  if (!host || activePointer === null) return
  try {
    host.setPointerCapture(activePointer)
  } catch {
    cleanupDrag()
    return
  }
  dragging.value = true
  if (typeof navigator.vibrate === "function") navigator.vibrate(10)
}

function onPointerDown(event: PointerEvent): void {
  if (!mediaId.value || event.button !== 0) return
  cleanupDrag()

  activePointer = event.pointerId
  host = event.currentTarget as HTMLElement
  startX = event.clientX
  startY = event.clientY

  window.addEventListener("pointermove", onPointerMove, { passive: false })
  window.addEventListener("pointerup", onPointerUp)
  window.addEventListener("pointercancel", onPointerCancel)

  holdTimer = window.setTimeout(activateDrag, HOLD_MS)
}

function onPointerMove(event: PointerEvent): void {
  if (event.pointerId !== activePointer) return
  const moved = Math.hypot(event.clientX - startX, event.clientY - startY)

  if (!dragging.value) {
    if (moved <= MOVE_TOLERANCE) return
    // 鼠标：按住拖就是拖，不用等 350ms。
    // 触屏：长按尚未成立就滑了 = 用户想滚页，放开手势。
    if (event.pointerType === "mouse") activateDrag()
    else cleanupDrag()
    if (!dragging.value) return
  }

  event.preventDefault()
  const hit = targetAt(event.clientX, event.clientY)
  paintDropTarget(hit?.el ?? null, hit?.side ?? "before")
}

function onPointerUp(event: PointerEvent): void {
  if (event.pointerId !== activePointer) return

  const wasDragging = dragging.value
  const moved = Math.hypot(event.clientX - startX, event.clientY - startY)
  const hit = wasDragging ? targetAt(event.clientX, event.clientY) : null
  cleanupDrag()

  if (wasDragging) {
    // 长按后原地抬手（hit 为 null）就是个空操作，不开大图。
    if (hit) moveImageNode(props.editor, mediaId.value, hit.id, hit.side)
    return
  }
  if (moved <= MOVE_TOLERANCE) void open()
}

function onPointerCancel(event: PointerEvent): void {
  if (event.pointerId !== activePointer) return
  cleanupDrag()
}

/* ---------- 灯箱 ---------- */

// 开灯箱前必须把焦点从 contenteditable 上抢下来，否则移动版弹软键盘遂图。
// 两句都要：activeElement.blur() 收当前焦点，editor.commands.blur() 防 PM 回焦。
function dropFocus(): void {
  const active = document.activeElement
  if (active instanceof HTMLElement) active.blur()
  props.editor.commands.blur()
}

async function open(): Promise<void> {
  if (!mediaId.value) return
  dropFocus()

  const mine = ++fullSeq
  const item = await mediaRepo.get(mediaId.value)
  if (mine !== fullSeq || !item) return

  fullBlob.value = item.blob
  lightboxOpen.value = true
}

// 关灯箱后绝不回焦编辑器：回焦 = 再弹一次键盘。
function close(): void {
  fullSeq += 1
  lightboxOpen.value = false
  fullBlob.value = null
}

onUnmounted(() => {
  resolveSeq += 1
  fullSeq += 1
  cleanupDrag()
})
</script>
```

### **K4、`ImageLightbox.vue` 补两处（防键盘与背景滚动）**

E2 第六节的接口不变，只在它内部加两件事：

1. **打开时把焦点放到关闭按钮上**。光靠 NodeView 里的 `dropFocus()` 只能保证“不弹”；把焦点落到灯箱自己的按钮上，才能保证 Esc 直接能关、且焦点不会被背景编辑区抢回去。
2. **打开期间锁背景滚动**：`document.body.style.overflow = "hidden"`，关闭时恢复。不锁的话在灯箱上滑动会带动下面的日记正文跑，关灯箱后位置已经飘走。

合并进现有 script 后的**完整 script setup 段**（直接覆盖，2026-09-03）：

```tsx
import { computed, nextTick, onUnmounted, ref, toRef, watch } from "vue"

import { useObjectUrl } from "@/composables/useObjectUrl"

const props = defineProps<{
  open: boolean
  blob: Blob | null
  alt: string
}>()

const emit = defineEmits<{
  close: []
}>()

const closeRef = ref<HTMLButtonElement | null>(null)

const blob = toRef(props, "blob")
// 关闭期间置 null，useObjectUrl 会 revoke 原图 URL：原图可能有几 MB，
// 九张图各挂一个实例时不能让它们常驻。

/**
 * 背景滚动锁必须带实例级标记。
 *
 * 每个 LocalImageView 都各自挂了一个 ImageLightbox，九宫格就是九个实例。
 * 如果无条件写 document.body.style.overflow，任意一个实例的 watch(immediate)
 * 或 onUnmounted 都会把别人正在用的锁解掉 —— 症状是灯箱开着背景却能滚。
 * 有了 locked，只有真正上过锁的那个实例才解锁。
 */
let locked = false

function lockScroll(on: boolean): void {
  if (on === locked) return
  locked = on
  document.body.style.overflow = on ? "hidden" : ""
}

function close(): void {
  emit("close")
}

function onKeydown(event: KeyboardEvent): void {
  if (event.key !== "Escape") return
  event.preventDefault()
  close()
}

watch(
  () => props.open,
  async (open) => {
    window.removeEventListener("keydown", onKeydown)
    lockScroll(open)
    if (!open) return

    window.addEventListener("keydown", onKeydown)
    // 焦点落到灯箱自己的关闭按钮上。NodeView 的 dropFocus() 只保证“不弹键盘”，
    // 这一步才保证焦点不会被背景的 contenteditable 抢回去（抢回去就再弹一次）。
    await nextTick()
    closeRef.value?.focus()
  },
  { immediate: true },
)

// 异常路径：灯箱开着时组件被销毁（拖拽后 NodeView 重建、直接后退路由），
// 不解锁就整个 App 再也滚不动。
onUnmounted(() => {
  window.removeEventListener("keydown", onKeydown)
  lockScroll(false)
})
```

### **K7、灯箱缩放与定位重做（2026-09-03，覆盖 K4）**

<aside>
🚩

真机又测出两个问题，**K4 那版解决不了，本节整体覆盖 K4**（K4 的 `closeRef` 聚焦与 `lockScroll` 都并进来了，不要两版混用）：

1. **在大图上双指放大，底下的日记页跟着一起放大。** 根因：`body { overflow: hidden }` 只锁**滚动**，锁不住浏览器的 pinch-zoom —— 双指手势被浏览器当成「缩放整个文档」接走了，灯箱只是恰好也在文档里，于是一起被放大。要让手势落到灯箱自己身上，必须在遮罩上写 `touch-action: none`，并**自己实现缩放**。
2. **页面滚动过之后再打开大图，关闭按钮显示不全。** 根因有两层：① 灯箱是 `LocalImageView` 的子节点，而 `.local-image` 带 `position: relative` + `overflow: hidden`，编辑区里任何祖先一旦产生 `transform` / `filter` / `contain`，`position: fixed` 的包含块就不再是视口而是那个祖先，遮罩随即被裁掉；② 页面被 pinch-zoom 之后，`fixed` 元素定位在**布局视口**，而用户看到的是**视觉视口**，右上角会被推到屏幕外。
</aside>

**两个修法各自对症**：

| 症状 | 修法 |
| --- | --- |
| 页面跟着放大 | 遮罩 `touch-action: none`  • 自己接双指手势（`setPointerCapture` 逐指捕获，`pointermove` 里 `preventDefault()`），缩放只作用在 `&lt;img&gt;` 的 `transform` 上 |
| 关闭按钮显示不全 | ① `&lt;Teleport to="body"&gt;`，让遮罩彻底脱离编辑区的裁剪与层叠上下文；② 用 `window.visualViewport` 的 `offsetLeft / offsetTop / width / height` 实时钉住遮罩，而不是 `inset: 0` |

**交互定案（刻意不做双击放大）**：单指点一下 —— 未放大时关闭、已放大时回到 1×；双指捏放缩放 1×–4×；放大后单指拖动平移（有边界夹紧）；桌面滚轮以指针为中心缩放；Esc 关闭。**不做双击放大**，否则「单指点一下关闭」必须等 250ms 去判是不是双击，关闭会明显发黏。

**完整文件（直接覆盖 `src/components/ImageLightbox.vue`）**：

```jsx
<template>
  <!-- Teleport 是修「关闭按钮被裁掉」的一半：灯箱原本挂在 .local-image 里面，
       那个容器 position: relative + overflow: hidden，编辑区祖先一旦有 transform，
       position: fixed 的包含块就不再是视口。挂到 body 下就不受任何祖先影响。 -->
  <Teleport to="body">
    <div
      v-if="open"
      class="lightbox"
      role="dialog"
      aria-modal="true"
      :style="viewportStyle"
      @pointerdown="onPointerDown"
      @pointermove="onPointerMove"
      @pointerup="onPointerUp"
      @pointercancel="onPointerUp"
      @wheel.prevent="onWheel"
      @contextmenu.prevent
    >
      <img
        v-if="url"
        ref="imgRef"
        class="full"
        :src="url"
        :alt="alt"
        draggable="false"
        :style="imageStyle"
      />

      <button
        ref="closeRef"
        type="button"
        class="close"
        aria-label="关闭"
        @pointerdown.stop
        @click.stop="close"
      >
        <svg viewBox="0 0 24 24" aria-hidden="true" focusable="false">
          <path d="M6 6l12 12M18 6L6 18" />
        </svg>
      </button>
    </div>
  </Teleport>
</template>

<script setup lang="ts">
import { computed, nextTick, onUnmounted, reactive, ref, toRef, watch } from "vue"

import { useObjectUrl } from "@/composables/useObjectUrl"

const props = defineProps<{
  open: boolean
  blob: Blob | null
  alt: string
}>()

const emit = defineEmits<{
  close: []
}>()

const MIN_SCALE = 1
const MAX_SCALE = 4
/** 与 LocalImageView 的 MOVE_TOLERANCE 同值：位移在此以内算「点一下」 */
const TAP_TOLERANCE = 8

const closeRef = ref<HTMLButtonElement | null>(null)
const imgRef = ref<HTMLImageElement | null>(null)

const blob = toRef(props, "blob")
// 关闭期间置 null，useObjectUrl 会 revoke 原图 URL：原图可能有几 MB，
// 九张图各挂一个实例时不能让它们常驻。
const source = computed(() => (props.open ? blob.value : null))
const url = useObjectUrl(source)

/* ---------- 视觉视口：修「关闭按钮显示不全」 ---------- */

// 不能用 inset: 0。fixed 定位的是「布局视口」，而用户看到的是「视觉视口」；
// 页面被 pinch-zoom 或被软键盘顶起时两者不重合，右上角会被推到屏幕外。
const viewport = reactive({ left: 0, top: 0, width: 0, height: 0 })

const viewportStyle = computed(() => ({
  left: `${viewport.left}px`,
  top: `${viewport.top}px`,
  width: `${viewport.width}px`,
  height: `${viewport.height}px`,
}))

function syncViewport(): void {
  const v = window.visualViewport
  if (!v) {
    viewport.left = 0
    viewport.top = 0
    viewport.width = window.innerWidth
    viewport.height = window.innerHeight
    return
  }
  viewport.left = v.offsetLeft
  viewport.top = v.offsetTop
  viewport.width = v.width
  viewport.height = v.height
}

/* ---------- 缩放与平移：修「原页面跟着放大」 ---------- */

const scale = ref(1)
const tx = ref(0)
const ty = ref(0)
const gesturing = ref(false)

const imageStyle = computed(() => ({
  transform: `translate3d(${tx.value}px, ${ty.value}px, 0) scale(${scale.value})`,
  // 手势进行中禁掉过渡，否则跟手会有一帧延迟；松手后的回弹才用过渡。
  transition: gesturing.value ? "none" : "transform 0.18s ease-out",
}))

const pointers = new Map<number, { x: number; y: number }>()
let startDistance = 1
let startScale = 1
let startAnchor = { x: 0, y: 0 }
let startTx = 0
let startTy = 0
let moved = 0

function clampScale(value: number): number {
  return Math.min(MAX_SCALE, Math.max(MIN_SCALE, value))
}

// 夹紧平移量：放大后图片边缘不许被拖离视口内侧，1× 时强制归零。
function clampTranslate(): void {
  const el = imgRef.value
  if (!el) return
  const maxX = Math.max(0, (el.clientWidth * scale.value - viewport.width) / 2)
  const maxY = Math.max(0, (el.clientHeight * scale.value - viewport.height) / 2)
  tx.value = Math.min(maxX, Math.max(-maxX, tx.value))
  ty.value = Math.min(maxY, Math.max(-maxY, ty.value))
}

function resetZoom(): void {
  scale.value = 1
  tx.value = 0
  ty.value = 0
}

function center(): { x: number; y: number } {
  return {
    x: viewport.left + viewport.width / 2,
    y: viewport.top + viewport.height / 2,
  }
}

/**
 * 围绕锚点缩放。推导：屏幕位置 = 中心 + t + scale × 图内向量，
 * 于是要让锚点下的那个像素不动，t_new = anchor − center − ratio × (旧锚点 − center − t_old)。
 * 少了这一步就是「从画面正中放大」，手指按住的位置会跑掉。
 */
function zoomAround(next: number, anchor: { x: number; y: number }, from: { x: number; y: number }): void {
  const c = center()
  const ratio = next / startScale
  tx.value = anchor.x - c.x - ratio * (from.x - c.x - startTx)
  ty.value = anchor.y - c.y - ratio * (from.y - c.y - startTy)
  scale.value = next
  clampTranslate()
}

function beginGesture(): void {
  const list = [...pointers.values()]
  startScale = scale.value
  startTx = tx.value
  startTy = ty.value

  if (list.length >= 2) {
    const [a, b] = list
    startDistance = Math.hypot(a.x - b.x, a.y - b.y) || 1
    startAnchor = { x: (a.x + b.x) / 2, y: (a.y + b.y) / 2 }
    return
  }
  if (list.length === 1) startAnchor = { x: list[0].x, y: list[0].y }
}

function onPointerDown(event: PointerEvent): void {
  // 逐指捕获，不是整体捕获：多指时每个 pointerId 各自捕获，
  // 手指滑出遮罩范围仍能收到 pointermove。
  ;(event.currentTarget as HTMLElement).setPointerCapture(event.pointerId)
  pointers.set(event.pointerId, { x: event.clientX, y: event.clientY })
  gesturing.value = true
  if (pointers.size === 1) moved = 0
  beginGesture()
}

function onPointerMove(event: PointerEvent): void {
  const point = pointers.get(event.pointerId)
  if (!point) return
  point.x = event.clientX
  point.y = event.clientY
  // touch-action: none 已经把手势交给我们，这里再 preventDefault 挡掉
  // 浏览器可能残留的滚动 / 缩放意图。
  event.preventDefault()

  if (pointers.size >= 2) {
    const [a, b] = [...pointers.values()]
    const distance = Math.hypot(a.x - b.x, a.y - b.y) || 1
    const anchor = { x: (a.x + b.x) / 2, y: (a.y + b.y) / 2 }
    zoomAround(clampScale(startScale * (distance / startDistance)), anchor, startAnchor)
    moved = TAP_TOLERANCE + 1 // 捏过就不再算「点一下」
    return
  }

  const dx = event.clientX - startAnchor.x
  const dy = event.clientY - startAnchor.y
  moved = Math.max(moved, Math.hypot(dx, dy))
  if (scale.value <= 1) return

  tx.value = startTx + dx
  ty.value = startTy + dy
  clampTranslate()
}

function onPointerUp(event: PointerEvent): void {
  if (!pointers.delete(event.pointerId)) return

  // 还有手指在屏幕上：以剩下的手指重新起算，避免松开一指时图片瞬移。
  if (pointers.size > 0) {
    beginGesture()
    return
  }

  gesturing.value = false
  if (scale.value < 1.02) resetZoom() // 捏回 1× 附近就归位，免得留下零点几像素偏移
  if (moved > TAP_TOLERANCE) return

  // 点一下：已放大时先回到 1×（此时用户多半是想看全图，不是想关），未放大才关闭。
  if (scale.value > 1) {
    resetZoom()
    return
  }
  close()
}

function onWheel(event: WheelEvent): void {
  startScale = scale.value
  startTx = tx.value
  startTy = ty.value
  const anchor = { x: event.clientX, y: event.clientY }
  zoomAround(clampScale(scale.value * (event.deltaY > 0 ? 0.9 : 1.1)), anchor, anchor)
}

/* ---------- 背景滚动锁、键盘与生命周期 ---------- */

/**
 * 背景滚动锁必须带实例级标记。
 *
 * 每个 LocalImageView 都各自挂了一个 ImageLightbox，九宫格就是九个实例。

  emit("close")
}

}

  window.visualViewport?.removeEventListener("resize", syncViewport)

    window.visualViewport?.addEventListener("scroll", syncViewport)

// 不解锁就整个 App 再也滚不动。
```

<aside>

### **L1、定案：不用 `[图片]` 占位**

`[图片] [图片] [图片] [图片]` 能解决「漏文件名」，但三个新毛病：

1. **九宫格就是九个 `[图片]`**，两行摘要全被占满，真正写的字一个都看不到。
2. **占位符会进搜索索引**。`contentText` 是搜索用的，写「图片」两个字进去，以后搜「图片」会命中所有带图日记。
3. 它把**结构信息塞进了纯文本字段**。图片有几张、封面是哪张，本该由 UI 直接读正文 JSON 得到，不该靠字符串里数占位符。

**定案的呈现方式**：

| 位置 | 呈现 |
| --- | --- |
| 摘要正文 | **只放真文本**。图片完全不进 `contentText` |
| 图片存在感 | 卡片左侧的**缩略图**（G 的 `EntryThumbnail`，已实施）＋ 标题行右侧**相机徽标 + 张数**（`📷 4`） |
| 整篇只有图、没有文字 | 摘要位显示**「4 张图片」**，用 `--color-ink-faint`，与真文本区分开 |

报错原文：


<aside>
🔍

**看清方向：错的不是 `LocalImageView.vue`（K3 那份一行不用改），是 `src/editor/media.ts` 的类型 import。**

`@tiptap/vue-3` 导出的 `Editor` 是 `@tiptap/core` 那个 `Editor` 的**子类**，多出 `reactiveState` / `reactiveExtensionStorage` / `contentComponent` / `appContext` 四个 Vue 专属成员。而 `NodeViewProps.editor` 声明的类型是**基类**。

于是：`moveImageNode(editor: vue3.Editor)` 要求子类，传进去的却是基类，少四个属性 → TS2345。E2 第二小节当时只交代了「从 `@tiptap/pm/model` 只 import type `Node`」，**没交代 `Editor` 的来源**，实施时自然按编辑器所在的包（`@tiptap/vue-3`）import 了，方向刚好反。

</aside>

**只改一行，在 `src/editor/media.ts` 顶部**：

```tsx
// 改前
import type { Editor } from "@tiptap/vue-3"

// 改后：这个文件只用到 core 的能力（state / view / chain / commands），参数就应该收基类。
// 收基类时 vue-3 的 Editor 仍能传进来（子类兼容基类）；收子类则会把
// NodeViewProps.editor 挡在门外 —— 就是本次报错。
import type { Editor } from "@tiptap/core"
```

**同文件的 `insertImages(editor: Editor, ...)` 一并受益、不用动**：`DiaryEditor.vue` 里 `useEditor()` 返回的是 vue-3 的 `Editor`，传给收基类的参数天然合法。

<aside>
⚠️

**三种不要用的“修法”。**

1. **不要在调用处断言**（`props.editor as unknown as Editor`）。它把类型不一致藏了起来，下次谁在 `moveImageNode` 里写一句只有 vue-3 `Editor` 才有的调用，编译期不报错，运行时才炸。
2. **不要把 `defineProps` 的 `NodeViewProps` 换成自定义类型**。它是 `VueNodeViewRenderer` 注入契约的一部分（P1-3 第 1 节），自己重写一份就得手工维护 `node` / `getPos` / `deleteNode` / `updateAttributes` 全套。
3. **不要把参数改成 `any`**。这是 P1 唯一一处直接 dispatch ProseMirror transaction 的地方，正是最需要类型看着的地方。
</aside>

纯类型改动，无运行时行为变化。改完跑 `npm run build`，并按 K6 第 2 条复测一次长按拖动排序仍生效。

```jsx
const groups = computed(() => {
  if (order.value === "updatedAtDesc") {
    return items.value.length
      ? [{ key: "updated", label: "近改动", items: items.value }]
      : []
  }

  const result: Array<{ key: string; label: string; items: EntryListItem[] }> = []
  for (const entry of items.value) {
    const key = entry.entryDate.slice(0, 7)
    const last = result[result.length - 1]
    if (last?.key === key) {
      last.items.push(entry)
    } else {
      const [year, month] = key.split("-")
      result.push({ key, label: `${year} 年 ${Number(month)} 月`, items: [entry] })
    }
  }
  return result
})

async function loadTags(): Promise<void> {
  try {
    tags.value = await tagRepo.list()
  } catch (reason) {
    tagError.value = reason instanceof Error ? reason.message : "标签读取失败"
  }
}

function toggleTag(id: string): void {
  const selected = new Set(tagIds.value)
  if (selected.has(id)) selected.delete(id)
  else selected.add(id)
  tagIds.value = [...selected]
}

function clearFilters(): void {
  tagIds.value = []
  dateFrom.value = ""
  dateTo.value = ""
  hasImage.value = undefined
}

function open(id: string): void {
  void router.push(`/entry/${id}`)
}

/** 有没有用户真的写下的字。L2 之后图片不再进 contentText，空串就是纯图日记 */
function hasText(entry: EntryListItem): boolean {
  return entry.contentText.trim().length > 0
}

function snippet(entry: EntryListItem): TextPart[] {
  return highlightParts(entry.contentText, keyword.value)
}

/** 纯图日记的摘要兜底。只用于展示，绝不写回 contentText（铁律 1） */
function fallbackExcerpt(entry: EntryListItem): string {
  return entryExcerpt(entry.contentText, imageCountByEntry.value[entry.id] ?? 0)
}

function dayLabel(entryDate: string): string {
  const [, month, day] = entryDate.split("-")
  return `${Number(month)}月${Number(day)}日`
}

// 单一序号 + 单一守卫，避免「封面是新一页、徽标还是上一页」的半旧状态。
watch(items, async (list) => {
  const mine = ++coverSeq
  const ids = list.map((e) => e.id)
  const [covers, counts] = await Promise.all([
    mediaRepo.firstByEntries(ids),
    mediaRepo.countByEntries(ids),
  ])
  if (mine !== coverSeq) return
  coverByEntry.value = covers
  imageCountByEntry.value = counts
})

watch(keyword, (value) => {
  const query = value.trim()
  void router.replace({ query: query ? { q: query } : {} })
})

onMounted(() => {
  const query = route.query.q
  if (typeof query === "string" && query) keyword.value = query
  void loadTags()
  void reload()
})

onUnmounted(() => {
  coverSeq += 1
})
```

```jsx
import { computed, onMounted, ref, watch } from "vue"
import { useRouter } from "vue-router"

import AlmanacCard from "@/components/AlmanacCard.vue"
import BambooSlipEmpty from "@/components/BambooSlipEmpty.vue"
import HomeDateNavigator from "@/components/HomeDateNavigator.vue"
import { entryRepo, mediaRepo } from "@/repo"
import { getAlmanac, type AlmanacDay } from "@/shared/almanac"
import { entryExcerpt } from "@/shared/entryMeta"
import { todayLocal } from "@/shared/time"
import type { EntryListItem } from "@/shared/types"

const router = useRouter()

const today = todayLocal()
const selectedDate = ref(today)
const almanac = ref<AlmanacDay | null>(null)
const dateEntries = ref<EntryListItem[]>([])
const recent = ref<EntryListItem[]>([])
const imageCountByEntry = ref<Record<string, number>>({})
const monthDays = ref(0)
const notice = ref("")
let loadSeq = 0

const dayNum = computed(() => Number(selectedDate.value.slice(8, 10)))
const monthLabel = computed(() => `${Number(selectedDate.value.slice(5, 7))} 月`)

const writeLabel = computed(() => {
  if (selectedDate.value !== today) return "补记一简"
  return dateEntries.value.length ? "再刻一简" : "刻一简"
})

/** 有没有用户真的写下的字。L2 之后图片不再进 contentText，空串就是纯图日记 */
function hasText(entry: EntryListItem): boolean {
  return entry.contentText.trim().length > 0
}

/** 摘要位：真文本优先，纯图日记退回「N 张图片」。只展示，不写回 contentText */
function preview(entry: EntryListItem): string {
  const value = entryExcerpt(entry.contentText, imageCountByEntry.value[entry.id] ?? 0)
  return value.length > 40 ? `${value.slice(0, 40)}…` : value
}

async function load(): Promise<void> {
  const mine = ++loadSeq
  const date = selectedDate.value
  const nextAlmanac = getAlmanac(date)

  const [minePage, latest] = await Promise.all([
    entryRepo.list({ dateFrom: date, dateTo: date, pageSize: 50 }),
    entryRepo.list({ pageSize: 5, order: "entryDateDesc" }),
  ])

  const prefix = date.slice(0, 7)
  const counts = await entryRepo.countByDate(`${prefix}-01`, `${prefix}-31`)

  // 张数依赖上面两个列表的 id，只能串行取。代价是多一个 IndexedDB 往返，
  // 换来的是全程只有一个 loadSeq 守卫，不会出现「条目是新日期、徽标还是旧日期」。
  const ids = [...new Set([...minePage.items, ...latest.items].map((e) => e.id))]
  const imageCounts = await mediaRepo.countByEntries(ids)

  if (mine !== loadSeq) return

  almanac.value = nextAlmanac
  dateEntries.value = minePage.items
  recent.value = latest.items
  imageCountByEntry.value = imageCounts
  monthDays.value = Object.keys(counts).length
}

function showBlockedNotice(): void {
  notice.value = "预简（待刻）尚未开放，暂只能刻已至之日"
}

function write(): void {
  void router.push({ path: "/entry/new", query: { date: selectedDate.value } })
}

function open(id: string): void {
  void router.push(`/entry/${id}`)
}

watch(selectedDate, () => {
  notice.value = ""
  void load()
})

onMounted(() => {
  void load()
})
</script>
```
