# P4 到期提醒本机验收指南

本批P4-2K实现原定应用内提醒核心：本机待刻总数、今日和逾期数量，使用设备自然日，只计未删除pending来源。不会改dirty/修订、不自动转简、不签到、不请求后台、不创建或清理数据。正式首页尚未接通，提醒先挂原5179游客验收页，不新增端口/数据库。

## 1. 拉取和检查

在现有p4/schedules分支先保留未提交改动，再拉取。在frontend目录执行：

```bash
git pull --ff-only
npm run check:p4
```

这包含新提醒回归和既有P4测试、vue-tsc及Vite构建；相关原宿主回归单独跑过不等于本机完整check:p4已过。P3全量按最终集成矩阵单独记录，不需要为了只读提醒升级依赖或迁移数据库。

## 2. 使用原5179验收页

日常origin若仍为用户此前报告的http://localhost:5173：

```bash
P4_DAILY_ORIGIN='http://localhost:5173' npm run dev -- --config vite.p4-acceptance.config.ts
```

访问 `http://127.0.0.1:5179/p4-acceptance.html`，仍先确认隔离闸门，再进入原`quire-p4-acceptance`库。若日常origin已变更，必须填真实origin，不照抄猜测。

**保留原验收数据，不点“在空验收库创建测试数据”，不清库，不重复首存/交接。** 此页无账号、真实云端、后台同步或自动备份；5181/5182另两库和证据不受此提醒影响。

## 3. 最小验收，不重跑已过流程

1. 顶部出现“本机待刻N简：今日X简，逾期Y简”。核对N=X+Y，并对比工作区全部未删除pending来源；不是只数当前分页。已转简、断简和未来待刻不计入。此前夹具日期可能已过期，不固定写死为1/1。
2. 点“查看预简工作区”：应只是聚焦/滚动到原工作区，不切换路由、过滤器，不关闭编辑器或保存/弃去输入。
3. 如愿意操作已有测试预简：把一条pending改期到今天/过去/未来或移入断简再恢复，保存后提醒自动重算。仅改专用库测试文字，已有未保存输入必须沿原流程处理；不要求创建新夹具或重新转简。
4. 切换到其他标签页再回来，或点“重新读取提醒”，数量正确；离线时已有本机数据仍可统计。离线只覆盖已加载页面，不能据此声称PWA离线冷启动已验。
5. 关闭验收宿主前仍应检查未保存输入，关闭后提醒卸载；重新进入只读计数。刷新后保留记录，页面仍需过原隔离闸门。

跨午夜无需修改系统日期强测：自动测试覆盖跨日、上海/纽约本地日及夏令时；真实跨午夜可留页观察，前台最多约60秒轮询重读（系统暂停/节流可能更慢），回前台或获得焦点会主动重读。不承诺关浏览器后准点提醒，不用24小时固定时长推算下一自然日。

## 4. 失败与上下文边界

读失败显示“暂不能读取”，不显示假0或继续显示旧数量。归属/恢复epoch及登录代次固定于首次捕获上下文：变化时旧实例停止，不自动认领或读取新账号；需要沿既有流程处理未保存输入后重新进入。原owner watcher检查登录代次和DB归属，新数据watch只触发只读重算。取消订阅/卸载后迟到结果不重新展示。

不能把“本机0简”解释成云端无待刻；离线设备尚未同步的数据不在本机统计内。P3签到日仍按原账号时区，本提醒采用设备自然日，二者不互相改写。

## 5. 本批证据范围

沙箱新增47项提醒运行时/只读模拟存储/静态接线测试通过；真实Vue DOM、IndexedDB watcher/浏览器与完整vue-tsc/Vite尚待本机。提醒统计/控制器、DB端口、Vue脚本语法检查不是完整项目类型检查。最终相关/全量测试数字见真相来源第五十二章，不用旧章节里的历史总项数替代当前结果。
