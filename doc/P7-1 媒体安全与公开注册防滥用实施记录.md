## 1. 私有媒体读取

- 移除 FastAPI `StaticFiles` 挂载，应用和 Nginx 两侧拒绝旧 `/media`、`/media/...` 静态入口。磁盘不能再作为公开 Web 根目录。
- 新增 `GET /api/v1/media/{id}/original|thumbnail`，使用现有 Bearer/JWT `get_current_user`，查询必须绑定 `Media.user_id`。未登录 401，其他账号或缺失资源 404；不会将原图冒充缩略图。
- 只接受已有服务器生成的确定性 ID 路径，复用现有纯文件探测/摘要核验函数；有界、no-follow FD 读取。**复用的只是安全文件读取原语，不绕过 P4 来源证明，也不将 P4 专用下载权限变为普通权限。**
- 原图/缩略图最多各 10 MiB，成功及错误响应 `private, no-store`，按 Authorization 区分；无公开签名 URL、无 query token。
- 前端只按 ID/variant 请求固定 API，不 fetch 服务器下发的任意 `remoteUrl`，不向外部 URL 发送凭据。复用账号固定与令牌刷新机制；网络前后、本地填充事务内和最后 await 后检查账号/恢复上下文。
- 本机 Blob 优先，失败不清理原有本机数据、不修改 dirty；迟到结果不重建已删除媒体、不覆盖新本机字节。P5/P6 继续只读本机，不新增云端补图。
- 原有 wire URL 和磁盘路径仍是元数据/存储定位，不再是可直接访问的公共图片链接；正文仍是 `local://media/{id}`。

## 2. 上传覆盖与事务边界

- 上传先锁真实账号行，再按全局媒体 ID 做当前锁读；已有其他 owner 直接 404，不能先写盘再依赖数据库报错。
- 同账号已完整上传保持幂等，不替换已存内容；缺失资源修复也只允许相同已有字节，不覆盖不同字节。缩略图/原图格式与已登记路径不符时拒绝。
- 保留 P4 现有确定性文件名。新文件先在同目录独占临时文件中完整写入和 fsync，再用 no-replace hard link 发布；不使用 `write_bytes` 覆盖或 `os.replace`。父目录/文件拒绝符号链接。
- 同一磁盘根目录的发布过程使用 POSIX flock；新文件归属本次 inode，失败仅清理本次新建文件。约束在 flush 阶段先检查，跨账号并发即使都读到“不存在”，也不能覆盖彼此文件。
- **COMMIT 回执丢失不能当作“确定未提交”。** 此时返回 503、保留可能已被数据库引用的文件，不盲删；用户重试核对。进程被杀/磁盘故障可能留下无引用文件，暂不提供自动删除器，须在停止写入、备份后只读对账再明确处理。不要自行删除 `.upload-*` 或未知占用文件。

## 3. 防滥用默认值

均可通过 `.env` 正整数配置，不读取/修改真实 `.env`：

| 设置 | 默认 |
| --- | --- |
| REGISTER_IP_PER_HOUR | 同 IP 注册尝试 5 次/小时 |
| REGISTER_GLOBAL_PER_DAY | 全实例注册尝试 100 次/滚动 24 小时 |
| LOGIN_IP_PER_MINUTE | 同 IP 登录尝试 30 次/分钟，成功也计数 |
| API_IP_PER_MINUTE | 同 IP API 请求 240 次/分钟 |
| UPLOAD_IP_PER_MINUTE / UPLOAD_USER_PER_MINUTE | IP / 账号各 20 次上传尝试/分钟 |
| MEDIA_READ_USER_PER_MINUTE | 账号媒体读取 120 次/分钟 |
| MEDIA_USER_MAX_BYTES | 每账号原图+缩略图合计 500 MiB |
| MEDIA_USER_MAX_COUNT | 每账号媒体记录上限 1000，包含空槽位 |
| MEDIA_DISK_RESERVE_BYTES | 媒体所在文件系统保留 1 GiB 可用空间 |

- 请求限流在解析大请求/密码哈希前执行，失败和畸形请求也消耗尝试额度。新限流器最多保留 4096 个活跃桶；满时拒绝新桶，不驱逐活跃限制。旧按邮箱登录失败表也有容量保护。
- 429 返回 JSON + Retry-After；容量/数量超限返回 413；存储暂不可用/空间保护返回 503。前端保留本机内容及未上传 dirty，错误向上传播，不把“返回了同步函数”当作同步成功；暂停的错误也不能被后续无工作循环洗成成功。
- 账号配额在账号行锁内按当前媒体记录指向的实际磁盘原图+缩略图字节计算，不信任可被同步元数据修改的 `size`。返回行数受限，不全量读取 Blob；数据库扫描成本不等于只扫描返回行。
- 所有本实例上传的磁盘发布在跨进程文件锁内检查空间储备；该保护不是整个服务器的磁盘配额，也不能阻止其他程序耗盘。
- Nginx 提供整个 API 的 IP 限速与 22m 请求体上限及结构化 429/413；应用同时限制实际读取的请求体字节，不能靠缺少 Content-Length 绕过。
- 应用只使用 ASGI `client`，不自己信任 X-Forwarded-For/X-Real-IP。systemd 明确只信任回环 Nginx 的代理头；Uvicorn 仍绑定 127.0.0.1。
- **限流是单进程内存状态，重启会重置，不是分布式/跨重启永久配额。** 首版继续一个 worker、一个 API 实例，不在本批引入 Redis。若日后多实例需重新冻结共享限流方案；文件保护/账号行锁不替代分布式请求限流。
- 注册全局预算统计尝试而非成功账号，是小服务器的保护阀，也可能被恶意消耗导致暂时停止注册；可按真实容量调整，不宣称能抵挡所有机器人或 DDoS。邮箱验证/找回密码、日记总量配额和验证码不在本批范围。

## 部署非授权边界

本批只提供模板，不安装或 reload Nginx，不启动 systemd，不申请证书、不执行迁移。模板 `limit_req_zone` 位于 nginx `http {}` 上下文；不得复制进已有 `server {}` 内。正式部署仍需证书、真实路径/账号/CORS、密码与 JWT 密钥、目录权限、备份恢复和空库迁移的分别确认。不存在“现在 pull main 就可公开注册上线”的结论。
