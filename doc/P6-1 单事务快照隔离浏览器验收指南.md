## 目的与边界

验证当前生产快照适配器在真实Dexie/IndexedDB中的单事务、只读、一致性与失效清理。仅用固定公开材料和模拟身份，本批保留固定2×2 PNG事务外原生解码/资源关闭和内容变化提示，增加真实快照诊断汇总及程序模拟降级选择/撤销；不代表真实用户点击正式确认界面。不验证/auth/me、JWT签名、正式账号接线、大图组合容量、字体、正式账号变化提示界面、分页、打印/PDF或手机内存。不代表P6-1整批通过。

入口只创建`quire-p6-snapshotcheck-<UUID>`随机测试库；两个真实连接读写该库。打开其他库、删除库、API/云媒体请求均被阻止。实际schema默认db实例只构造、不打开，守卫拒绝其他库名。测试材料由writer显式写入并记账，生产读取路径应零写入；另有一次应被ReadOnlyError拒绝的原生只读写探针。不会读取日常日记/账号/私人文件，不删除随机测试库，不清理P4/P5验收目录。

## 二、Edge / Chrome / Safari 各运行一次

1. 打开上述精确地址，初始应显示尚未运行；没有点击不应开始DB核验。
2. 点击“创建随机库并核验一次”，保持页面前台；每次重新载入后运行会创建新随机库，不自动删除旧库。
3. 完成后核对16项全部通过，受控快照展示已经释放。
4. 展开“原始报告（仅固定材料）”，复制报告连同浏览器名称和`git rev-parse HEAD`结果回传。报告不包含私人日记，不要另贴真实库内容。

应核对：

- `complete: true`，16项`passed: true`，无error。
- 37篇不截20；首次快照四表同一物理readonly事务，各读取请求属于该事务；正文/标签/Blob同版本。
- `productionWriteAttempts: []`、`networkAttempts: []`、`objectUrlAttempts: 0`。
- `readonlyWriteProbeDenials: 1`；这是测试专用原生写探针被拒绝，不是生产写入成功。
- 新增诊断场景预期3个问题、1篇受影响、2张去重图片；完整版默认阻断，内部程序明确选择降级后也仍`completeOutputReady: false`；撤销、复制报告、跨任务、重捕获不得复用确认。
- `imageDecodePeak: 1`、`bitmapsCreated === bitmapsClosed`且大于0，`contentSubscriptionsRemaining: 0`；真实2×2 PNG读取后在事务外解码，注入失败与原生成功分开记录。
- 订阅剩余0，最终数据库连接关闭；`opened`只含报告中同一随机库名。
- 固定writer操作共22条DBCore记录，严格白名单：种子entries/add40、tags/add1、media/add3、meta/add3、schedules/add1；之后entries/put1共5条、tags/put1共4条、media/put1共4条、meta/put1共4条。材料写入不能被宣传成整个测试“无写入”。

第5项并发由真实读调用点排队另一连接原子写；不在生产事务内等待测试暂停。取消、替换和身份变化属于受控场景，不冒充真实用户并发、真实登录或全库恢复。本批有内部changed/订阅和隔离页受控提示：普通变化仅提示，旧快照不变，明确重捕获才更新；meta代际变化直接清空。当前采用表级保守通知，所选范围外改动或迟到事件也可能提示；不保证changed=false是无变化证明。正式UI仍待后续。
