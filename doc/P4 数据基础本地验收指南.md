## 1. 拉取开发分支

```bash
cd ~/Documents/Quire
git status
git fetch origin
git switch p4/schedules
git pull --ff-only origin p4/schedules
```

先保留本地未提交改动，不能强制切换或覆盖工作区。首次本地不存在该分支时，单一origin环境的git switch会跟踪同名远程分支；如未自动跟踪，再执行 `git switch --track origin/p4/schedules`。

main仍保持P2/P3稳定源码。此轮没有PR合并或生产发布。

## 2. 前端自动检查

在原有依赖已安装的项目环境中执行，不升级npm或依赖：

```bash
cd frontend
npm run test:p4
npm run check:p4
npm run check:p3
```

P4目前7个测试文件、54项；覆盖日期/文本规则、稳定来源ID、内部CRUD/schema、备份v3及v1/v2兼容/媒体字节/来源映射/首次快照/损坏与过新隔离、认领清库失败、owner恢复代际、P2转换保护和refresh/401身份隔离。测试辅助器优先使用项目typescript；无typescript且Node支持stripTypeScriptTypes时，仅能运行擦除类型后的断言。

**test:p4不等于类型检查，模拟事务不等于真实IndexedDB。** check:p4通过才登记项目vue-tsc/Vite结果；P3检查继续单独登记。任何缺测试/启动失败/断言失败均非零退出。

## 3. 后端无数据库写入的检查

```bash
conda activate quire
cd ~/Documents/Quire/backend
python -m compileall -q app
python -m ruff check app tests alembic/versions/20261008_add_schedules.py
python -m pytest -q
python -m alembic heads
```

项目依赖需已经安装。新增4项迁移AST合同测试，另有3项SQLAlchemy模型/DDL编译测试；后者不需要数据库，但需要SQLAlchemy。保存真实输出，不预设全量pytest总项数。

`alembic heads`预期源码迁移头为p4_schedules，**不代表运行数据库已升级**。已有环境可用 `python -m alembic current`读取实际库版本；目标库必须先确认。

可选生成P4增量离线SQL（不执行数据库写入）：

```bash
python -m alembic upgrade p3_checkins:p4_schedules --sql > p4-schedules-preview.sql
```

核对新建schedules的13列、3个用户维度索引、转换目标唯一键、状态/转换关系检查约束、DATETIME(3)/BINARY(16)/字符集及无外键。检查约束须在MySQL 8.0.16+验证执行效果。不要误把生成SQL当作迁移实测。

## 4. 真实IndexedDB升级：独立测试环境

本批schema已有version(3)。**打开开发前端会自动升级同origin的quire库，不能依靠切回旧v2前端无损回滚。** 先防蠹并保留文件，优先使用独立浏览器配置/测试origin，不在唯一日常数据副本上直接试。

1. 用原v2版本在独立测试环境建立日记、图片、标签、断简、草稿与owner/同步meta样例，记录数量与内容并导出备份。
2. 在相同测试origin加载本开发版本；确认原四表/记录/Blob/草稿/owner/lastSyncAt/conflicts/pendingPurges完整，新增schedules为空。
3. 确认Entry来源索引非唯一，schedules索引使用0/1与复合索引，不以deletedAt/null索引查询活跃数据。
4. 刷新仍可读。此批没有日程入口，DEV $repo也不暴露scheduleRepo；不要绕过该闸门制造尚无完整日程云端闭环的数据。
5. 保存测试环境、前后数量与截图/结果；失败时不删除唯一原库来“解决”错误。

真实MySQL应用/降级测试应在已备份的独立测试库进行，生产迁移等待P4后续批次与验收。downgrade删除日程和长期幂等关系，有损。

以下使用独立测试origin/测试账号；日程UI、DEV $repo写入口仍未开放。可运行自动测试检查转换夹具，不在日常数据中绕过闸门造终态记录。
