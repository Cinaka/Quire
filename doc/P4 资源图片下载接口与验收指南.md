## 2. 接口契约

`GET /api/v1/schedules/{schedule_id}/review/resources/{media_id}/{variant}`

- 使用现有Bearer鉴权；来源及媒体必须UUID v7。variant只允许`original`或`thumbnail`。
- 必填query来自刚获得的当前资源证明：`expected_size`（1～10MiB整数）、`expected_mime`（png/jpeg/webp/gif）、`expected_sha256`（64位小写hex）。不接收文件路径、任意URL、owner覆盖、base64上传或下载落盘目标。
- 来源必须属于当前账号、终态身份/回执可核对、有当前稳定关联日记；图片必须被该日记当前受支持正文引用，且媒体行同时匹配账号/来源。未知回执、身份冲突、pending、purged或未知正文不开放读取。
- 已软删日记在仍有当前稳定资源时可只读取得本人的图片；不恢复日记/来源、不改删除状态。它不是允许恢复或永久弃去的凭证。
- 返回既有Envelope，data包含：`read_only:true`、`resolution_enabled:false`、`proof_scope:"current_entry_image_bytes"`、schedule_id/media_id/variant/size/mime/sha256/data_base64。字节为受限base64 JSON，不是公开文件URL或跳转、签名地址，也不是防蠹备份/首次转换确认。
- 成功响应`Cache-Control:no-store`、`Pragma:no-cache`、`X-Content-Type-Options:nosniff`；路由内拒绝同样不缓存。没有范围下载/重定向/客户端任意路径功能。

404：不存在/他人来源、当前不引用或不属于当前日记的媒体、缺失文件/缩略图；不会拿原图顶替缩略图。409：无法验证的身份/正文/路径/字节、大小/格式/摘要已变化或锁竞争；保留保护，重新核对，不返回新字节让旧授权继续。422：非法UUID/variant/证明query；401：未鉴权。错误不包含磁盘路径、SQL、存储URL或图片数据。

## 3. 文件与事务边界

只从服务端已有媒体行生成式相对路径定位文件；不请求外部URL。以目录FD逐级O_NOFOLLOW，最终文件O_NOFOLLOW/O_NONBLOCK，只接受普通非空文件。单张最多10MiB；原图元数据大小亦匹配预期，缩略图按自己的字节证明核对。

同一个FD、同一次受限读取同时计算SHA和收集字节；读前/读后/当前名字的设备、inode、大小、mtime、ctime及文件头MIME核对，拒绝变长/缩短/同大小修改/替换、符号链接与FIFO。证明不一致时不返回任何已收集字节，也不返回新摘要作为旧请求的替代授权。既有只读probe_image仍只返回摘要，不带字节，旧语义保留。

持有原有账号/来源/稳定日记/媒体行锁读取，最终只rollback，无flush/commit、媒体写入或删除。操作系统文件不受数据库锁永久保护；返回仅代表此次读取的字节与预期图片证明一致，不代表请求之后云端未变化、整包资源一致或允许解除本机保护。

## 4. C10 前端内部接线与边界

- `createScheduleCloudResourceImageTransport()` 只构造能力，不发请求。`getPinnedScheduleResourceImage` 使用固定来源/媒体/variant路径与证明query；不接受URL/owner覆盖。固定owner/token代次沿用原请求拦截器及同账号单飞refresh，旧账号401/迟到响应不能转交新账号。
- 成功图片响应使用有界文本，先核对状态、信封和长度再JSON解析；按预期base64长度+4096设传输预算，progress超限触发AbortController，并最终检查长度。浏览器progress并非绝对流式内存配额，仍依赖服务端10MiB限制，不能宣称任意响应均零额外分配。
- `validateScheduleResourceImage` 严格字段白名单、固定来源/媒体/variant/只读含义、大小/MIME/摘要一致，canonical base64与文件头校验后逐张复算SHA-256；不能仅信任响应中的sha字段。整批材料（含保留槽位）最多16MiB，每张最多10MiB；无后台抓图/外部URL/自动全选。
- 独立内部工厂 `createInternalScheduleCloudResourceRepairer(transport)` 暴露 `prepare(id, selectedIds)`、`repair(reviewId, true)`、`cancel()`。prepare先复制明确选择，固定账号/token代次/DB epoch，记录本机完整保护/字节指纹，取得完整云端证明，计算缺失槽位。仅下载缺失原图/缩略图；非空已有槽位须先匹配云端证明，原字节及元数据不覆盖。无缩略图证明时不拿原图替代。
- 所有下载先留内存。prepare结尾重读完整云端证明并核对本机指纹；成功只给计划，不写DB。明确确认后，再沿用原补齐器的两次完整云端证明、本机/材料重验及事务内最终检查，单事务写缺失媒体槽位与专用补齐留档。新留档kind为 `missing-resource-from-cloud`，不伪装成本机证据文件或文件回读/恢复授权。
- 日记、预简、共享标签、首次意图、冲突候选/P2保护、基线/游标均不因下载成功被取舍、确认、恢复或同步；已有dirty/时间/URL不修改，新缺失媒体行仍dirty=1。原证据文件导入及双方取舍证据兼容流程保持。
- `cancel()` 中止当前图片请求并使票据失效；忙状态保持到旧异步结束，不允许重叠下载。确认事务仍用现有abort守卫，取消/失败不留下半批。提交已完成后取消只能要求重新读取，不虚称撤销已提交数据。停止等待期间可能已发出的只读证明GET不等于业务写入，也不会自动重试下载。
